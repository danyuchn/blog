Claude Code 會把它覺得值得記的事，寫成一份份小檔案放在專案底下，下次開工自動載入。我用了幾個月，這些記憶檔累積到四百多份。有一天我翻開索引，發現裡面不少內容，根本不該放在那裡。

如果你用 ChatGPT 的記憶功能、Claude 的專案知識，或是自己養一份「給 AI 看的筆記」，底下的做法其實照樣能套。

## 記憶檔變成了垃圾抽屜

翻過之後，內容大致分成幾種：

- 某位客戶或學員現在進行到哪、下次要做什麼。這是狀態，過兩週就過期了。
- 某次做事的完整步驟，只有特定任務才會用到。
- 金額和日期的流水帳。
- 已經不再成立的舊結論。

這些放在每次對話都會載入的地方，有兩個壞處。第一是占掉對話一開始的空間，模型每次都要先讀一遍跟眼前工作無關的東西。第二是它們會過期，但過期之後還是會被當成事實讀進去。這跟我之前寫過的[規則越加、模型越不聽話](/blog/posts/zh/harness-slim-down-36)是同一個原理，不過這次對象換成了記憶。

## 先分去處，再刪

我沒有逐份去抓「留或刪」。我先問的是：這份東西應該住在哪？

- 只有某類任務才用到的做法和陷阱，搬進對應的技能（skill），需要的時候才載入。這一批大約 56 份。
- 客戶、學員和專案的狀態，補進我的知識庫主檔，確認事實沒有漏掉，再把記憶檔刪掉。這一批 38 份。
- 已經過時的，直接刪掉。9 份。

記憶檔最後其實只留三種：我是誰、我的偏好和判準；我糾正過它、而且確認過正確的做法；還有某個外部資源在哪裡、怎麼查。

## 數字

整批處理完，我數了一下檔案：

- 所有專案合計，記憶檔從 403 份降到 302 份，少了 101 份。
- 我最常用的那個專案，從 118 份降到 65 份。
- 同一個專案的索引檔，從 6,532 個位元組降到 4,900，少了四分之一。
- 這次 commit 刪掉 4,382 行、新增 383 行；新增的大半是下一節的閘門本身。

## 為什麼要裝閘門

只清一次沒有用。放著不管，模型又會把客戶狀態、金額流水帳、整套做法寫進記憶，索引大概一天就長回來了。

所以我加了一道寫入閘門：每次模型想寫或改記憶檔，都要先過幾條檢查。沒過就直接擋下來，並告訴它這份東西該去哪裡。

- 新檔案一律要有名稱、一行說明和類型。
- 不准再開「專案」型記憶，狀態屬於知識庫。
- 「糾正」型的記憶，必須寫明為什麼，以及以後怎麼用。
- 內文如果出現三個以上不同日期、三筆以上金額，或待辦清單，就當成流水帳擋下來。
- 新檔案超過 2.5KB 就擋下。要嘛拆開，要嘛它其實是一套步驟，該放進技能（skill）。

如果真的有必要，可以在內容裡加一行註記放行。放行理由會被記錄下來。

閘門上線前，我拿現存的記憶檔全部原樣重寫測試了一遍。結果一份都沒有被誤擋。

## 你可以怎麼用在自己的 AI 筆記上

不需要寫程式，也不用自己一條一條分，交給 AI 去掃。它用的判準是這幾條：

1. 每一條問一次：這是不是我是誰、我的偏好、我糾正過的事、外部資源在哪？如果都不是，就是搬家的對象。
2. 客戶或專案的狀態，放回你原本記客戶的地方，像是試算表或 CRM。AI 要用時再去讀，不要寫死在它的記憶裡。
3. 一套步驟的做法，寫成一份獨立的作業說明，只在做那類任務時才餵給 AI。
4. 每條保留下來的偏好，都要補一句「為什麼」。沒有理由的規則，AI 遇到例外時就只能硬套。
5. 之後每個月再叫 AI 掃一次，看有沒有新長出來的流水帳。

把下面這段貼給 Claude Code 這類讀得到檔案的 AI，括號換成你的情況。它會自己讀、自己分類、自己列出搬移和刪除清單，你只要看表，決定哪幾項動手：

```text
請檢查你替我記下來的所有記憶檔（位置：（填記憶資料夾的路徑，或匯出檔的路徑））。
先自己把每一份讀完，包含索引檔，不要問我內容。
每一份歸入其中一類：
A. 我是誰、我的偏好或判準
B. 我糾正過、確認過的做法（要有原因）
C. 外部資源在哪、怎麼查
D. 以上都不是。再判斷它屬於：客戶或專案狀態、某類任務的步驟、已過期，哪一種
然後給我一張表：檔名、類別、建議動作、一句理由。
建議動作只有四種：保留、搬到（填我記客戶的地方）、改寫成獨立的作業說明、刪除。
搬移或刪除之前，先確認內容裡的事實不會因此遺失。
這一步只列表，不要動任何檔案。我看完表，告訴你要執行哪幾項，你再動手，做完回報實際改了哪些。
```

就這樣。

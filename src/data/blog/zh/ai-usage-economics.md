Claude Code 對我來說不是偶爾開一下的工具，而是每天開機就在跑的工作環境。正因為每天泡在裡面，當終端機突然跳出 Rate Limit，那種落寞感是極其真實的——比網路斷線還難受，因為手頭的工作真的就硬生生停在那裡了。

更荒謬的是月底看用量分析時，消耗歷史新高 +111%。當你把花費跟產出分開看，那個數字就不是「效率的代價」，是「被工具溺愛的帳單」。用量會自己膨脹、額度規則不透明、模型又好用到讓人上癮——這三件事疊起來，月底那張帳單很容易被自己合理化成「這是生產力的代價」。但把花費跟產出分開看，常常會發現：你付的是被工具溺愛的錢，不見得是產能的錢。

反觀免費版 GPT，作者自己用至今還沒 hit limit。問題不是免費版多強，是付費的 Claude 讓人太常 hit limit 了。**Claude 用戶的「滿足度」跟「焦慮度」一起拉高**——比起免費 GPT 用戶在「能用就好」的滿足區，Claude 用戶長期活在「下個小時還能用嗎」的計時區。每到週重置前夕，社群截圖貼文總會出現固定的慌亂：使用率已達 92%，距離重置還有十個小時，底下留言哀鴻遍野：「沒用完我睡不著覺」、「做夢都夢到在浪費 token」。

這不是使用者個人的問題，而是訂閱制在底層精心設計的機制。月費配上使用上限，天然製造出一種「沒用完很虧」的心理暗示——就像買了健身房月票，沒去的課虧的是自己的肉體，而沒燒完的 token 虧的則是現代人的智識焦慮。

當用量會自己悄悄膨脹、額度規則隱晦不透明，再加上模型好用到讓人上癮，月底那張帳單就很容易被合理化成生產力必繳的學費。要擺脫這種麻醉劑式的焦慮，得先把背後的這套「用量經濟學」看清楚。

## 訂閱制的大算術：官方補貼與那些危險的省錢捷徑

只講事實，不評論個人：各家 AI 實驗室的自家訂閱方案，本質上是最划算的，官方補貼的倍數甚至有 10 到 50 倍。舉個例子，在 Claude 訂閱 100 USD 方案，一個月能跑的量如果折算成 API 定價，相當於 5,000 USD 的額度。

如果是設立路由大平台，那就很有可能只能走 API 定額……這樣真的好嗎？

同一天還有另一個版本的極端省錢算術，那就是「三人共享帳號」。這是我那陣子聽過最好笑的事，比市長候選人提倡的多個 AI 入口大平台更好笑。你是不是沒有用過 Claude，不知道三人共享就等於三人一起手牽手下封號地獄。

想從反方向體驗額度的，也有辦法：直接進 Claude Code 訂 6,000 的方案，然後開 fable + ultracode，就可以體驗到不只是主管，甚至是老闆的感受。當然最先體驗到的是額度到了，薪水發不出來的感受。

說到極端定價，另一個方向的冷知識：目前為止 API 定價最貴的模型並不是 Claude Fable，是 GPT-o1-pro，150/600，約為 Fable/Mythos 的 12-15 倍（10/50）。它在 2025 年 3 月發佈，後來處於棄用但未退役狀態，而 OpenAI 也確定在 2026 年 10 月 23 日將其關閉，「最貴模型」這個頭銜它也撐不了太久。

## 額度黑箱與膨脹陷阱：為什麼你的 token 總是悄悄燒光

有人實測：5x 到 20x 的「增加 4 倍」其實只是五小時額度的 4 倍。**週額度其實只有增加 2 倍**。

Pay more, get less than expected。這不是個別感覺，而是數學設計。如果你升級是為了跑長時間、跨多天的批次任務，要先確認你真正需要的是五小時容量還是週容量。這個差距很少被討論，但它直接影響你在「連續工作場景」和「長週期平均使用」兩種情境下的實際體驗。如果你的工作節奏是每天短時間、分散使用，5x 方案對你的週額度改善其實有限。在 Codex 那邊也是類似邏輯：Tibo 預告 back-to-back reset 意外讓作者實測出 20 USD 方案 5 小時窗口跟 7 天窗口的關係：7 天額度大概等於 5 輪 5 小時窗口再多一點。

另一個讓人摸不透的是額度重置時間。為什麼每個人的 reset 時間都不一樣？有人在禮拜天，有人在禮拜三。這算是 Anthropic 的「需求平整」（demand smoothing）策略——如果重置同時重設時間，所有人的重置時間會變得一樣，大家可能就會在週期快到的時候瘋狂用，可能會加重尖峰負載，導致伺服器不穩定，作者猜測他們才刻意打亂，避免週尖峰集中在一兩天。

除了時間打散，另一個方向是併池。早起一則冷新聞：Claude Design 的獨立額度已經消失，併入整體 Claude 的使用額度中。獨立額度一個一個被收進主池，彈性是有了，代價是你更難精算「這個功能我到底還剩多少能用」。

更刺激的是 tokenizer 重製。你什麼都沒改，同樣一份工作，模型換個 tokenizer，用量就悄悄多出 1.4x（四成）。這種膨脹不會寫在顯眼處，你往往是從額度消耗速度變快才後知後覺。

名義容量和真實可用容量之間還存在時差。最近實測發現，以目前的方案加上美東尖峰時段，你大概會在 1 小時後 hit limit。這代表訂閱的「真實可用容量」跟你買的「名義容量」之間有時差——尖峰時段名義容量會被分母稀釋。

就連許多人寄予厚望的輔助功能，也可能成為額度殺手。Skill 比較不像是不同部門，更像是操作手冊。長期使用的話，三天兩頭工作階段崩潰（shutdown），不 shutdown 的話就是 hit limit。**Skill 不是節省 token，是換一種方式把 token 用掉**——Skill 載入本身就要費 token，而且更容易把長 context 撐到上限。如果你 hit limit 的頻率變高，先檢查是不是被 Skill 拖累的。

同樣的道理也適用於圖形介面：Cowork 是 Claude 的沙盒介面版本，它的 token 消耗比直接用終端機 CLI 快非常多。原因有幾層：介面本身的 wrapper overhead、預設的 safety 注入，以及 context 管理方式不同。如果你在用 Cowork 然後覺得 Pro 根本不夠燒，切換到 CLI 之後會發現同樣的任務省很多。Cowork 的定位應該是入門體驗，不是正式工作環境。

## 一個五小時窗口的真實身價：71 萬輸出與 55 倍補貼

到底一個五小時窗口能榨出多少價值？

Opus 5.5 發佈以來，額度變得非常省，五小時窗口也擴增了額度。有天早上好不容易在 5 小時內用完了一個窗口，我很好奇到底這個窗口值多少 token，於是調用終端機紀錄檔分析指令與代理人會話工具去扒出來看：

- 窗口時間是 8:00-13:00，手動開的主會話 6 個，同時最多 3 個在跑，另外還有 2 個是排程自動跑的
- 主會話的模型回合數：Opus 5.5 佔 746 回合，Sonnet 5 佔 187 回合
- 派出去的子代理（subagent）共 32 隻：Sonnet 23 隻、Opus 6 隻、Fable 3 隻
- 總輸出大約 71 萬 token，讀快取大約 4.4 億 token

這個架構的分工非常清楚：主線由 Opus 5.5 做決策跟驗收，大量執行丟給 Sonnet 子代理，Fable 只在需要第二意見的時候出場。

這一整個窗口大概佔週額度 12%，API 等值 156.69 USD，也就是說一週大概 1,276 USD。按照比例計算，如果整個月都把週額度用滿，那就是 5,469 USD。換句話說，相對於 100 USD 訂閱費，作者換算下來補貼是 55 倍！

## 快取機制與按量付費：不花冤枉錢的底層常識

要榨出官方補貼的真實價值，必須先搞懂快取的計費與生命週期。

很多人不知道這項常識：**只有 API 計費才會對快取讀取（cache reads）計費，訂閱方案的快取讀取完全免費。** 如果你有一份很長的系統提示詞或專案規範（例如 CLAUDE.md），你的訂閱方案不會因為它被快取讀取而扣費；但 API 用戶每一次 cache hit 依然需要支付小額的讀取費用。

關於快取的有效時間，依據官方文件，只要是訂閱方案且在額度內，主對話的快取時間就是 1 小時；而子代理（subagent）、額外加購用量（usage credits）和直接使用 API key 時，快取時間則是 5 分鐘。

在實務操作上，要省錢就必須保護好快取。隨時在終端機輸入 `/usage`，可以在最後一行查看目前的快取命中率。想要維持高命中率，除了不要中斷離開太久，最忌諱的就是在同一個工作階段中隨意切換模型。好消息是，在 Opus 5.5 中，對話中切換推理強度（effort）不會破壞快取：希望模型更仔細更自主就切高 effort，希望更快速、由你更多介入互動就切低。

搞懂了訂閱快取，什麼時候該轉向按量付費（On-Demand）？

訂閱制適合天天重度使用固定旗艦模型的人；但如果你的重活是「偶爾一次、吃很多 token、又不需要挑最貴模型」，按量付費就不會浪費在你根本沒用到的月租額度上。例如只要用到大量文字的地方就會用到 OpenRouter，比如會議記錄整理。因為性質很 on-demand，而且都選量大便宜的模型，儲值 10 USD 就可以用非常久。

在按量付費這一側，GPT-5.6-Luna 便宜到有點荒謬。我接在兩個地方：類似沉浸式翻譯的網頁外掛，每天約 50 到 80 個外語網頁一鍵全翻譯；類似 Typeless 的語音輸入法「Say It」，每天約 100 到 150 次使用做文字整理。連續 10 天下來每天花費不到 0.01 美元，費用儀表板顯示甚至直接是 0.0。

## 夜市牛排與判斷框架：你買的是能力擴充還是焦慮稅

聊完算術，回到心態上的一個根本問題：

有兩百塊的夜市牛排，也有兩千塊的餐廳牛排。後者有比前者好吃十倍嗎？

幾乎不可能。但還是有人買單。原因很多：環境、服務、儀式感、可以帶客戶。這些都是牛排以外的東西。

AI 訂閱費也是一樣的邏輯，卻幾乎沒有人這樣思考它。AI 訂閱費跟產出效益的比例，總感覺怪怪的。Sonnet 跟 Opus 的差價很大，但日常 80% 的工作 Sonnet 就夠用。**升到頂級模型或 Max 方案帶來的「真實生產力提升」並沒有等比例放大**。很多人付 Max 是付「焦慮稅」——怕用低配漏掉某個能力。但低配漏掉的多半不是能力，是耐心。

Pro 到 Max，差距不只是額度量，是用起來的「質感」完全不同。如果你只是偶爾問問題，Pro 完全夠用；但如果你開始跑 agent、讓 AI 自主完成多步驟工作，Pro 的週額度很快就見底。我自己摸清這件事之前，兩天額外用量就燒了 20 USD，補購又燒了 20 USD，最後才直接升級。

在 Pro 下你會一直在算還剩多少，在 Max 下幾乎不需要想這件事。我曾先開到 20x，但隨後覺得用量跟不上——AI 跑的時候我也在同時思考怎麼驗收、怎麼給下一個指令，人腦並不是真的能跟上 20x 的產出速度，後來便退回 5x。100 美元的 Max 平攤到每個工作天，對我來說是合理的工具成本。

要判斷一個方案是否值得，可以用這三個問題當作檢驗框架：

**1. 我用這個工具做的事，有沒有讓我做到本來做不到的事？**
不是「讓我更快做完」，而是「本來根本不會做、現在做到了」。這才是 10 倍價值的來源。如果只是讓原本兩小時的工作變成一小時，那你買的是效率，不是能力擴充。效率值多少錢，跟能力擴充值多少錢，是完全不同的計算。

**2. 我有沒有在用這個工具解決它真正擅長的問題？**
很多人買了頂階方案，主要卻用來改改句子、問幾個 Google 一搜就有的問題，或者做一些 GPT-4o free 版可以搞定的事。這不是工具問題，是使用場景問題。夜市牛排跟餐廳牛排的差距，在你一個人只想吃飽就走的情境下幾乎是零。

**3. 我的使用量有沒有真的碰到上限？**
如果你從來沒碰過週限額，Pro 方案通常就足夠了。如果你每次到重置前都在衝量，那有兩種情況：要麼你真的需要升級，要麼你只是被訂閱制的焦慮機制倒逼自己衝刺。後者不是真的需要，是被設計出來的需要。

夜市牛排好不好吃，端看你為什麼去夜市。訂閱費值不值，不是問這個工具好不好，而是問你有沒有用對地方。

## 分工實戰與額度管理：從時段配置到自動排程

在明確的框架下，日常工作的模型配置可以非常精確：

- 寫文章、整理思路：Sonnet，搭配中等推理強度（medium effort）。
- 一般程式任務：Opus，搭配中等推理強度（medium effort）。
- 複雜架構、跨檔案分析：Opus，搭配 high 或 max 的高推理強度。
- 在模型版本選擇上，如果新版本（例如過去的 4.7 相對 4.6）個人體感沒有顯著提升，不必急著切換；而到了 Opus 5.5，額度真的很省，五小時窗口也擴增了額度。

工作時段的選擇能直接化解尖峰稀釋。既然美東尖峰時段容易在 1 小時內撞牆，實務上的對策就是把重要工作排在台北時間早晨（北美深夜離峰）做。這也意外解釋了為什麼最近 Claude 在亞洲時區反而比較好用。

而在工具端，Claude Code 後來新增了額度重置後自動繼續的功能，不必死守在螢幕前等待；若五小時窗口被打滿但任務不能停下，可以透過離峰算力模式繼續執行，雖然速度較慢且同樣計入週額度，但至少能確保進度推進。

訂閱方案每個月附贈的等值 API credit，也必須好好善用。官方 Help Center 寫明，每月的 API credit 並不適用於互動式終端（切換登入模式吃不到它），它是專門提供給 API 與 Agent SDK 等非互動式場景使用的。

善用這筆額度，作者目前的用法是直接把它接到每天半夜都會跑的待辦晨報儀表板、電子報素材收集、每週 harness 維護自動排程之中。一開始盤點時會發現有些排程用上了 Opus，隱藏費用極高；改用 Sonnet 5.5 搭配調整 effort 與提示詞，最終能在維持相同品質的前提下，將開銷直接降低一半。

此外，這筆額度也可以用來做兩件事：一是自己設計任務評測集，測試不同模型在不同 effort 下的表現，找出子代理人最細部的派工設定；二是每週以 25 USD 為限，交給 AI 自主把低風險的待辦事項處理掉。而像作者面對 11 月初到期的 Cloud Session credit，想不到要用什麼的話，也是在到期前幾天切換模式把它用掉，避免額度過期浪費。

最後是管理的心態：訂閱額度是有限的資源，但它的稀缺感不應該扭曲你的工作判斷。

我見過有人因為害怕超量，把本來應該交給 AI 處理的事情拿回來手動做，結果省了 token 卻浪費了自己的時間。額度買來是讓你節省時間的，不是讓你精算哪些任務「值不值得」消耗的。如果距離重置只剩 5 分鐘，而額度還有 10% 沒用完？那就果斷拿去跑有價值的任務燒完。重置前你的額度是你的，不燒掉就只會直接蒸發。

## 限制與邊界備忘

各項方案與工具邊界集中彙整如下：

- 多人共享帳號存在極高的封號風險，切勿以此方式分攤成本；官方訂閱補貼高達數十倍，第三方 API 路由平台則按實際 token 計費，無法享有訂閱制的算力補貼。
- 方案升級存在非線性落差：5x 到 20x 方案標示的「增加 4 倍」僅適用於五小時滾動窗口，每週總額度實際僅增加 2 倍；Codex 方案的 7 天額度約折合 5 輪 5 小時窗口再略多一些。
- 快取與 API credit 的適用邊界：訂閱方案額度內的主對話快取時間為 1 小時，但子代理（subagent）、加購用量（usage credits）與 API key 的快取時間僅為 5 分鐘；每月贈送之 API credit 無法在互動式終端透過登入切換使用，僅限外部 API 與 Agent SDK。
- 輔助工具的隱形負擔：Skill 注入與 Cowork 沙盒介面皆會帶來額外的提示詞開銷與 context 負擔，容易加速額度耗盡或引發中斷，正式高強度工作建議以終端機命令行為主。
- 尖峰時段的容量稀釋：在北美工作時間的尖峰期，名義容量會因伺服器共享分母擴大而縮水，連續高強度調用下可能在 1 小時左右即觸發限制。

你一定有過這種經驗：去咖啡店或出差在機場等飛機時，不想背厚重的筆電，只想帶一台輕便的 iPad 出門；但當你真的需要處理正事——整理大量的專案文件、更新資料庫，或是讓電腦裡設定好的 AI 幫你跑一段長時間的任務——光靠 iPad 上的網頁版聊天視窗，根本使不上力。

因為你真正好用的工作環境、整理好的資料夾，全都在家裡或辦公室那台桌上型電腦裡。

很多人第一個想到的解法是裝「遠端桌面」軟體，把家裡電腦的整個螢幕畫面傳到 iPad 上操作。但實際用過就知道，在外面連遠端桌面往往是一場災難：游標跟不上指尖、畫面延遲卡頓，而且因為要一直傳送高畫質影像，iPad 的電量就像倒水一樣往下掉。

其實，如果你的日常工作不是寫程式，而是**寫文件、管理知識庫、指派任務給 AI 執行**，你根本不需要在 iPad 上「看到」家裡電腦的桌面畫面。你需要的只是一條穩定、省電的文字連線通道，讓你在 iPad 上打字下指令，由家裡的電腦在背景把活幹完。

## 為什麼放棄「看畫面」，反而能拿回九成生產力？

我自己平常大量使用 Claude Code（一款裝在電腦裡、能直接讀寫你電腦檔案並自動執行多步驟任務的 AI 助手）。對多數非工程背景的工作者來說，這類電腦端 AI 最強大的地方，是它能直接幫你整理散落各處的筆記、撰寫長篇文稿、或同時跑好幾項資料整理工作。

要讓 iPad 用上這股算力，核心思路只有一個：**把「傳送整個螢幕畫面」改成「只傳送文字指令與結果」。**

這樣做有三個立竿見影的好處：

1. **極度省電，能撐一整個下午**：因為只傳輸純文字，不傳送笨重的螢幕影像，耗電量比遠端桌面少非常多。帶著 11 吋 iPad 在外面工作，電池可以安穩撐過一整個下午。
2. **在咖啡店、機場也不怕卡頓或斷線**：文字傳輸需要的網路流量極小，就算公共場所的網路不穩，打字與看 AI 回應依然流暢。
3. **切去回訊息、網路瞬斷，工作進度也不會消失**：在 iPad 上我們很常切換到其他 App 看資料或回訊息。只要在電腦端加裝一個「工作狀態保留工具」，就算網路短暫斷開或你把 iPad 蓋上，家裡的電腦依然會繼續跑 AI 任務；等你重新連回去，畫面會一字不漏地停在你離開前的那一秒。

## 怎麼做到？只需要三個角色分工合作

這套做法不需要你懂網路架設，也不用去動家裡的路由器設定。整個流程只需要三個免費或輕量的工具互相配合，各自負責一件事：

### 1. 打通家裡與外面的私人通道（使用 Tailscale）
以前要從外面連回家裡的電腦，得設定一堆複雜的網路轉發規則。現在只要在 iPad 和家裡的電腦（我是用 Mac Mini）都裝上 **Tailscale**（一款幫你的不同裝置建立私人安全連線的軟體），兩邊登入同一個帳號，就設定完了。不管你人跟 iPad 在哪個網路環境下，都能像坐在家裡一樣直接連上電腦。

### 2. 在 iPad 上穩定顯示中文與抗斷線的對話視窗（使用 Moshi）
通道打通後，iPad 需要一個負責打字下指令、看電腦文字畫面的連線 App。多數同類型的連線工具對中文字的排版支援不好，字很容易跑位；我實測過幾款後，最終留下 **Moshi**（一款專為行動裝置設計、能穩定顯示中文字且抗斷線的文字連線 App）。它不僅中文字顯示最穩定，在咖啡店或機場這種網路容易波動的環境下，也比傳統連線方式更不容易斷線。

### 3. 讓工作進度在背景「永遠活著」的保險箱（使用 tmux）
如果你直接連線電腦跑 AI，一旦 iPad 切去別的 App 或網路斷掉，正在跑的任務可能就會跟著中斷。這時就要靠 **tmux**（一個裝在電腦端、能把工作視窗留在背景持續運作的終端機管理工具）。它就像在電腦裡開了一個不會關門的房間：你在房間裡請 Claude Code 跑長時間的任務，就算你人離開房間（iPad 斷線或切換畫面），AI 還是在裡面繼續做；你隨時推門回去，就能無縫接續原本的工作狀態。

## 我實際用起來的日常場景與體驗

在找到這套組合之前，我試過 Jump Desktop、VNC 等各種遠端桌面方案，用起來都不怎麼舒服——延遲感非常明顯，操作不流暢，電量消耗又快。那時候我意識到，我的目標不是在 iPad 上「看到」Mac 的畫面去修一個小問題，而是要在 iPad 上真正重建九成的日常生產力。

換成這套純文字連線組合後，我現在帶 11 吋 iPad 出門的日常工作流變得非常單純：

1. 在咖啡店打開 iPad 上的 Moshi，一鍵連回家裡的 Mac Mini。
2. 接回原本留在背景的工作視窗，裡面的檔案與 AI 對話還停在出門前的狀態。
3. 直接在裡面喚醒 Claude Code，開始寫文件、跑自動化助理任務、或是管理我的知識庫。
4. 如果同時有兩件事要做，我就把畫面一分為二：一邊讓 AI 跑任務，另一邊同步看執行紀錄。

整套操作下來，沒有遠端桌面的黏滯感，iPad 也不會發燙耗電。國外甚至有玩家用類似的文字連線思路，摸索出在 Tesla 車機螢幕上連回家裡跑 Claude Code 的用法——只要把「看畫面」的執念放下，能工作的場域其實比想像中自由很多。

## 你明天可以怎麼試？

如果你也想試試看「不帶筆電、只帶 iPad 出門指揮家裡電腦跑 AI」，不需要一次把所有指令學會，可以分三步慢慢體驗：

1. **先確認你的電腦端 AI 跑得起來**：先在家裡的電腦上試用像 Claude Code 這類能直接處理本機資料夾與文件的 AI 工具，挑一件你平常最花時間的文書或資料整理工作交給它。
2. **用最零門檻的方式連通兩台裝置**：在電腦與 iPad 都裝上 Tailscale 並登入同一帳號，體驗看看「不改任何網路設定就能在外連回家」的便利感。
3. **裝上連線 App 試跑一次外出工作**：在 iPad 裝好 Moshi 連回家裡電腦，試著在外面用 iPad 下指令讓家裡的電腦幫你整理一份文件。等你習慣這種輕量節奏後，再照著下一節的步驟把背景保留工具（tmux）加上去。

## 給想自己動手設定的人：技術細節與指令整理

如果你已經準備好要照著架設，或是想了解這套組合背後的技術規格與具體操作指令，以下是完整的設定原理與我實測過的避坑細節：

### 網路層：Tailscale 穿 NAT 零設定
* **運作原理**：Tailscale 會在你的裝置之間建立基於 WireGuard 的網狀網路（mesh network，讓多台裝置直接點對點加密互通的虛擬網路架構）。
* **省掉的設定**：因為它能自動穿透 NAT（網路位址轉譯，家用路由器把內部裝置隱藏在同一個對外網址後的機制），你完全不用動路由器設定、不用開連接埠（port）、也不用申請動態網域名稱（DDNS）。兩端裝好、登入同一個帳號，就能取得專屬的 Tailscale IP 直接連線。

### 終端層：為什麼選 Moshi 而不是其他 SSH App？
* **SSH（安全殼層協定，透過加密文字通道遠端操作另一台電腦的標準技術）App 比較**：我在 iPad 上實測過好幾個 SSH 終端 App：
  * **Termius**：介面漂亮，但在 CJK rendering（中日韓文字渲染排版）上有 bug，打中文字或看中文文件時排版會跑掉。
  * **Blink Shell**：也是可行的選項，但綜合比較下來，**Moshi** 在中文字顯示的穩定度上表現最好。
* **連線協定優勢**：傳統 SSH 走的是連線一斷就得重來的通道，而 Moshi 採用 **UDP 協定**（一種不維持死板長連線、改以快速封包傳遞資料的網路傳輸方式），因此在咖啡店、機場這類不穩定的網路環境下，比傳統 SSH 更能抵抗瞬斷。

### 工作狀態保留：tmux 常用操作與多工配置
* **為什麼必備**：SSH 連線本身只要一斷開，正在執行的程式就會被強制關閉。tmux 能讓工作階段（session）獨立留在 Mac Mini 上持續運作，不受 iPad 切換 App 或網路中斷影響，這對需要長時間執行的 Claude Code agent 任務來說是必備的保護。
* **日常四步指令與操作**：
  1. 在 iPad 打開 Moshi，輸入家裡 Mac Mini 的 Tailscale IP 建立連線。
  2. 輸入 `tmux attach` 接回先前已經開好的工作階段（session）。
  3. 在 tmux 環境裡啟動 Claude Code，正常下達工作指令（因為大多數場景是寫文件、跑 agent、管理知識庫，不需要像寫程式那樣逐行比對程式碼差異 `diff`，純文字介面就非常夠用）。
  4. 需要同時監看多項任務時，使用 `tmux split` 分割畫面（建立多個 pane 子視窗），就能一邊跑 agent 任務、一邊即時查看執行日誌（log）。

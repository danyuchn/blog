## 被原生介面拖垮的潛力股

很多人在酸 Gemini 不好用，但 99% 的人都沒發現一個事實：問題根本不在模型本身，而是 Google 自家的原生操作外殼（網頁版與官方終端工具 AGY）實在太爛，把整個體驗徹底拖垮。

最近看了 X 上的不少分析跟小道消息，我有一個預感：最快一個月，最遲年底，Gemini 會重回 agent 排名第二的位置。

一旦你用 API 或腳本把它接到別家的操作外殼，能力就會瞬間解放。我自己平常就很愛用 Gemini 3.8 Flash，主要有幾個原因：速度快、單次呼叫 API 定價實惠、訂閱制的調用額度量大管飽；偶爾拿來當主對話（當 Claude 額度快滿時），也能明顯感覺到它比 Codex 更容易合作。但更關鍵的是，它在寫作和多模態這兩項核心能力上，表現極其亮眼。

## 專心做大文豪與原生多模態霸主

在目前所有模型裡，Gemini 3.8 Flash 的原生多模態依然穩坐第一名，而在寫作潤稿上，它更是我心中的第一名。

不得不說，在各家都在瘋狂卷 coding 的情況下，Google 能做出一個寫作底子這麼強的模型，我真的很感激。「阿公」（或「雙子星阿公」）是我對 Gemini 的暱稱。社群自動發文如果改用 Gemini 來潤稿，文字會自然得多、不惹人厭得多，大家真的可以去換換模型試試看。如果在日常工作流裡讓 Claude Code 呼叫 Google 的終端工具來寫給人看的文件與信件，用起來更爽，簡直就是大文豪。

有次朋友傳東西給我看，我第一直覺就想到經典類戲劇《玫瑰瞳鈴眼》，當下派出大文豪雙子星阿公（Gemini 4 Argon）來編劇本。結果出來的效果太強了（認真），文筆好到狠甩其他模型幾十條街。別的模型寫起故事常常是「起承轉蛤」，邏輯段落接不上，但阿公寫出來是真的「起承轉合」，情節絲絲入扣。我完全覺得 Gemini 他們家根本不用去卷 coding，專心做大文豪就好。

## 每月 140 美元的御三家配置

在日常工作流中，我不建議只押寶單一模型，而是透過三家訂閱各取所長。我每個月 140 美元的御三家黃金搭配是這樣拆解的：

第一棒是每月 100 美元的 Claude。這個檔位會附贈 100 美元的 API 額度，我直接拿來跑自動化排程，底層只跑 Haiku 和 Sonnet；平常需要人機深度協作的任務，基本上都交給 Opus 5.5 med。

第二棒是每月 20 美元的 GPT。20 刀這個檔位已經是甜蜜點，因為現在的 Codex 根本不值得花上 100 刀（要花 100 刀以上都建議直接選 Claude）。這 20 刀主要買的是他們家斷崖式領先的生圖功能，以及電腦與瀏覽器操縱，而且全部由 Claude 來負責派工。模型方面只用 Luna 和 Terra 分擔粗工與審查；在 20 刀方案下硬要用 Sol 或 Astra，表現還不如直接用 Opus 5.5。

第三棒就是每月 20 美元的 Gemini（Google AI Pro 方案）。這 20 刀方案划算到令人咋舌，我算幾個實際用下來的帳給大家看：
- 5TB 雲端硬碟空間。
- 每月 200CU 的 Colab 算力：可以用來跑開源模型 qwen 3.8 27b。Google 大善人給的這 200CU 效期長達三個月，只要持續訂閱每個月都會進帳，並採三個月滾動過期。上個月我在上面開 A100 跑本地模型，轉錄幾百小時長度的音檔才花了 150CU，怎麼用都用不完，結果新的 200CU 又進帳了。
- 1000 點 Google Flow 額度：可以使用 2026 年 11 月發布、當時影片生成排名第一的 Omini 1.2 Flash 模型，能生成 330 秒的影片。光是把這項折算成 API 費用就已經超過 20 美元。劈柴你真的是大善人大善人大善人。
- 模型本體：有 Flash 3.8 量大管飽處理所有多模態任務，加上 Argon 大文豪專門掌管文字寫作。

## 調用眉角、風控與防護機制

要把這套配置用順，有些實際調用上的邊界與細節必須先摸清：

在額度分配上，網頁瀏覽器的額度跟 Google 終端工具（AGY）是完全分開計算的（順帶同場臭一下 GPT，你們真的智障）。因此遇到純粹的多模態任務，我會直接讓它去開瀏覽器，用網頁版裡的 Gemini 來處理。

在終端命令列調用上，直接下 `agy -p` 是完全可行的。重點要先看懂官方的風控機制：系統會偵測帶有其他家特徵的 system prompt，如果用反向代理直接把終端工具接到其他執行外殼，帳號很快就會被殺；但如果是純寫腳本，用 `agy -p "prompt"` 的方式來調用，我用了兩個多月，天天用、周周把額度打滿，目前為止都沒出過任何問題。

在任務指派與穩定度上，雜活之王其實就屬 Gemini 跟 Luna。但 Luna 沒有多模態，近期又被降智；Gemini 雖然作為 agent 能力已經堪用，但跟直接接 API 相比，幻覺率還是略高，偶爾也會出現提權越權的現象。因此在實務上，我都會為它掛上更嚴格的 hook，並讓 Claude Code 掛著 monitor 即時監控程序隨時盯著。

另外，Argon 大文豪雖然文筆極佳，但額度燃燒的速度確實有點驚人。不過聽說後續的 Gemini 4 Carbon 會非常強大，相當值得期待。

每個月花 140 刀把這三家串在一起，各司其職，體驗確實美滋滋。

## 附錄：名詞與設定說明

- **Harness**：指包裹模型的操作外殼與執行環境（如網頁版或命令列工具）。
- **AGY**：Google 的終端命令列工具。
- **Hook 與 Monitor**：Hook 是在 agent 執行操作前後自動攔截檢查的規則；Monitor 是即時監控程序。

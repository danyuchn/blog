你跟 AI 一起工作時，有沒有過這種感覺：它很聰明，但你就像在帶一個每五分鐘就要回頭請示一次的新人？

明明只是整理自己電腦裡的草稿、改壞了隨時可以還原的小事，它卻每做一步就停下來問你「可以嗎？」；好不容易忙完想收工了，問它「還有什麼要我決定的？」，它卻又發散出三條新支線，把真正需要你拍板的事藏在長篇大論中間；更別提當你在通勤路上用手機看回覆時，它還是照樣丟出密密麻麻的寬表格與流程圖，字小到根本沒辦法看。

很多人以為這是因為自己的提示詞（Prompt，也就是你下給 AI 的指令）寫得不夠好，於是每次開新對話就不斷重打同一句話。

前陣子我請 AI 翻了我自己過去三週的對話紀錄，看到數字時嚇了一跳：
- 「中間不用過問我」「我給你充分的自主性完成這項任務，中間不用過問我」，同樣意思的話我在 25 場對話裡講了 **28 次**。
- 「我要準備收斂了」「還有其他要我決定的事情嗎？」，這類收尾要求出現了 **35 次**；「報告進度、列出要我決定的事」出現了 **32 次**。

同一句話在三週內手打了快三十次，問題絕對不是你不會下指令，而是**我們一直用同一種預設狀態，去應付完全不同的工作階段**。

這篇文章想跟你分享一個不用懂寫程式也能馬上借鏡的做法：把你跟 AI 合作的過程拆成「衝刺、分流、收尾」三種工作模式，外加一個「電腦／手機」的閱讀開關。前半段我們完全不談程式，直接看這套方法怎麼運作、能帶來多大的改變，以及你明天打開 AI 就能直接複製貼上的對話範本；後半段則留給想自己動手打造外掛的人，完整公開背後的技術設計。

## 為什麼 AI 老是抓不到你的節奏？

我們在工作時，腦袋其實會自然切換狀態：
1. **剛開始衝刺時**：你希望對方放手去做，不要每改一行字就來敲門，除非是要對外寄信或花錢才需要叫你。
2. **手上有大批雜事時**：像是一次要分類幾百行資料、大量核對清單，你希望把這些粗活分流出去，把主力留給真正需要動腦的決策。
3. **準備下班或結束會議時**：你不想再聽新點子了，你只需要一張乾淨的清單，告訴你「還差哪兩個決定就能收工」。

但 AI 不知道你現在處於哪個階段。對它來說，每一則訊息都是獨立的：你不講，它為了安全起見就是每步都問；你不攔，它為了展現能力就是一直延伸新話題。

解決方法很簡單：**不要再靠臨場打字提醒，而是把這三種狀態定義成明確的「模式開關」。** 當你喊一聲切換模式，AI 就知道現在該遵守哪一套規矩。

## 三個工作模式＋一個裝置開關：用白話看它怎麼幫你

我在自己主力使用的 AI 工具 Claude Code（Anthropic 推出的 AI 工作與程式助手，能直接讀寫電腦裡的檔案並執行任務）裡面，把日常工作拆成了三個可以隨時切換、也能互相組合的模式，加上一個裝置切換開關：

[![三種模式加上裝置開關各自影響 AI 的哪個環節](/blog/assets/posts/work-mode-ai-working-modes/1-how-it-works.jpg)](/blog/assets/posts/work-mode-ai-working-modes/1-how-it-works.jpg)

### 1. 自主模式（Auto）：能還原的事直接做，高風險的事最後一次問
開了這個模式，只要是在我自己電腦上操作、改錯了隨時能用版本紀錄還原的事，AI 都不准停下來問我；就算撞到系統原本設定的安全提醒，系統也會直接告訴 AI「不要問使用者，請照標準做法自己修好繼續」。

那什麼時候必須停下來？只有四種高風險動作：**對外寄信或發訊息、付款、刪除救不回來的資料、更改權限設定**。遇到這些事，它會先記在待辦清單上，把手邊能做的都做完，最後再一次列出來讓我點頭。

### 2. 收斂模式（Wrap）：不准再開新支線，結尾只列「待拍板清單」
當工作接近尾聲、或者我準備離開座位時，我就會切到收斂模式。這個模式只有兩條死規矩：
- **不開新工作**，只把手上正在做的事情收完。
- **每一則回覆的結尾，必須列出「需要我拍板決定的事」**，而且每一項都要附上它的建議選項；如果已經沒有要決定的事，就提醒我可以正式收尾存檔。

### 3. 外派模式（Out）：正在等的事走最快的路，大批次雜活才分流
很多人同時訂了兩三家 AI（例如 Claude、ChatGPT 的 Codex、Google 的 Gemini），會想把查核、摘要、上百行逐條分類這類大量重複的工作「外派」給其他 AI 分擔，把主力 AI 的額度留給最重要的判斷。

但這裡有個我踩過大坑才學到的教訓：**千萬不要讓 AI「預設什麼都外派」。**

剛開始我寫了一堆規則叫它盡量外派，結果有一天我覺得 AI 變得很遲鈍，連我正在螢幕前等著要的小事，它也轉手派給外部工具；有一次外部服務剛好卡住，它就這樣讓我乾等了整整 **14 分鐘**沒有回報。

後來我跟 AI 討論出一個核心原則：**「做事效率優先於派工」——我正在等的事，走最快最穩的路直接交付；我沒在等的大批次工作，我打開外派模式時你再分流出去。** 而且它會自動看哪一邊的免費或訂閱額度還夠，如果某一家已經用超過九成，就自動改派給另一家。

### 4. 電腦／手機切換（At）：看我手上拿什麼，決定給我圖表還是三行字
這是我自己最喜歡的小開關。當我告訴它「我現在切到手機」，它接下來的回覆就會收起所有寬表格和流程圖，濃縮成幾行重點文字；等我回到桌前切回「電腦」，下一則回覆就立刻恢復成有圖表、有對照表的完整版面。

## 真實效果如何？一週 136 場對話的實測證據

這套模式做好之後，到底有沒有真的改變 AI 的習慣，還是只是自我感覺良好？

用滿一週後，我請 AI 直接調出我那一週（10/18 到 10/25）親自互動的 **136 場對話、共 1,098 個來回回合**（已排除系統在半夜自動執行的排程），把「沒開模式」的對話當作基準，跟「打開模式」之後的表現做了一場硬碰硬的對照：

[![一週實測的主要數字：收斂模式開啟後回覆結尾附決策清單從 10% 升到 86%，外派模式開啟後有外派的回合從 11% 升到 34% 至 55%](/blog/assets/posts/work-mode-ai-working-modes/3-results.jpg)](/blog/assets/posts/work-mode-ai-working-modes/3-results.jpg)

### 改變一：收尾不再大海撈針，附決策清單的比例從 10% 暴增到 86%
效果最驚人的是收斂模式（Wrap）。
- 沒開的時候，AI 在回覆結尾主動幫我整理「待決策清單」的比例只有 **10%**；打開之後直接跳升到 **86%**。
- 主動提醒我可以收工存檔的比例，也從 **3.5%** 升到 **26%**。
- 更棒的是，AI 的話變精簡了——平均每則回覆從 **878 字降到 647 字**，少了四分之一的廢話與發散。

你可以看下面這張實際對話的對照圖：左邊是沒開模式時，要我決定的事情散落在段落裡；右邊打開收斂模式後，結尾清清楚楚列出兩項待決事項，還附上它的建議，我只要回「照建議」就能下班。

[![同類的收工回報，開收斂模式前後的對照](/blog/assets/posts/work-mode-ai-working-modes/4-wrap-before-after.jpg)](/blog/assets/posts/work-mode-ai-working-modes/4-wrap-before-after.jpg)

### 改變二：手機不再滑到眼花，三行字就能掌握進度
切換裝置的效果也完全符合預期。我在同一場對話裡實際測試切換：切到手機後，它只用三行精簡文字回報結果，完全沒有表格；一按切回電腦，下一則立刻恢復成流程圖加完整對照表。

### 改變三：外派幫主力 AI 省下 14% 到 25% 額度，但老實說「省錢不省時」
在沒有開外派模式前，我曾經丟了四題測試給 AI，裡面甚至包含「960 行資料逐條分類」這種最該分流出去的苦工，結果四題它全部自己硬吞下來做完，一題都沒外派。

加上外派模式開關後，有把工作分流出去的回合從原本的 **11% 提升到 34% 至 55%**。算下來，那一週大約幫我省下了相當於 **230 到 480 美元**等值的主力 AI 額度（約占當週總用量的 **14% 到 25%**）。

不過數據也告訴我一個很誠實的真相：**外派省的是額度，不是時間。** 把複雜度差不多的任務放在一起比，有外派的回合反而要讓我多等 **20% 到 80%** 的時間。這也再次印證了前面的原則：趕時間、正在等的事自己做最快；不趕時間的大批雜事再開外派省額度。

### 意外抓到的盲點：人天生愛點選單，而且收尾時更需要「自主」
看數據還幫我抓到一個原本沒發現的設計瑕疵。那一週我總共切換了 **158 次**模式，結果顯示我 **100% 都是叫出選單用點的**，沒有任何一次是自己手打指令參數。

但第一版的選單「一次只能選一個模式」。這導致我前面開著「自主模式」順順地做，最後要收尾點了「收斂模式」時，自主模式就被自動關掉了！偏偏收尾存檔的階段，最容易遇到各種整理檔案的小關卡，自主模式被關掉反而讓它在最後一刻停下來問我。發現這件事之後，我立刻把選單改成可以「複選組合」（例如同時開自主＋收斂），最後一哩路才真正順暢起來。

[![複選選單：各模式可以勾選組合，選完後狀態列顯示目前開啟的模式](/blog/assets/posts/work-mode-ai-working-modes/2-menu.jpg)](/blog/assets/posts/work-mode-ai-working-modes/2-menu.jpg)

## 你明天可以怎麼試？八個溝通心法與一組照抄範本

就算你用的不是 Claude Code，而是日常的 ChatGPT、Claude 網頁版或各種 AI 助手，你一樣可以把這套「工作模式」的思維搬過去用。

下面這八句話，是我跟 AI 一步步磨出這套系統時**實際對它講的原話**。你可以直接看每句話背後的用法，換成你自己的工作情境：

### 1. 請 AI 幫你找出「最常重複講的話」
> 「還有mode是不是也要加一個中間不用過問我的，你去看 /history-find 我是不是也常講這句話，而且這個模式要避開現有hook會停下來等我確認的限制。」

- **你明天可以怎麼用**：如果你常在同一個專案對話裡跟 AI 合作，直接問它：「幫我回顧我們過去的對話，找出我最常對你重複叮嚀哪三句話？」重複次數最多的那句話，就值得你寫進固定指令或做成一個模式代號。

### 2. 當 AI 不照你的意思做時，先問原因、不要急著加新規定
> 「所以根據評測現在的結果，看起來是模型本身不愛派工？還是是因為harness的原因？你能同時深入分析嗎？」

- **你明天可以怎麼用**：很多人發現 AI 沒照做，第一反應就是再補三條規定，結果規定越多越亂。下次它不聽話時，先問它：「你剛剛沒有照某個方式做，是因為你預設的習慣如此，還是我前面給你的哪兩條指示互相衝突了？」先抓出病因再改。

### 3. 兩個目標拉扯時，把難題丟回給 AI 討論
> 「我現在也有一個困惑：到底要以派工效率為優先，還是要以做事效率為優先？你來跟我討論，給我建議，好不好？」

- **你明天可以怎麼用**：當你在「要快還是要省額度」「要詳細還是要簡短」之間猶豫時，不用自己硬想規則，直接把你的兩難丟給它，請它列出兩種做法的優缺點與建議，你只要最後拍板就好。

### 4. 用「拿掉這條你還會嗎？」幫指令瘦身
> 「原則同意你的改法 但是呢放在 claude.md以及其他harness的應該是越精簡越好 如果模型本來就已經知道，就不用放（拿掉會知道嗎 的標準）」

- **你明天可以怎麼用**：寫給 AI 的背景說明（像是自訂指令或專案說明檔）越長，它越容易抓不到重點。每次想加新規則時，先問它：「如果拿掉這一行，你本來就會這樣做嗎？」如果它本來就會，就大膽刪掉。

### 5. 過一週，請它拿真實對話紀錄來驗收
> 「我想知道這個mod是否有真實改變模型的行為？用 /history-find 撈過去一週的對話觀察」

- **你明天可以怎麼用**：改了提示詞或工作流程後，過幾天請 AI 幫你檢查：「看我們這幾天的對話，你覺得新的規則有發揮作用嗎？有沒有哪裡還是老樣子？」

### 6. 照你真實的偷懶習慣來設計口令
> 「改動的話我覺得就是直接讓我打指令加參數的時候 打入可任意組合的參數（順序不限） 這樣最簡單 而如果遇到互斥的狀況 你覺得該怎辦」

- **你明天可以怎麼用**：不要設計那種你自己都記不住的複雜口令。告訴 AI：「我很懶得打字，我希望只要打『收尾』兩個字，你就自動幫我做完 A、B、C 三件事；如果跟我原本的要求衝突，你覺得該怎麼處理？」

### 7. 請它幫你算算看「這樣省了多少成本或時間」
> 「那外派你幫我計算一下我省多少額度？我知道很難估算 你儘可能收集資料取估算值較好」

- **你明天可以怎麼用**：只要你是為了省時間或省錢而設計的流程，都可以請 AI 幫你粗估效益，並請它一併列出「這個估算有哪些不確定的地方」，幫你判斷值不值得繼續維持。

### 8. 固定不變的提醒，只在「切換的時候」講一次就好
> 「有什麼不破壞快取的方式嗎？如果不是注入系統提示，而是只是在切換後最新一則對話或者是壓縮後注入」

- **你明天可以怎麼用**：不需要每一則訊息都貼一大段規則給 AI。跟它約定好：「只有在我喊『切換成手機版』或『切換成收尾模式』的時候，你才改變做法，中間就照舊。」

### 直接複製：幫你的 AI 裝上工作模式的起手範本

如果你想在自己的 AI 工具裡建立一套專屬的工作模式，可以把下面這段文字複製起來，把括號裡的情境換成你的日常工作，直接貼給你的 AI：

```text
我想建立一套我們合作時的「工作模式開關」，讓我只要打一個簡短代號（或點選單），就能切換你的工作方式。

1. 先幫我回顧過去的對話（或我最常交代你的工作），找出我最常重複叮嚀的要求（例如「中間不用過問我」「準備收尾了，列出要我決定的事」「這批資料先做初步分類」），列出最常出現的三類。
2. 依這三類各設計一個簡短的模式代號。每個模式寫清楚：開著的時候你會怎麼做、什麼高風險的事情不管開不開都一定停下來問我（例如對外寄信、付款、刪除重要資料、改權限）。
3. 規則越精簡越好：你本來就會做的事不要寫進去。
4. 模式要能任意組合（例如同時開「自主＋收尾」），如果兩個模式互相衝突，請先提出你的建議處理方式。
5. 我有時在（電腦／手機）上看回覆：在電腦上請給我清楚的表格與架構，當我說「切到手機」時，請一律改用三到五行的精簡文字回覆。
```

如果你平常用的是網頁版或手機版 AI，看到這裡就可以直接去試了！哪怕只是今天下班前對 AI 試喊一句：**「我們進入收尾模式：不要再開新話題，請把目前進度收完，並在結尾只列出需要我拍板決定的事，每項附上你的建議。」** 你都會立刻感受到收工的速度快上好幾倍。

而如果你本身也有在用 Claude Code，想知道我是怎麼把這套機制做成狀態列看得見、能自動攔截確認視窗的外掛，下面最後一節就是留給你的技術拆解。

## 給想自己動手做的進階使用者：Claude Code 技術實作拆解

> 這一節是給想在 Claude Code 裡自行實作外掛（Mod）的讀者參考。如果你不需要自己寫設定檔，可以直接跳過本節，完全不影響前面的方法。

在 Claude Code 裡，這套工具叫做 `work-mode`，本質上是一個外掛模組（Mod，能掛載在對話流程各個節點上的擴充程式），搭配幾個在工具執行前做檢查的攔截腳本（Hook，也就是在 AI 準備執行某個動作前先幫你把關的檢查哨）。

### 1. 為什麼不直接改「系統提示」，而要塞在每則訊息後面？
剛開始最直覺的做法，是在組裝系統提示（`prompt.compose`，也就是對話最開頭給 AI 的固定背景說明）時，把目前的模式寫進去。但實測後發現兩個致命傷：
1. **對話中途不會即時更新**：系統提示只有在對話被壓縮（Compact，把過長的歷史對話濃縮摘要）或重開時才會重新建立。第一版的裝置開關就是寫在這裡，結果有一次我從遠端切回電腦後，整整**一個半小時**它都還以為我在用小螢幕。
2. **會打破快取（Cache），讓回應變慢又變貴**：AI 處理對話時，會把前面沒變過的內容存成快取（記憶暫存），不用每次重算。系統提示在最前端，只要改一個字，後面整串對話的快取就全部作廢。

因此，現在的做法是：**系統提示只放一段永遠不變的預設值（預設為電腦版格式），所有會變動的模式提醒，都在使用者送出訊息的那一刻（`classic.UserPromptSubmit`），動態附加在訊息尾巴（`additionalContext`）。**

[![一則訊息的時序：使用者送出後附上提醒，系統提示與既有對話的快取前綴保持不變](/blog/assets/posts/work-mode-ai-working-modes/7-message-sequence.jpg)](/blog/assets/posts/work-mode-ai-working-modes/7-message-sequence.jpg)

為了更省空間，四個功能附加提醒的頻率也不同：
- **收斂（Wrap）與外派（Out）**：開著的時候，每則訊息都會附加（外派會多帶一行目前的外部額度狀態）。
- **自主（Auto）與裝置（At）**：採用「只送一次」的設計。只有在剛打開、剛切換裝置，或是對話被壓縮、重開之後的第一則訊息才會送出提醒，並用旗標（`autoSent`、`deviceTold`）記住「已經講過了」。如果某一則訊息半路被其他檢查擋下來沒送進模型，旗標就不會變動，確保下一則重送時一定會補講。

[![兩個只送一次的狀態機](/blog/assets/posts/work-mode-ai-working-modes/9-send-once-state.jpg)](/blog/assets/posts/work-mode-ai-working-modes/9-send-once-state.jpg)

### 2. 整體架構與五個觸發事件
整個模組的進入點只有一個 `register.tsx`，底下分派給三個檔案：管工作模式的 `tempo.ts`、管電腦／手機切換的 `device.tsx`，以及管外派提醒的 `nudge.ts`。

[![work-mode 的架構圖](/blog/assets/posts/work-mode-ai-working-modes/6-architecture.jpg)](/blog/assets/posts/work-mode-ai-working-modes/6-architecture.jpg)

它們只監聽 Claude Code 的五個核心事件：

| 事件名稱 | 觸發時機 | 外掛做什麼事 |
|---|---|---|
| `session.start` | 對話剛開始 | 註冊 `/work-mode` 與 `/at` 兩個指令、把「已送出」旗標歸零、更新畫面下方的狀態列，並把目前模式寫進狀態檔 |
| `prompt.compose` | 組裝系統提示 | 放進一段固定不變的「電腦版回覆格式」說明 |
| `classic.SessionStart` | 清空、接續或分岔對話 | 重設自主模式與裝置的「已送出」狀態，確保下一則訊息會重新通知模型 |
| `session.compact` | 對話歷史被壓縮完成 | 主對話壓縮完後同樣重設「已送出」狀態，避免舊提醒在濃縮時被洗掉 |
| `classic.UserPromptSubmit` | 使用者按下送出訊息 | 把目前開啟的模式提醒文字塞進 `additionalContext`（若是子代理發出的訊息或被擋下的訊息則跳過） |

另外，當外派模式開啟時，`nudge.ts` 會額外監聽工具執行後的事件（`classic.PostToolUse`）：如果主線 AI 在同一個回合裡讀檔案、跑指令的輸出累積超過 20,000 字元，卻還沒有把工作派出去，就會在那個回合自動塞一次外派提醒。

### 3. 狀態存放在哪裡？
為了讓「同一場對話裡的模式互不干擾」，但「切換手機／電腦可以跨分頁同步」，狀態分別存在三個地方：
1. **單一對話記憶體（`$.state`）**：存這場對話目前開了哪些模式，不會影響旁邊同時開著的其他對話視窗。
2. **全域共用儲存區（`$.store`）**：存目前是電腦還是手機（`device`）。只要在任何一個視窗喊了切到手機，其他視窗在送出下一則訊息時就會自動同步。
3. **本機狀態檔（`~/.claude/state/tempo/<session_id>`）**：因為外部的 Shell 檢查腳本讀不到外掛內部的記憶體，所以每次切換模式時，外掛會同步寫一個以對話 ID 命名的 JSON 小檔案，讓下面的「自主模式檢查哨」讀取。

### 4. 自主模式（Auto）怎麼把「停下來問你」變成「AI 自己修」？
平常在 Claude Code 裡，我們會設定一些執行前的安全檢查哨（`PreToolUse` Hook）。遇到可疑動作時，檢查哨可以回傳兩種決定：
- **`ask`（詢問）**：畫面上跳出確認視窗，整個 AI 停下來等你按同意。
- **`deny`（拒絕並退回）**：**不跳視窗吵使用者**，而是直接把「拒絕原因」當作執行結果退回給 AI 看。

自主模式的秘訣就在這裡：對於那些「在自己電腦上、可以還原」的檢查哨，當它讀到狀態檔裡開著自主模式時，就會**把原本要回傳的 `ask` 換成 `deny`**，並在拒絕原因裡直接寫明：「不要停下來問使用者，請改成某某標準做法後直接繼續。」AI 收到這段話，就會自己摸摸鼻子修好再送一次，一週內就這樣默默幫我擋下並自動處理了 **10 次**原本會打斷我的確認視窗。

至於對外發信（Gmail、Slack、LINE）、讀寫機密憑證、刪除檔案（`rm`）或強制還原（`git reset --hard`）這些高風險檢查哨，則完全不接入這套切換機制，不管你有沒有開自主模式，該停下來問就一定停下來問。

[![PreToolUse 閘門的判斷流程](/blog/assets/posts/work-mode-ai-working-modes/8-gate-decision.jpg)](/blog/assets/posts/work-mode-ai-working-modes/8-gate-decision.jpg)

檢查哨讀取狀態檔的共用 Shell 函式（`tempo-auto.sh`）寫法如下：

```bash
tempo_mode_on() {  # 用法：tempo_mode_on "$INPUT" <mode>
  local sid f
  sid=$(printf '%s' "$1" | jq -r '.session_id // ""' 2>/dev/null) || return 1
  case "$sid" in ""|*/*|*..*) return 1;; esac   # 擋掉空值與不安全的路徑
  f="${TEMPO_STATE_DIR:-$HOME/.claude/state/tempo}/$sid"
  [ -f "$f" ] || return 1
  jq -e --arg m "$2" '((.modes // []) | index($m)) != null' "$f" >/dev/null 2>&1
}
tempo_auto_on() { tempo_mode_on "$1" autonomous; }
tempo_deny() {
  jq -n --arg r "$1" '{hookSpecificOutput:{hookEventName:"PreToolUse",
    permissionDecision:"deny",permissionDecisionReason:$r}}'
}
```

### 5. 參數任意組合與互斥邏輯
在解析 `/work-mode` 的參數時，不管使用者是用空白、逗號還是 `+` 號連接（例如 `/work-mode wrap auto`），也不管順序如何，都會統一轉成小寫並排序。如果使用者同時選了「外派（out）」與「收斂（wrap）」，因為都已經要收尾了不該再開新的外派工作，程式會自動讓「收斂」勝出，並把「外派」剔除：

```ts
// tempo.ts parseTempo（核心邏輯節錄）
const words = arg.toLowerCase().split(/[\s,+]+/).filter(Boolean)
if (words.length === 0) return { kind: 'status' }   // 不帶參數時直接打開複選選單
for (const w of words) {
  if (w === 'off') continue
  const mode = WORDS[w]                             // 對應到 autonomous、dispatch、converge
  if (!mode) return { kind: 'error', message: `Unknown mode "${w}".` }
  picked.add(mode)
}
if (picked.has('converge') && picked.has('dispatch')) {
  picked.delete('dispatch')                         // 外派與收斂同時選時，收斂優先
  note = 'out dropped: wrap and out exclude each other, wrap wins (jobs already out still finish).'
}
const modes = ORDER.filter(m => picked.has(m))
```

### 6. 想自己試做？只要 25 行程式碼的「最小收斂模式」
如果你也想在 Claude Code 裡動手做一個最簡單的模式開關，我最推薦先從**收斂模式（Wrap）**開始。因為它不需要連動外部的檢查哨腳本，也不用寫本機狀態檔，只要短短 25 行就能跑起來：

```ts
import { atom, read, update } from 'claude-code'
import type { Register } from 'claude-code'

// 記得在型別檔宣告 PluginState['my-wrap'] = { on: boolean }，並在 hooks.json 指向這支檔案
const wrapOn = atom({ plugin: 'my-wrap', key: 'on' } as const, false)
const TEXT = '[wrap] 不開新工作，把手上的收完。回覆結尾列出需要使用者決定的事，每項附建議；沒事了就建議收尾。'

export const register: Register = on => {
  on('session.start', async ($, e, next) => {
    await $.command.register({ name: 'wrap', description: 'wrap on | off', immediate: true })
    return next(e)
  })
  on('command.run', { command: 'wrap' }, async ($, e) => {
    const v = e.args.trim() !== 'off'
    await update($, wrapOn, () => v)
    $.ui.status(v ? 'WRAP' : undefined)
    return { text: v ? 'wrap on' : 'wrap off' }
  })
  on('classic.UserPromptSubmit', async ($, e, next) => {
    const r = await next(e)
    if (e.agent_id || r.block || r.preventContinuation || !(await read($, wrapOn))) return r
    return { ...r, additionalContext: [...(r.additionalContext ?? []), TEXT] }
  })
}
```

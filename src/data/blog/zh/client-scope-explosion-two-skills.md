我原本以為只有我自己一個人會在跟 Claude 對話時資訊負載量過高、會看不懂他說的話，後來今天才發現我並不孤單，我的客戶也有一樣的問題。

今天，我們一起把他跟 Claude 討論公司內部月報的超長對話打開來看，才發現問題所在。他一開始第一則問的是：今年年底前營業額要做多少才不虧錢。然後還給了大量資料跟想法。我大概看過去，心想：提示詞寫得很詳細嘛。

但是往下捲一兩個回合，AI 已經在跟他討論要不要恢復投廣告了。

我：？？？？？？

再往回看，我才發現那一大串 prompt 裡面夾雜三個東西：問業績，問之後是不是還需要一個儀表板，還問這個經營策略正確與否。等於他把資料、指標、決策，全部塞在同一段對話裡。然後當 AI 一次回他的時候，scope 太分散資訊密度也太高，他就直接爆！掉！了！完全看不懂意思。

但是他面對爆掉的應對，是岔開話題，繼續去問有沒有其他的指標。這只是讓 scope 繼續發散，而 Claude 就陪著他發散，沒有勇氣主動幫他收斂，告訴他「你飄走了」，等於 Claude 也被他帶跑了。

所以我當場幫他裝了兩個我自己每天在用的 skill：

第一個是 `/explain`。你開始覺得看不懂就用這個 skill。它會把剛剛那段用高中生都看得懂的大白話重講，不懂就用，不准裝懂。

第二個是 `/first-principles`。你自己思考卡關、迷航時就用，他會用 Elon Musk 的第一性原理先問「這件事拿掉會怎樣」，能砍就砍，挑戰所有內建假設，砍完再從最根本的事實重建推理。我們拿它審了整段對話，結論是他要的那些精確數字有一半是根本用不到的，AI 帶他做的那些報表有很多是為做而做的，而真正會影響他的營運本質的，卻都還沒有被碰觸到。

當場用了這兩個 skill 後，我問他「你認同嗎？有感覺討論收斂嗎？」

他回了我一句意味深長的話：

> 我終於知道以前的員工為什麼說「跟我工作很累」了

今天我帶給他的，是讓 AI 有勇氣把他的發散思緒拉回來的 skill。

如果你也想要試試同樣的 skill，可以參考：<https://github.com/agentcrew-academy/harness-starter-kit>

## 另一個客戶，同樣的毛病：CEO 級的發散

同樣的毛病我在另一個客戶身上也遇過，等級更高。

這位客戶是一間小公司的 CEO，才幹很好、業務也很熟，但最大的短板有兩個：所有業務都停留在人治，know-how 跟流程全存在他的記憶跟經驗裡；思維太靈活，跟 AI 合作反而太發散。過去我們已經幫他把散落各處的原始資料收整過一輪，該接 API 的接了，接不了的也落成檔案讓 AI 讀得到，光是這一步就贏過很多人了。

那天的 session 我們回顧他跟 AI 協作的過程，發現真實的問題：他會跟 AI 展開非常多對話——談業績計算公式、監控指標——但每一個對話窗都停在 AI 的回應那裡，沒有寫日誌、沒有結論、沒有版本控制，什麼都沒有。他一直在跟 AI 腦力激盪，卻完全沒有落地。檔案名字有的叫「老版本」有的叫「已淘汰」，同樣性質的欄位格式各自不同——不同對話裡的 agent 根本沒有一套規矩，前後飄移得很嚴重。

那天做的事就是「立規矩」：逼他用 Grill-me skill 把所有 spec 設定清楚，檔名格式、資料夾結構、內部欄位，不准「再看看先這樣」；把定下來的 spec 落檔連上 CLAUDE.md 引用，另外設計 lint 腳本接 hook，規則面跟閘門面雙重確保；做一個收尾的 checkpoint skill，內含 git commit、push、寫 daily log、更新進度檔，讓他未來每一步都可以溯源。我提醒他：沒落檔就不算數，任何對話中只要離開座位，哪怕是上廁所，也要先 checkpoint。

結束後的感想：這些對工程師、軟體開發者來說應該都是常識，但出了編程圈之外，還是有很多人不知道也需要這些知識。知識的詛咒一直都存在——自己習以為常的東西，在同溫層之外其實是很寶貴的技能。

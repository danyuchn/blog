你是不是也有過這種經驗：平常在網頁上跟 AI 聊天、改改信件都很順，但當你聽說現在的 AI 工具（像是 Claude Code，一款能直接讀寫你電腦檔案、幫你執行任務的 AI 助手）可以直接幫你整理整包講義、改文件、跑專案，興沖沖打開來看，卻立刻卡在第一個問題——

我到底該下載畫面漂亮、可以用滑鼠點的「桌面版應用程式」，還是打開那個黑底白字、看起來像駭客在用的「終端機」（命令列介面，也就是沒有按鈕、純粹靠打字下指令的文字視窗）？

更讓人一頭霧水的是，身邊同樣買了高階付費方案（Max 方案）的朋友，有人用圖形化的協作模式做幾個小時的小專案，系統就跳出通知說「額度用光了」；有人卻能從早到晚開著 AI 處理工作，一整天連一半的額度都花不到。

到底差別在哪裡？沒有程式背景的老師、主管或專業工作者，又該從哪裡開始？

過去一年裡，我被問過無數次「該用終端機還是桌面版」。老實說，我自己寫過五篇文章討論這件事，而我的答案在一年內變了三次——三月和四月我說「終端機，沒得商量」，五月我改口說「初學者直接從桌面版開始就好」，到了八月我又忍不住感嘆「終端機才是原廠親生的」。

這不是因為我善變，而是工具演進得太快。把這一年的踩坑與實測攤開來看，如果你今天想讓 AI 真正走進你的日常工作，你不需要先去背任何電腦指令，只需要掌握下面這套「先求順手、再求效率」的做法。

## 明天就能試：不用寫程式，把 AI 變成高效工作流的三個做法

如果你主要的工作是寫文件、整理資料、規劃專案，而不是天天寫程式，請照著這三個步驟走：

### 第一步：第一天先開「桌面版」，別被黑底白字的畫面擋在門外

很多人以為要用好進階 AI 工具，第一天就得逼自己學會看黑底白字的終端機。現在完全不用了。

自從官方把桌面版應用程式（Claude Desktop App）大翻新之後，它已經涵蓋了終端機九成以上的功能。如果你的日常場景是「跟 AI 對話、寫文件、整理資料」，桌面版友善的畫面完全夠用。先在熟悉的視窗介面裡摸熟「怎麼吩咐 AI 讀資料夾、怎麼讓它幫你改稿」，等過了半年，你發現自己想做更多自動化、或者覺得視窗介面限制住你了，那時候再花一個下午學終端機都來得及。把順序顛倒過來，第一天就被一堆設定擋住，反而最容易放棄。

### 第二步：看懂「為什麼額度會瞬間燒光」——少用包山包海的圖形沙盒，多用純文字對話

為什麼同樣訂了高階方案，有人幾小時就撞到使用上限？關鍵在於你讓 AI 用什麼方式工作。

有些強調全自動、有圖形畫面的協作模式（例如 Cowork），就像請了一個助理坐進一間獨立的虛擬辦公室裡，他每做一個動作，都要「把整個螢幕截圖拍下來看一遍」，還要把整份文件從頭到尾重讀一次，並且把前面每一步的對話紀錄全部背在身上。看圖片對 AI 來說是非常昂貴的消耗，加上動作慢，一件在純文字模式下 5 分鐘能做完的事，在那裡可能要拖上 40 分鐘；拖得越久，累積的歷史包袱越重，額度就像開了水龍頭一樣流光。

相反地，在純文字主導的工作模式（無論是桌面版裡的 Code 對話，或是終端機介面）下，AI 不需要截圖看畫面，而且能做到「只讀你指定的段落、重複的規則不重複扣額度」。當你把不必要的畫面雜訊拿掉，不僅額度省下好幾倍，你還會明顯感覺到同一個 AI 模型「變聰明了」——因為它能把所有的腦力都花在解決你的問題上，而不是浪費在理解複雜的畫面環境。

### 第三步：打破「乾等 AI 回覆」的習慣——三線並行加上語音派工

多數人用 AI 的方式是「問一個問題、盯著螢幕等它跑完、再問下一個問題」。只要換個工作習慣，你的產出效率馬上可以翻倍：

1. **開三個對話視窗分頭跑，把等待時間變成零**：
   你可以同時開三個對話（Session），像帶三位助理一樣分工：
   - **一號視窗跑長任務**：丟給它需要跑比較久的工作（例如大批量整理資料、抓取檔案）。
   - **二號視窗處理手邊的主力工作**：例如請它陪你改文章、整理會議記錄或調整文件結構。
   - **三號視窗負責快問快答**：隨時查一個小資料、確認某個細節。
   當一號視窗在忙的時候，你就在二號或三號視窗下指令，工作節奏完全不會中斷。

2. **用「語音輸入」直接口述派工，不回頭改錯字**：
   下指令給 AI 時，不需要像寫公文一樣字斟句酌。你可以直接打開電腦的語音輸入對著它講話——就算語音辨識出來的格式慘不忍睹、整篇錯字、還夾雜著「嗯嗯啊啊」的口頭禪，現在的 AI 都能從前後文看懂你的意思。用嘴巴交代任務、用眼睛看文字確認結果，不用分心去點選滑鼠按鈕，是目前最流暢的人機協作方式。

## 一年三次改口：我自己在實務上踩過的真實證據

上面這套「先用桌面版上手、避開高消耗圖形沙盒、再用多視窗與語音提速」的建議，是我花了一整年真金白銀與工作時間換來的。回頭看我這一年在三個時間點的立場轉變，你就能更清楚什麼時候該用哪個工具。

### 2026 年 3 月：一場「幾小時頂到限額」的震撼教育

三月時，很多訂了 Max 方案的人跑來問我：為什麼用終端機跑整天工作，用量從來不超過一半；但切換到 Cowork（圖形化協作環境）做幾小時的小專案，額度就見底了？

我實測換算後發現，Cowork 消耗額度（Token，AI 計算字數與收費的基本單位）的速度遠高於終端機版的 Claude Code。一個做複雜檔案操作的 Cowork 任務，消耗的額度相當於幾十條普通聊天訊息。官方標榜 Max 5x 方案每階段有「225+ 條訊息」的額度，一旦換算成 Cowork，大概只能做 10 到 20 個實質操作。

這不是我一個人的體感。當時網路社群與開發者論壇上有大量實測回報：有人回報額度消耗速度比以前快了 4 倍以上，也有人在 Threads 上直言它「燒額度的速度比 Claude Code 快太多（Burns limits way faster than Claude Code）」、「在 Claude Code 裡 5 分鐘的任務，到 Cowork 變成 40 分鐘（5min task in CC → 40min in Cowork）」。相比之下，隔壁棚的 ChatGPT Work 在這類沙盒體驗上就成熟得多。因此那時候我的建議很直接：非必要，別去碰會狂吃額度的圖形沙盒。

### 2026 年 4 月：電腦卡頓與「一天更新兩次」的落差，讓我死守終端機

四月時，官方推出了改版後的桌面版應用程式，介面變得更漂亮友善。

![Redesigning Claude Code on desktop for parallel agents](/blog/images/claude-desktop-redesign.jpg)

但當時如果你問我日常用哪個，我的答案還是「終端機，沒得商量」。原因有兩個非常現實的工作痛點：

第一是**電腦會不會卡**。我的主力電腦是 M2 MacBook Air，當時只要開著桌面版 App 做其他事，整台機器就會明顯遲鈍卡頓；類似 VSCode 這類帶有豐富圖形介面的編輯器，吃掉的電腦資源也是純文字終端機的好幾倍。相反地，我開著終端機軟體（Ghostty），同時開 3 個視窗、每個視窗切 3 到 4 個分割畫面，同時跑 5 到 6 個 AI 對話視窗，電腦依然輕快流暢。對我是 PTT 世代的人來說，黑底白字不只親切，更是實打實的速度差距。

第二是**修問題的速度**。當時終端機版幾乎每天都有 1 到 2 個版本更新，而桌面版 App 要等 2 到 4 週才更新一次。例如三月底的一次更新（2.1.86 版），一口氣修掉了「處理大型檔案時白白浪費額度」以及「對話太長導致電腦記憶體暴增」兩個大問題。用終端機的我當天就拿到修復，用桌面版的人卻還得忍受好幾個禮拜。那時我寫下一段話：「選擇終端機不只是技術偏好，也是一種對 AI 工作方式的態度宣示——你要的是完整的能力，哪怕入門成本稍高一點，長期下來有複利。」

### 2026 年 5 月：桌面版大翻新，我第一次建議初學者「從桌面版開始」

才過了一個月，我的答案變了。

五月中旬前，官方把桌面版 App 大幅翻新，一口氣把九成以上的功能都跟終端機同步，更新速度也跟上來了。更關鍵的一個體悟是：雖然最新功能還是會在終端機先上線，但**最新的功能爛尾或出錯的機率其實很大**。官方推出新功能的速度永遠比後續修補來得快，一般工作者根本沒有必要去當白老鼠、被各種初期錯誤困擾。等新功能在終端機上測試穩定了、搬到桌面版再用，反而是更舒服的選擇。

也就是從這時候開始，我對所有初學者改口：直接從桌面版開始，完全沒問題。

### 2026 年 8 月至 10 月：當你走到重度使用，終端機依然是「親生的」

到了八月，當我想在手機等行動裝置上遠端操控 AI 工作時，又再次感受到原廠對不同介面的「偏心」。

因為官方工程師自己天天都在用終端機，所以任何新功能或修補都會優先給終端機；至於其他周邊介面（像是官方的遠端控制功能 remote control），更新就慢吞吞——甚至連「打斜線叫出常用指令選單」這種基本功能，都是推出三個月後才修好。雖然八月時終端機也曾罕見地停更了 8 天、系統問題清單（Issues）一度維持在五千筆上下，但整體而言，終端機依然是功能最完整的第一現場。到了十月下旬，官方也終於把桌面版與終端機的底層設定檔打通，讓兩邊的切換變得更加無縫。

這三次答案的變化擺在一起，其實就是一條最清晰的學習曲線：**入門靠桌面版跨過門檻，日常靠純文字與多視窗省下額度與時間，進階重度使用再靠終端機解放全部潛力。**

## 給想自己動手的人：底層機制與進階環境設定

如果你讀到這裡，想進一步了解前面提到的「額度消耗差異」在技術底層是怎麼發生的，或者你已經準備好要嘗試終端機與多視窗配置，以下是完整的技術細節。

### 1. Cowork 與 CLI（命令列介面）的 Token 消耗架構差異

為什麼在第一節中，我們說 Cowork 的消耗遠高於 Claude Code CLI？在技術架構上有三層原因：

- **沙盒虛擬機（Sandboxed VM）的隱藏開銷**：
  Cowork 運行在隔離的虛擬機環境中，每次操作背後會觸發：
  1. **截圖與圖片處理**：視覺 Token（Vision token）計費遠高於純文字。
  2. **多次推理呼叫**：單一任務背後可能觸發 5 到 10 次（甚至十幾次）API call（應用程式介面呼叫）。
  3. **整檔讀入 Context（上下文視窗，即 AI 單次對話能讀取的記憶空間）**：無法像 CLI 一樣精準控制只讀取需要的段落。
  4. **完整歷史疊加**：每一步都夾帶前面所有步驟的紀錄，搭配較慢的執行速度（5 分鐘對比 40 分鐘），形成 Context 越滾越大的惡性循環。
- **CLI 的節流機制**：
  - **快取機制（Prompt caching）**：系統提示詞（System prompt）、規則設定檔（`CLAUDE.md`）與工具定義等重複內容會被快取，新開對話（Session）時不重複計費。
  - **按需載入（On-demand loading）**：可透過 `CLAUDE.md` 架構精準控制只載入需要的檔案與自訂技能（Skill），且完全省去視覺 Token 開銷。
- **相關查證紀錄**：
  這項差距在 Anthropic 的 GitHub Issues 中有明確紀錄，包含 `#16856`（用戶回報 Token 消耗速度加快 4 倍以上）、`#23318`（多人確認用量異常）、`#33120`（Cowork 專屬的速率限制 rate limit 問題）。分析師 Zvi Mowshowitz 的專文比對也指出，兩者的核心差距正是 Context control（上下文控制）。

### 2. 版本更新紀錄與設定檔路徑演進

- **版本修復實例**：
  - 2026 年 3 月底的 `v2.1.86` 版，修復了大型檔案 JSON 跳脫字元導致的 Token 虛耗，以及長時間對話（Session）的記憶體暴增問題。
  - 2026 年 8 月中旬（`v2.1.220` 版前後），向來一天一更的 CLI 曾出現連續 8 天未更新的現象，當時經機器人去重後的 GitHub Issues 仍穩定在 5,000 筆以上。

![anthropics/claude-code repo 的 GitHub 頁面，Issues 顯示 5k+，最新 commit 標著 v2.1.220、committed last week](/blog/assets/posts/cli-vs-desktop-three-answers/3-cli-no-update.jpg)

- **設定檔與環境變數（PATH）的打通**：
  在 2026 年 4 月時，CLI 與桌面版讀取的是完全獨立的設定檔（CLI 讀取 `~/.claude.json`，桌面版讀取 `~/Library/Application Support/Claude/claude_desktop_config.json`），且桌面版當時不繼承系統 Shell 的 `PATH` 環境變數，因此配置外部擴充工具（MCP server，讓 AI 連接外部服務的標準介面）時，若只寫 `uvx` 會找不到指令，必須填寫完整路徑（如 `~/.local/bin/uvx`）。
  **2026 年 10 月 20 日更新**：這項限制已經解除。現在桌面版的 Code session 與 CLI 讀取的是同一套設定檔，在 macOS 上也會自動從 shell profile 抓取 `PATH`。

### 3. 進階終端機工具鏈：Ghostty、多視窗與行動端連線

當你需要用到剩下的 10% 進階功能——例如自動觸發腳本（Hook）、子代理（Subagent）細部控制、或是與版本控制（`git`）、影音處理工具（`ffmpeg`、`yt-dlp`）串成混合工作流時，可以採用以下配置：

- **終端機軟體 Ghostty**：
  Claude Code 主要維護者 Boris 曾提到：「雖然我自己在用 iTerm2，但整個 Anthropic 團隊推薦 Ghostty。」從 iTerm2 轉移到 Ghostty 的三大優勢是：採用 GPU 硬體加速渲染（捲動與反應極快）、中英文字體可分開指定最佳化、以及純文字設定檔易於版本控管。你可以直接請 Claude Code 幫你修改 Ghostty 設定檔來測試最舒適的字體組合。

![Ghostty 終端機截圖](/blog/images/micro-notes/ghostty.jpg)

- **多視窗與手機遠端分割畫面**：
  在電腦上可利用 Ghostty 的多分頁或 `tmux`（終端機視窗分割管理工具）同時管理多個 Session。而在行動裝置上，由於官方的雲端遠端控制（remote control）更新較慢（早期曾長達三個月無法在輸入斜線 `/` 時跳出 Skill 提示選單）且缺乏分割畫面（Split pane），進階做法是直接從手機透過 `mosh`（支援斷線自動重連的遠端連線工具）連回桌機（如 Mac mini）跑 CLI，就能在手機螢幕上同時上下開啟兩個獨立的 CLI 對話視窗同步作業。

![手機上透過 mosh 連回 Mac mini 跑 CLI，畫面是 agent 正在把一批 gog CLI 的工具陷阱寫進文件的 diff](/blog/assets/posts/cli-vs-desktop-three-answers/1-remote-control.jpg)

![手機畫面上下同時開著兩個 pane，各自是一個獨立的 CLI session](/blog/assets/posts/cli-vs-desktop-three-answers/2-no-split-pane.jpg)

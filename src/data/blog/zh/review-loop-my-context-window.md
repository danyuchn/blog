## 起因是一位網友的注意力耗弱

有位脆友說，跟 agent 協作會注意力耗弱。我一看就知道那是什麼感覺，因為我跟他一樣。這才發現我的 Context Window 比當今大模型還脆弱。

## 請他把想法完整做成一份報告書

我給那位網友的建議是：請他把他的想法完整做成 html 報告書（也就是 artifact）。

然後你打開錄音程式用錄音的，不要看到 agent 回什麼就立刻打字回，邊看邊對錄音機講你的看法跟疑問。一個章節一個章節專心講你的審查意見。

我常常這樣子針對好幾份 context 完全不同的文件，專心錄音審查，盡情說出我的想法跟推理論述嘗試說服 agent，往往就是一個小時多，但是可以非常專心進入心流狀態。

## 錄音怎麼接回 agent

錄完之後，用我這篇教的方法配置 gemini：[語音下指令的兩種習慣](/blog/posts/zh/voice-input-two-modes/)，讓 agent 幫你一次語音轉錄，再根據你的意見去修改 html，或者提出他的看法。

但是要標註哪些已經有共識，哪些他同意哪些不同意，方便第二輪範圍更收斂。

## 他跑的那二十分鐘，我去做別的事

通常他這個修改都會十幾二十分鐘，我就會去做家事、吃飯或者運動，讓腦子休息。

等於自己幫自己壓縮上下文，避免精神耗弱。

回來就可以看到新的 v2 文檔，你就可以又有精力對較小的範圍跟他做辯論了。

## 所以我把它做成 SKILL

我把這套流程開源成一個文檔審查 SKILL，希望邀請脆友來試看看。

流程就是上面那套：請 Agent 對某個想法出完整提案書，我專注用錄音或者逐格打字的方式完整審查給出每個細節的意見，再把這些意見統一交給 agent 調查、重構或修改提案。通常完整意見交給他之後，他就會開始自己運作幾十分鐘再出第二版，中間我就會跑去吃飯、運動或做家事。

<https://github.com/agentcrew-academy/harness-starter-kit/tree/main/skills/review-loop>

## 跟官方 Plan Mode 不一樣的地方

兩點。

一是他可以用 artifact 讓你跟他互動。

二是有防止不同版本間內容靜默消失飄移的內容鎖定機制。

你有沒有過這種疲勞：上週才跟 AI 討論完一個大案子，交代了一整串背景、做了一堆決定；結果這禮拜開一個新對話，它就像失憶一樣，所有前因後果都要你從頭講起？

或者，你的筆記軟體和待辦清單越用越亂：某天想找三週前存過的書籤，翻了十分鐘找不到；打開待辦清單，發現同一件事被記在兩個地方，卻不知道哪個才是最新的。每一件小事單獨看都不嚴重，但合在一起，就是「這個系統我已經不太信任了」。

很多人的直覺是去找更酷炫的筆記軟體，或是期待 AI 廠商推出更強的記憶功能。但在我看來，真正的解法其實很樸素：**模型的長期記憶不能存在模型那裡，要存在你自己這裡。**

當你把日常的決定、踩過的坑、所有大大小小的待辦事項，全都放在電腦裡同一個地方，再讓 AI 直接去讀寫它——你不只治好了 AI 的失憶症，連每天寫日報、排待辦的麻煩都一併解決了。

這就是為什麼我最後選擇了 Obsidian（一款把所有筆記用純文字檔存在自己電腦裡的免費筆記軟體），並把它跟 Claude Code（Anthropic 推出的桌面端 AI 工具，可以直接讀寫你電腦裡的資料夾與檔案）接在一起。

這篇文章想跟你分享：這套「把東西放在一個地方，讓 AI 也看得到」的做法怎麼運作、你明天可以怎麼用兩件小事開始第一步，以及當筆記越長越大之後，怎麼靠 AI 幫你大掃除。至於設定檔、自動化指令與底層清理的技術細節，我全部放在文章最後一節，給想自己動手設定的人參考。

## 為什麼是本機筆記，而不是 Notion 或雲端對話紀錄？

我會用 Obsidian，不是因為它有多漂亮的介面，也不是因為哪個生產力 YouTuber 推薦，而是因為一個字：**本地**。

我們每天跟 AI 講的東西、做的決定、學到的教訓，如果只留在當下的聊天視窗裡，下個月再開新對話，AI 完全不知道之前發生過什麼。就算廠商提供了雲端記憶，那個記憶的所有權也不在你手上。

那為什麼不用 Notion 這類雲端筆記？因為雲端工具的資料存在別人的伺服器上，匯出格式有限，而且你永遠不知道廠商什麼時候會改連線規則、改定價、改政策。更實際的問題是，要讓 AI 讀取雲端筆記，中間必須透過 API（不同軟體之間傳遞資料的轉接介面）串接——多一層轉接，就多一個可能壞掉的斷點。

相反地，Obsidian 裡的所有筆記，本質上都是存在你電腦硬碟裡的 Markdown 檔案（一種輕量的純文字格式，副檔名是 `.md`，任何文字編輯器都能打開）。Obsidian 本身其實就是一個閱讀器而已，哪天這個軟體消失了，你的資料還是完整留在電腦裡。而且因為檔案就在本機，AI 可以直接讀寫，不需要任何中間層。

簡單、可靠、不依賴任何服務商。這才是知識管理工具該有的樣子。

前陣子網路上有一波討論說「該揚棄 Markdown，HTML（網頁用的排版格式）才是未來」。我不覺得這是誰淘汰誰的問題，就像問「該買運動鞋還是皮鞋」一樣，要看你下一步是去打球還是去開會。HTML 適合「發布給其他人看」，而 Markdown 適合「給未來的自己加上 AI 一起看」。在建立個人知識庫這件事上，純文字的本機檔案依然是最穩固的地基。

## 當 AI 讀得到你的筆記庫，日常工作會變成什麼樣子？

當你的筆記庫裡放了工作日誌、靈感、各專案的狀態與待辦事項，並且讓 AI 直接接入之後，日常工作會出現三個很明顯的改變。

### 1. 不用刻意寫日報，工作本身就是日報

以前寫工作日誌是一件要額外花力氣的事。現在我在跟 AI 工作的對話視窗裡，只要做完一個段落，就請 AI 把剛剛完成的工作打上時間標籤，直接寫進當天的每日筆記裡。到了每個禮拜結束，再把這一週的每日紀錄彙整成週報，過去做了哪些事一目了然。你不用再為了「寫日報」而寫日報。

### 2. 早上問一句「今天我要做什麼」，讓 AI 幫你分流待辦

把待辦事項都放進筆記庫的好處是，AI 可以隨時幫你分辨哪些是「阻塞待辦」（需要等別的事情完成、或別人配合才能往下做的），哪些是「非阻塞待辦」（現在馬上就能動手辦到的）。

我常常在工作開始時直接問 AI：「今天我要做什麼？」它就會從我的筆記庫裡撈出所有待辦、幫我排好優先順序；甚至在我跟它討論工作的空檔，它就能順手把那些馬上能辦的非阻塞項目先處理掉。

### 3. 兩條動脈互查，找資料不再大海撈針

很多人用筆記軟體最大的痛點，是東西放進去就再也找不到了。要解決這個問題，重點不在軟體功能，而在知識庫的結構。我的筆記庫主要靠兩條動脈在運轉：

- **時間軸**（每日筆記、每週覆盤）：記錄「什麼時候發生了什麼事」。
- **主題軸**（進行中的專案、人生主軸、重要決策紀錄）：記錄「每個主題目前的最新狀態」。

這兩條線怎麼連起來？靠的是雙向連結（在筆記裡用 `[[主題名稱]]` 的括號語法，點擊就能跳轉到另一篇筆記的內部連結）。每天的日記會連到當天碰過的專案或主題；反過來，每個主題檔下面也會反向連回相關的日記。這樣不管你是只記得「大概是上禮拜聊到的」，還是只記得「跟某個專案有關」，從任何一邊點進去，都能順著連結找回完整的來龍去脈。

## 你的第一步：寫完才整理，不要先設計再寫

看到這裡，你可能會想：「所以我現在要先來設計一套完整的資料夾分類嗎？」

千萬不要。如果你一開始就想設計一個完美的結構，你會卡在「這篇到底該分在哪一類」上面三個月，最後一個字都沒寫。

好的知識庫成長曲線是**滾出來的，不是規劃出來的**。第一週你只需要做兩件事：

1. **建一個每日筆記資料夾，每天寫一篇當天的筆記**：把今天完成的事、做出的決定、踩到的坑記下來。
2. **遇到任何專有名詞，就用 `[[名字]]` 包起來**：不管是人名、專案名還是工具名，先括起來再說。

你甚至不需要立刻去建立那個名字對應的檔案。在 Obsidian 裡，被括起來的名字會自動標記成「尚未建立的連結」。等你寫了一陣子，某天發現某個主題常出現、需要獨立整理時，再點一下那個連結，它就會自動幫你建好檔案了。

先照這樣寫兩個月。兩個月後，你會自然看出哪些東西一直在重複、哪些主題該獨立出來、哪些可以合併。**寫完才整理，永遠比先設計再寫走得遠。**

## 我自己用了一年半的真實演進與「爛帳大掃除」

說說我自己走過的路當作印證。我用 Obsidian 大概一年半，最開始真的就只有「每日筆記」跟「專案」兩個資料夾，完全沒有事先規劃，就是每天寫，遇到新類型才開新資料夾。

- **用到第 3 個月**：發現很多長期想法重複寫在不同天的日記裡，才開了「人生主軸」資料夾（把事業、健康、關係、財務各自獨立成一個檔案）抽出來管。
- **用到第 6 個月**：開始讓 Claude Code 在每次啟動對話時，自動讀取我指定的記憶入口檔，我的知識庫正式進入「AI 可讀」階段。後來也陸續長出了放重要決策脈絡（不只記結論，還記下「為什麼這樣選」）、書籤與書摘、私密筆記（跟療癒、伴侶、家人有關）以及舊任務歸檔的資料夾。
- **用到第 9 個月**：單篇筆記連出去的雙向連結數量爆炸（一篇超過 50 個連結），於是開了「每週覆盤」資料夾當作匯總層。
- **用到第 12 個月**：開始每週做一次主檔同步檢查，比對專案檔最上方的狀態摘要跟底下的內容標題有沒有矛盾，結果一抓就抓出兩三個已經悶了 3 週的矛盾。

但就算這樣滾出了一套順手的系統，知識庫還是會退化。知識庫壞掉通常不是因為某一天突然出錯，而是慢慢爛掉的。今年四月底，我花了四天做了一次徹底的知識庫健檢，把埋了好幾個月的爛帳翻出來清，也歸納出幾個任何管待辦、存書籤的人都會遇到的通病：

### 為什麼待辦清單總是會失控？五個根本原因

那次健檢我終於想通「為什麼待辦清單用久了就讓人不想看」，背後其實就五個原因：

1. **同一件事記在兩個地方（雙主檔職責模糊）**：兩邊都在追蹤同一件事，卻沒講清楚以哪邊為準，結果兩邊都過期。
2. **分工邊界漂移（角色漂移）**：原本某個清單或規則只管 A 事，慢慢開始順手管起 B 事，但沒有更新說明，導致其他地方也以為自己要管 B。
3. **做完的事沒歸檔（無歸檔）**：已經完成的任務沒有正式收掉移走，繼續混在清單裡，清單越長就越難信任。
4. **責任邊界未定**：這件事到底歸哪個專案管？邊界不清，就最容易被晾在那裡沒人動。
5. **待辦標記格式不統一**：有些地方打勾選框、有些地方寫文字狀態、有些地方貼圖示，要搜尋未完成事項時根本抓不齊。

這五個問題裡，「記在兩個地方」和「做完沒歸檔」是最常發生的。只要規定每一件待辦只能活在唯一一個主檔裡、做完立刻移去歸檔區，清單的信任感就會回來一大半。

### 為什麼存了書籤卻永遠找不到？

書籤系統崩潰的方式也很固定：一開始隨手存，越存越多，最後變成「我確定我存過，但就是搜不到」。

我在健檢時把所有書籤重新整理，不再只靠自由標籤，而是固定用四個問題幫每個書籤貼標籤：
1. **它是什麼類型**（工具、文章、影片、參考資料、討論串）
2. **它屬於哪個主題**（例如教學、財務、AI 工具）
3. **它用在哪個專案上**
4. **它現在的狀態是什麼**（使用中、已過時、已歸檔）

定出這四個維度後，搜尋準確率明顯提升；更重要的是，我開始會定期把標記為「已過時」的書籤清掉，不讓它們無限堆積。

### 92 個斷掉的連結，不用一天全修完

雙向連結很好用，但只要檔案改過名字、搬過家，或是當初打錯字，連結就會靜靜地斷在那裡，不會跳出任何警告。那次我讓 AI 掃描整個筆記庫，一口氣抓出 92 個斷掉的連結。

如果把 92 個都當成緊急事項，你大概看一眼就不想動了。我的做法是分三層處理：
- **高優先**（核心專案主檔、每日筆記的主連結斷了）：當天立刻補齊。
- **中優先**（日記裡的交叉引用、讀書筆記的來源連結）：請 AI 整批一次修好。
- **低優先**（已經歸檔的舊筆記漏連）：先標記起來留著觀察，不急著動。

分出輕重緩急，清理才不會變成心理負擔。

### 當筆記越來越多：試試「消融實驗」

如果你已經記了一段時間，把工作與生涯方方面面都放進了知識庫，筆記與規則越疊越多時，我很推薦試試一個我最近最喜歡的提問法：**消融實驗**（借用科學實驗的概念：故意拿掉系統裡的某一個零件，看整體運作會不會受影響；如果完全沒影響，就代表那個零件是多余的）。

你可以直接請 AI 幫你審視現有的筆記模組或規則：「如果拿掉這一個部分，對我們日常的工作成果會不會有影響？」如果拿掉也沒差，就放心把它刪掉或歸檔吧。

## 動手設定區：目錄結構、Claude Code 自動化與每季健檢清單

如果你已經準備好要自己動手把 Obsidian 跟 Claude Code 接起來，這一節整理了我實際在用的資料夾結構、日常指令、Token（AI 計算文字量與額度的基本單位）減肥法，以及每季一次的維護清單。

### 1. 筆記庫（Vault）完整資料夾結構

以下是我演化一年半後的資料夾配置，你可以先從前兩個開始，需要時再照著擴充：

- `daily/YYYY-MM-DD.md`：每日筆記（完成事項、決定、踩坑、教訓）
- `weekly/YYYY-MM-DD.md`：每週覆盤（當單檔連出去的 `[[wikilink]]` 超過 50 個時，用來當匯總層）
- `projects/`：每個進行中的專案一個 `.md` 檔，記載當前狀態、待辦、決策歷史
- `pillars/`：人生的幾個長期主軸（事業、健康、關係、財務），每個一個檔案
- `bookmarks/`：讀到的好東西、工具、書摘。在檔案中固定加上四個控制詞彙欄位：
  - `kind`：`tool` / `article` / `video` / `reference` / `thread`
  - `topic`：所屬主題（如 `claude-code` / `youtube` / `teaching` / `finance`）
  - `applies`：適用專案
  - `status`：`active` / `stale` / `archived`
- `decisions/`：重要決策的脈絡記錄（不只記結論，記下「為什麼這樣選」）
- `personal/`：私密區
- `archive/`：已完成的舊任務歸檔

### 2. Claude Code 接入與日常操作指令

- **跨對話持久化記憶**：在筆記庫建立一個入口檔案（例如 `MEMORY.md`），設定讓 Claude Code 在每次對話（session）啟動時自動讀取。這樣模型一開場就掌握你的背景，且檔案所有權完全留在你本機。
- **自動記日誌（`/obsidian log`）**：設定好 `/obsidian` 的 log 自訂技能（Skill，把固定工作流程包成一個可隨時呼叫的快捷指令）後，工作完一個段落輸入 `/obsidian log`，Claude Code 就會把當前對話視窗裡完成的工作加上時間標籤，自動寫進當天的 `daily/YYYY-MM-DD.md`。
- **統一待辦格式**：為避免搜尋抓不齊，待辦事項建議統一語法 Schema（不要混用 `- [ ]`、`status: pending` 與各種圖示）。

### 3. 給 AI 規則減肥：用按需載入（Lazy-load）省下 42% 起始額度

很多人用 Claude Code 會把大量的個人規則和偏好寫在 `rules` 資料夾裡，讓 AI 每次啟動都全部讀進來。但規則一條條加、沒人管總量，就會吃掉大量起始 Context（AI 在單次對話中能記住與處理的文字容量上限）。

我在四月底健檢時發現，每次開新對話什麼事都還沒做，起始規則就先吃掉 **13,020 tokens**。

- **解法**：把「不是每次對話都會用到」的規則，從常駐規則移出來，改包成 **Skill 按需載入（lazy-load）**——只有當你呼叫特定指令時才載入該規則，平時不佔用空間。
- **成效**：重構後每次對話起始負擔降到 **7,590 tokens**，減少了 **42%**。同樣的 Claude Max 訂閱方案、同樣的時間內，能讓 AI 做的事情明顯變多。

### 4. 每週與每季的自動化維護儀式

**每週額度重置日的固定儀式**（當每週額度即將在一天內重置、你暫時變身「單日 Token 富翁」時，可以開計畫模式讓 AI 跑兩件事）：
1. 開給 Claude Code 權限，掃描所有專案資料夾，請它列出過時與暫存檔案的歸檔清理建議。
2. 用命令列工具讀取本週所有對話紀錄，找出你跟 AI 溝通不順、反覆糾正的地方，請它對照官方最佳實踐，自動修正你的設定檔（`CLAUDE.md`、規則檔與記憶檔）。這會讓你接下來一週工作順暢非常多。

如果你常遇到「進度都改了七八輪，說明文檔卻還停在第一版；記憶檔裡還寫著舊工具，其實你早就換新工具了」的狀況，可以參考 GitHub 上的社群技能 `neat-freak`。每次任務結束後執行 `/neat`，它會自動比對並對齊你的設定檔（`CLAUDE.md` / `AGENTS.md`）、文檔資料夾（`docs/`）與 AI 記憶系統，輸出一份變更摘要。自動化不是為了替代思考，而是讓整理這件事可以更頻繁、無痛地發生。

**每季一次的知識庫健檢 SOP（約 2～3 小時）**：
- [ ] 輸入 `/cost` 或 `/context` 檢查每次對話的起始 token 數是否超過 8,000；若超過，就把非常駐規則改為按需載入（Skill lazy-load）
- [ ] 跑一次全筆記庫的 `[[wikilink]]` 斷連掃描，依高、中、低三層優先序處理
- [ ] 待辦來源審計：確認每一個待辦事項都只存在唯一一個主檔裡（Single Source of Truth），並把已完成項目移入歸檔
- [ ] 書籤清理：清掉標記為 `status: stale` 的過時書籤，並幫未分類的書籤補上四軸標籤
- [ ] Skill 清單檢查：刪除功能重複或已經沒在用的自訂指令

這五件事每季花兩三個小時做一次。不做的話，問題不是不存在，只是埋在看不見的地方慢慢消耗你對系統的信任感而已。你不需要第一天就做到這一步——今天先打開電腦，寫下你的第一篇每日筆記就夠了。

Pro 20 美元，適合偶爾問問題、還沒讓 Claude Code 自己跑多步驟工作的人。Max 5x 100 美元，適合每天開著 Claude Code 當工作環境的人，我自己用這個。Max 20x 200 美元，我的建議是先別買。API 按量付費，留給「偶爾一次、吃很多 token、又不挑最貴模型」的重活。

價格跟額度我是 2026-10-18 當天去官方頁面查的，之後會變，以[官方定價頁](https://claude.com/pricing)和 [Max 方案說明](https://support.claude.com/en/articles/11049741-what-is-the-max-plan)為準。

## 官方現在怎麼寫（截至 2026-10-18）

- Pro：每月 20 美元，年繳是每月 17 美元（一次付 200 美元）。包含 Claude Code 和 Opus。
- Max 5x：每月 100 美元，每個 session 的用量是 Pro 的 5 倍。
- Max 20x：每月 200 美元，每個 session 的用量是 Pro 的 20 倍。
- Max 兩檔都附每月 API 額度，5x 是 100 美元，20x 是 200 美元。
- 額度分五小時的滾動視窗跟週額度。網頁、桌面、手機、Claude Code 共用同一個池。Fable 在 Max 最多只能用到週額度的 50%，Pro 要用 Fable 得另外買 usage credits。
- [Claude Code 的說明頁](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan)沒有給訊息數、小時數或 token 數，週額度的實際數字也沒公布。

最後這點很重要，下面幾段講到的「實際夠不夠用」，都是我自己或別人實測的，官方沒有數字可以對。

## Pro：偶爾問問題夠用，開始跑 agent 就見底

如果你只是偶爾問問題，Pro 完全夠。但你一開始讓 Claude 自主完成多步驟工作，Pro 的週額度很快就見底。Pro 用起來你會一直在算還剩多少。

我自己在摸清楚這件事之前，兩天 extra usage 就燒了 20 美元，補購又燒了 20，最後直接升級了。

另外如果你是用 Cowork 然後覺得 Pro 根本不夠燒，切到 CLI 同樣的任務會省很多。Cowork 的 token 消耗比 CLI 快。

## Max 5x：我自己的選擇

如果要訂 Claude，我的建議很簡單，直接訂 100 美元的方案。我選它看的是 Fable，他們家最大的優勢在這，架構策略、意圖對齊跟洞見，到目前為止我還沒看到 GPT 家有哪一個模型比得上。

100 美元平攤到每個工作天，對我來說是合理的工具成本。Max 下幾乎不需要想還剩多少這件事，這是跟 Pro 最大的差別。

給個實際的量。我有一天早上把一個 5 小時窗口用完，6 個手動開的主 session、32 隻 subagent，主線 Opus 5.5 做決策跟驗收，大量執行丟給 Sonnet，Fable 只在要第二意見的時候出場。那個窗口大概佔週額度的 12%，API 等值 156.69 美元。我拿 ccusage 看近 30 天的總量，API 等值大約 6,000 美元，對上 100 美元的月費，補貼倍數真的很誇張。

Max 每個月還送等值的 API credit，這個要善用。我是接到每天半夜跑的晨報、電子報素材收集跟每週的 harness 維護。想三人分一個 Max 來省錢的話，我只能說，三人共享就是三人一起下封號地獄。

## Max 20x：先別買

「5x 到 20x 增加 4 倍」有人實測過，那 4 倍只是五小時額度，週額度只有增加 2 倍。我自己是先開 20x，結果用量跟不上，因為 AI 跑的時候我也在同時想怎麼驗收、怎麼下一個指令，並不是真的能 20x。後來我就退回 5x 了。

所以如果你想升 20x 是為了跑長時間的批次，要先確認你真正缺的是五小時容量還是週容量。如果你每天短時間、分散使用，5x 升 20x 對週額度的改善其實有限。

我自己判斷要不要升，會先問：每次到重置前你是不是都在衝量？衝的是真的有事要做，還是不用完睡不著？後者是被設計出來的需要，訂閱制的焦慮機制在倒逼你。完整的判斷框架在[用量經濟學](/blog/posts/zh/ai-usage-economics)那篇。

## 什麼時候該用 API

我自己的用法是兩種。一種是大量文字但是偶爾才跑一次的工作，比如會議記錄整理，我走 OpenRouter 按量付費，儲值 10 美元可以用好久。另一種是自動化排程，用 `-p` 模式接 API key，吃的是 Max 附的那份 API credit。

有一個陷阱要記得：官方說明頁寫了，只要系統裡有 `ANTHROPIC_API_KEY` 這個環境變數，Claude Code 就會用 API key 而不是你的訂閱，你會被收 API 費用。額度打滿的時候，官方也給了選項，可以等、升級，或開 usage credits，usage credits 是按標準 API 價格計費。

## 買之前還要知道的

額度被吃掉，不一定是你用太兇。快取 bug、resume 重算整包上下文、Opus 4.7 的實測消耗，還有我自己一個 session 半小時燒掉 90% 的 subagent 遞迴，我都記在[額度事件那篇](/blog/posts/zh/claude-code-quota-incident-log)。如果你買了 Max 還是覺得額度不對勁，先去對一下那四起。

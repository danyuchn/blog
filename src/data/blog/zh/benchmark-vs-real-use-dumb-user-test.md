為什麼模型刷出來的 benchmark，跟使用者的實際體驗差別有時會巨大到讓人懷疑人生？

但只要一把它拉進每天真實的開發場景，那種落差卻常常讓人徹底傻眼。我覺得有幾個原因：

## 跑分無塵室與混亂現實的三大落差

模型跑分與實際手感之所以脫節，核心在於三個根本矛盾：

1. 人類下的提示詞不會那麼工整標準：在現實工作裡，人下的提示詞往往東講一句、西講一句，該講的重要脈絡漏了一大堆，根本無法在一開始就完整闡述自己的意圖。
2. 真實開發不一定是追求一步到位：跑分很大一部分看的是「one shot完成率」。但我們真實世界的開發流程，不一定是追求一步到位，而是追求邊走邊調、「指哪打哪」的這個感覺。純跑分完全測不出這種即時跟隨的動態體驗。
3. 測試環境整齊如無塵室，真實環境滿是污染衝突：跑分時的上下文乾淨無瑕，控制架構整齊得像是無塵室。然而真實使用者的 harness 往往亂成一團，上下文可能還會污染、衝突。模型抵抗上下文混亂的能力就很重要。

正是這三點，在真實場景中直接分出了模型的高下。

## 為什麼我們需要「蠢人跑分」

以後真正應該被設計出來的，是「蠢人跑分」（蠢人 benchmark）。

這種測試的邏輯非常直接：找一群最不會下提示詞的初學者，讓他們把最混亂、最缺脈絡的工作直接砸給模型。在這種東缺西漏、毫無秩序的極限考驗下，如果還能讓使用者忍不住驚呼「天哪！你竟然知道這就是我要的」，那才是真正稱得上神之模型的存在。

就目前而言，Opus 5.5 只要不遇到降智情況，確實已經展現出達到這個標準的實力。

## 從平庸到防禦：GPT 6 在混亂現實中的崩塌

拿 GPT 6 來說，一旦脫離了無塵室跑分，放進混亂現實裡，換來的往往是極度沉悶與挫折的體驗。

真的很好奇到底是在訓練階段把 base model 訓爛了，還是 codex harness 太糟。面對複雜任務，它怎麼可以被塑造成一個沒有品味、極度平庸、毫無主見、畏畏縮縮、鑽牛角尖、死認字面意思、吞噬用戶判斷，而且講話帶滿卸責語氣的懦夫模型？更讓人難以接受的是，它的反應速度甚至比地端運行的本機模型還要慢。

整體而言，GPT 6 給人一種揮之不去的窒息感：

- 把人搞瘋的防禦性寫作
- 過於注重局部正確性，忽略全局
- 完全不敢顯示自己的主見下判斷
- 甚至會吞噬使用者的判斷跟業務邏輯

## 思考預算落差與你的退訂判準

造成這種體驗落差的另一個殘酷事實是：現在訂閱制裡提供的 Astra，跟剛發布時的表現根本是兩個完全不同的東西。

X 上有人實測過 juice 值（思考預算）：透過 API 調用的 Astra 700 多，訂閱制的 20 多。

拿我自己的經驗來說，這 28 天不知道還能撐多久，感覺是沒招了。每次遇到問題，我都只好叫 Opus 來收爛攤。所以我的建議是：退訂改 Claude⋯

至於那些透過 API 外接 Astra 或 Sol 到第三方 coding agent 的朋友們，外接版本的實際表現到底如何？有沒有朋友可以出來分享？但在日常高壓混亂的實戰開發中，能真正看懂你的混亂、幫你收拾殘局的工具，才值得你留下來當主力。

## 附錄：名詞與技術細節

- Harness（控制架構 / 測試環境）：指包裹並驅動模型進行推理解答的外圍環境與上下文管理系統。跑分時的 harness 高度規範且純淨，而真實使用者的工作環境則充滿各種動態變數與衝突脈絡。
- Juice 值（思考預算）：模型在輸出答案前被分配用於內部推理思考的運算資源額度。X 上的實測指出，API 調用的 Astra 思考預算達 700 多，訂閱制的則為 20 多。
- Astra / Sol / Luna：均為 GPT 6 系列之相關版本與內部代號。

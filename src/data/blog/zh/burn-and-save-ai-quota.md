很多人買了 AI 訂閱，最常碰到的矛盾只有兩種：不是白天趕工時額度被敲光，就是每週看著重置倒數、一堆送的額度悄悄過期。

我住在曼谷，從 GMAT 老師轉做 AI 工作流後，每個月固定付大約 125 美元買三個訂閱：Claude Max 5x、Codex Plus（ChatGPT Plus）跟 Google AI Pro。但真正讓我停下來算帳的，不是每個月扣多少款，而是我發現自己手上有七個不同規則的額度池，裡面塞滿了免費的、會定期重置的、或是快要到期的算力。如果放著不管，它們每週都在作廢；但如果為了不浪費而胡亂派工，AI 只會生出一堆需要我人工審查的廢話，等於花錢幫自己製造無薪加班。

為了解決這個焦慮，我這兩週做了兩件方向相反、但本質上是一體的事情：

第一件是「燒額度」：把快作廢的算力，全部砸在能讓機器自己驗證對錯的工作上，趁我睡覺時跑完。

第二件是「省額度」：用這些多出來的免費算力，回頭重構工作環境、瘦身規則、排定自動化，讓未來的每次對話都少讀 token。

到了 11 月，這套系統進一步演進，從原本預先跑基準測試的靜態分工，進化成由終端儀表板與路由腳本驅動、按剩餘額度動態派工的飛輪。這篇文章把這套完整的盤點清單、決策過濾題、夜間批次打法、結構性省額度技巧，以及最後的動態派工邏輯整理成一次寫完的架構，文末也附上可以直接照抄的提示詞。

## 盤點手上的七個額度池

我每個月的固定訂閱支出大約是 125 美元：

- Claude Max 5x，100 美元
- Codex Plus（ChatGPT Plus），20 美元
- Google AI Pro，優惠價 4.99 美元

但真正讓我開始盤點的，是這些訂閱附送的東西。Max 5x 每月附一筆 100 美元的 API promo，claude.ai 另外給了 250 美元的雲端 session credit，Google AI Pro 每月附 200 個 Colab 運算單位（CU）。這些每一筆的規則都不一樣，有的跟著帳單週期作廢，有的一次性，有的 90 天過期。

盤點的方式很簡單，我叫 Claude Code 開瀏覽器去每個設定頁看，把餘額、重置時間、到期日、能用在哪裡整理成一張表。10/10 做了第一次，10/20 七個池全部重新查一次：

| 額度池 | 怎麼重置／何時到期 | 能用在哪 |
|---|---|---|
| Claude Max 5x 訂閱 | 每 5 小時一個窗口，另有週額度，週日重置 | 主對話、subagent、夜間批次 |
| Claude 雲端 credit 250 美元 | 一次性，11/05 到期 | 只能給雲端 session，碰不到本機的檔案跟憑證 |
| Console API promo 100 美元 | 每個帳單週期一筆，期末作廢、不累積 | API、Agent SDK、`claude -p` 帶 API key 的排程 |
| Codex Plus | 5 小時加每週，常常不定期提前重置 | 程式工作、對抗式審查 |
| agy（Google AI Pro） | 三組模型各有每週與 5 小時上限 | 長文件摘要、轉錄、第二意見 |
| Colab CU | 每月 200，每批 90 天過期 | 本機跑不動的訓練跟重型批次 |
| 本機模型（Mac mini） | 不計費，只受時段限制 | 夜間空檔批次、不能上雲的敏感資料 |

![七個 AI 額度池依重置週期排列：從每 5 小時重置的訂閱窗口，到一次性的雲端 credit，標出哪些快到期](/blog/assets/posts/burn-and-save-ai-quota/1-quota-pools.jpg)

最後我讓 Claude 寫了一個小指令，打一行就能看到大部分額度還剩多少。雲端跟 Console 這兩筆查不到，還是要自己上網頁看。

## 三道過濾題：決定額度要拿來做什麼

10/16 週額度重置前，我還剩一半以上沒用。我請 Claude 去 Reddit 跟網路上找大家怎麼「有意義地」花額度，再對照我自己的狀況給建議。

r/ClaudeCode 有一串在講「Max 額度每週都浪費」，裡面有人講得很中肯：產出如果需要你人工審，等於幫自己製造工作。

所以我最後定了三條判準，照順序問：

1. **會不會作廢？** 會作廢的先用。雲端 credit、這期的 Console promo、快重置的週額度排前面。
2. **產出能不能自己驗對錯？** 測試會不會過、答案鍵對不對、影片能不能算繪出來，這種讓機器判就好。要我一條一條讀的產出，排後面。
3. **做完會不會留下東西？** 工具、規則、可以重跑的腳本，下次還能用。一次性的報告排最後。

![決定一筆額度要拿來做什麼的三道問題：會不會作廢、產出能不能自己驗對錯、做完會不會留下長期資產，三題都過的優先做](/blog/assets/posts/burn-and-save-ai-quota/2-decision-flow.jpg)

判準定好之後，再決定每個池負責什麼。10/20 我跟 Claude 一起排的分工是這樣：

| 額度池 | 負責什麼 | 規則 |
|---|---|---|
| Claude 訂閱 | 主對話、需要判斷的工作、終審 | 所有路線最後都由 Claude 接住 |
| 雲端 credit | 大批、不需要本機憑證的工作 | 一律推到分支開 draft PR，不准合併；一次用完就不再用 |
| Console promo | 每天固定跑的排程 | 額度用完自動退回訂閱 |
| Codex | 產出能被測試或檢查器判對錯的程式工作、對抗式審查 | 額度到線或失敗就退回 Claude |
| agy | 長文件摘要、轉錄、第二意見 | 每組每週留 10% 給我手動用，用到 90% 就不派 |
| Colab | 訓練、本機跑不動的重型批次 | 照優先順序花，快作廢的先吃 |
| 本機模型 | 凌晨空檔、可斷點續跑、敏感資料 | 只在 02:15–05:45 跑，有記憶體跟 swap 守門 |

## 趁睡覺把額度燒掉：只做機器能自己判對錯的事

在具體燒額度的時候，首要原則就是趁我睡覺，讓它把一整批事情做完。

10/19 晚上睡覺前，我跟 Claude 說：你可以自己開好幾個視窗分頭做，不用停下來問我，越少吵我越好。它從晚上 11 點做到隔天早上 6 點多，週額度用到一半就自己停下來。

做的事大多跟我自己的 GMAT 練習平台有關。最有代表性的一件：平台上一萬八千多題，它全部檢查一遍，確認沒有任何一題「學生答對了卻被判錯」。

接著它再找另一個模型，把近千題推理題重新做一次，兩邊答案對不上的才留給我看，最後只剩 8 題要我判斷。

早上我起床，它已經把需要我拍板的事整理成十項，我一次回完，該上線的就上線。

其他會作廢的邊際額度，我也照同樣的原則分配給各自最適合的任務：

一次性的雲端額度：幫我抓教材裡的錯。這筆 250 美元只能在雲端用，用完就沒了。我拿它檢查我的 Claude Code 課程教材，讓它逐段對照官方文件，找出寫錯或過時的地方，抓到 11 處，我看過再改。雲端那邊碰不到我電腦裡的東西，我比較放心交給它。

每月送的 API 額度：拿來跑每天的例行報告。我每天早上有一份 AI 整理的晨報，另外每天會收集電子報素材，以前都吃訂閱額度。我改成用 Max 每月送的那 100 美元 API 額度跑，一個月大概只花 36 美元，品質我抽看過沒變差。這樣訂閱額度就省下來給我白天用。

Google 送的 Colab 運算：訓練自己的小模型。我拿來訓練幾個小模型，看能不能在自己電腦上取代付費服務。語音轉文字那個成功了，之後就用它；想模仿我寫作語氣的那個，盲測輸給我現在的做法，就直接刪了。另外順手試了一個開源的 AI 影片模型，做出一支 44 秒有台詞的短片。

拿自己的工作考新模型。[Haiku 5.5](/blog/posts/zh/haiku-55-own-task-benchmark) 出來的時候，我拿自己平常真的在做的工作出了 13 題考它，大概花掉 15 美元的額度。結果「檢查東西有沒有錯」這類工作，便宜的 Haiku 跟貴的模型做得一樣好，成本大約只要十分之一。之後這類工作我就都交給它。

## 用多出來的額度，打造以後永久省額度的系統

把快作廢的額度燒掉只是手段，真正的回報是拿這些多出來的算力，去打造以後可以省額度的資產。

便宜的事交給便宜的模型。檢查類交給 Haiku，寫程式跟幫忙挑錯交給 Codex，長文件交給 Google 的模型，能在自己電腦跑的就趁半夜跑。不管走哪一條，做不了的最後都會回到 Claude 手上。

讓 AI 每次少讀一點東西。AI 每次對話前都會先讀一堆我寫給它的規則跟背景資料，讀越多越貴。我做了兩件事：一是讓長對話早一點自動壓縮，前後比較，每次對話要讀的量少了大約三成；二是把只有特定工作才用得到的規則拆出去，要用的時候再讀。我公開的免費設定包，每次都要讀的內容少了八成多。

具體算一下前後 11 天的帳：我把 Opus 5.5 的自動壓縮設在 400k，前後各 11 天比較下來是這樣：

補一下為什麼會省：每次呼叫都要把整段上下文重送一次，1M 上線後少了自動壓縮的天花板，對話一長到 50 萬，一個短回覆就吃掉 50 萬 token。之前整理額度事故時有寫完整紀錄：[額度事故紀錄](/blog/posts/zh/claude-code-quota-incident-log)。

我覺得 400k 最剛好～

規則加太多反而變慢。10/21 我覺得 Opus 變笨了，請 Claude 翻當天的對話紀錄找原因。結果模型本身沒有退步，是我自己加的「能外包就外包」跟其他規則打架。我把那條拿掉，改成「我在等的事，用最快的方法先做完」。

讓資料不要越來越亂。我同時用 Claude Code 跟 Codex，兩邊的設定很容易越改越不一樣；筆記知識庫也常常同一件事寫在兩個地方，後來一邊改了、另一邊沒改。現在有排程每週自動比對、自動修，修壞了會自動還原。

把天天要做的事排成自動排程。現在我電腦上有 17 個排程每天自己跑，例如：

- 早上自動擬好 Reddit 回覆的草稿，我只要說要發哪幾則
- 學生的新成績單一到，自動先做好診斷簡報
- 我的平台一出錯，AI 自動先寫好修正，等我看
- 額度用完的長工作，等額度恢復會自己接著跑，跑完通知我手機
- 週日重置前如果額度還剩很多，自動挑不用等我的事去做

這些都只做到「準備好」，要發出去、寄出去的，還是等我按。

找出我一直在重複講的話。我請 Claude 翻我兩週來跟它講的一千多則訊息，找出我一直重複要求的事，挑出 8 件可以做成自動化的，已經陸續在做。

不相信 AI 說「我檢查過了」。有一次排程裡的 AI 說它已經檢查過連結，其實根本沒跑。現在這類檢查改由程式自己驗；AI 說檢查過、卻沒留下檢查紀錄的，會直接被擋下來。

這一連串調整累積下來，實際帶來的結構性改變如下：

| 效果 | 白話講 | 現在的狀態 |
|---|---|---|
| 同樣的工作更便宜 | 檢查類工作改用便宜模型，成本大約剩十分之一 | 已經實測 |
| AI 每次讀的東西變少 | 每次對話少讀約三成，換算一個月省下六百多美元的等值費用 | 前後比較過 |
| 訂閱額度留給白天 | 每天的例行報告改用每月送的 API 額度，一個月約 36 美元 | 跑了幾天都正常 |
| 我要記得做的事變少 | Reddit 回覆、電子報、成績單分析改成自動先準備好 | 已經在跑 |
| 提醒清單變短 | 「有空可以先做」的清單，從 61 條篩到真的能做的 1 條 | 已經在跑 |
| 兩套工具不再各說各話 | Claude Code 跟 Codex 設定不一致的地方清到 0 | 已經清完 |

有些效果要過一陣子才看得出來。我排了 10/29、11/06、11/18 三次回頭看，主要看兩件事：AI 是不是真的比較省，我在等的事有沒有比較快做完。沒變好就再改。

## 從預跑基準測試，進化到按剩餘額度動態派工

到了 2026 年 11 月，這套額度分工跟派工方式又改了一輪。

我在自己用來開多個 AI 分頁的終端機工具裡手搓了一個很簡單的額度儀表板，沒有要開源，因為實在是太簡單了，甚至你把下面這張圖給 AI，他都能 5 分鐘內做出來。

[![終端機裡的 AI 額度儀表板：Claude、Codex、Gemini 的 5 小時與 7 天額度、Argon 7 天額度、Grok 週期，各自顯示已用百分比、距離重置的時間與重置日期](/blog/assets/posts/burn-and-save-ai-quota/quota-dashboard.jpg)](/blog/assets/posts/burn-and-save-ai-quota/quota-dashboard.jpg)

這個只是前端顯示，後面真正重要的是接上了路由腳本。負責指揮的主要 AI 派工時都會先查即時額度，再加上事先用 benchmark 測過的各模型分工強弱項，來決定當下任務最適合派給誰、思考強度要開多少。

所以實在是想不通為什麼有人要踩終端機捧 Desktop App。終端機自定程度最高，手又可以不用離開鍵盤，資源又節省，任何新功能永遠是 CLI 先出，Desktop App 隨後才跟上。我可以認同 Desktop App 美觀易用，但也不需要踩一捧一吧～

不過這套靠 benchmark 決定分工的做法，跑沒幾天我就決定改掉了。

原本我決定各家模型分工的模式，是拿自己的任務設計成 benchmark，每次有模型更新時就各種檔位測過一遍，根據消耗額度、時間跟交付品質決定怎麼設定派工規則。但是這樣做後來發現有幾個問題：

1. 現在模型迭代的速度越來越快，每次都要重測，不符成本效益。
2. 各家模型的額度在重置前沒有被充分利用。

所以後來有一個新的靈感：

1. 直接捨棄 benchmark，也不預設細緻的派工角色，改成純按額度來決定。快要重置且額度剩餘的先派。只是派完都要由負責指揮的主要 AI 驗收。這樣可以充分運用到各家額度。
2. 由於重置會是輪流的，所以只要用得夠勤，每種模型都有充分的機率會被外派，能夠平均累積數據。
3. 過一個禮拜，直接回來讀那一週的對話紀錄，量測每種模型被委派後的成功率、消耗額度跟耗費時間，這時就能最清楚地看到誰適合什麼任務，再來寫派工規則。沒被量測到的就是隔週的重點量測對象。

這種靈感是 Anthropic 最頂級的 Fable 模型才會想出來的吧！（自誇）果然人類的創造性思維還是最重要的。

## 想照做可以直接抄的提示詞

上面每一步，我其實都是用一般的對話叫 Claude Code 做的，沒有寫什麼特別的程式。下面是我覺得最關鍵的幾句，可以直接改成你自己的狀況貼進去。

**第一步：盤點。**

> 幫我開瀏覽器，到我每個 AI 訂閱的用量頁，把每一筆額度的剩餘量、重置時間、到期日、能用在哪些工具上，整理成一張表。查不到的寫「查不到」，不要猜。最後標出 30 天內會作廢的有哪些。

**第二步：決定拿來做什麼。**

> 照這三個問題，把我的待辦跟長期計畫分類：一、用的額度會不會作廢；二、產出能不能用測試或檢查器自己判對錯，不需要我一條一條讀；三、做完會不會留下以後能重用的工具或規則。三題都過的排第一，列出來給我選。

**第三步：放手讓它跑。**

> 這批你自己做，我要去睡覺，不用停下來問我。規則：週額度用到 50% 就停；每件做完先自己驗證，沒跑驗證就寫「沒跑」；會對外發送、刪資料、動到金流的不要做，列出來等我；所有改動放在分支，不要合併。

**第四步：早上收件。**

> 把昨晚做完的事列成清單，每條附上你怎麼驗證的、驗證結果，以及需要我決定的事。需要我決定的編號排好，讓我一次回覆。

**第五步：開始省。**

> 翻我過去兩週的對話紀錄，找出我重複要求超過三次的事，排出最值得做成自動化的前五名，附上每一項大概能省多少次介入。

> 檢查我的常駐設定（CLAUDE.md、rules），找出只在某一類任務才用得到的段落，搬到按需載入的 skill，常駐只留一行指針。

> 我想把查核類的工作改派便宜的模型。先拿我真實的工作出 10 題，讓便宜跟貴的模型各跑一遍，分數一樣才換，不一樣就維持原本的。

> 每一個自動化排程都要有失敗時通知我的方法；用外部模型的，額度用完要自動退回 Claude。

## 實行時的提醒與邊界

在執行這套流程時，有幾個具體的額度處理原則與操作邊界需要注意：

首先是還沒花完的額度處理：

- **一次性 credit**：一次性用完就不再用，也不會為它建排程；本機額度吃緊的時候，就拿它跑大批、不需要本機憑證的工作。
- **每月送的 API promo**：挑可以走 Batch API 的批次工作吃掉。
- **會滾動到期的運算單位**：照排好的順序，拿來跑模型訓練、重轉錄舊資料或合成查詢這類重型批次。
- **常不定期重置的訂閱**：能花就花，不用太在意剩多少，但產出一定要能被測試判對錯，或經過 Claude 審。
- **本機半夜空檔**：拿來做逐字稿粗加工、文件分類、去識別化這種可以斷點續跑、之後還會有人再看一遍的批次。

其次是不要落入訂閱焦慮的陷阱。我不會為了用完而用完。重置前硬衝量，多半是訂閱制設計出來的焦慮，這點我在[訂閱怎麼選](/blog/posts/zh/claude-code-plan-picker)那篇寫過。真的沒有合格的工作，就讓它作廢。

最後是自動化的安全底線。所有在夜間或背景放手讓 AI 跑的任務，一律要求在獨立分支開 draft PR，不准自動合併；所有對外發送的訊息、信件、社群貼文，或是刪除資料、修改金流設定的動作，一律維持人手拍板，AI 只能停在「準備好等我按」的狀態。

就這樣。

坊間有一句玩笑話：「只要你學得慢，就什麼都不用學。」

這句話拿來自嘲很幽默，但在 AI 上好像也有用（？過去我們為 AI 寫了大量的 Skill、前處理手冊與繁複的提示詞規則，背後的原因往往只有一個：當時的模型能力不夠強、創意不夠豐富，處理細節時頻頻出錯。為了解決問題，我們只能像保母一樣，透過大量試錯將踩坑經驗一條一條轉化為硬性限制，用密密麻麻的規範把模型框在安全範圍內。

然而，在 Opus 5.5 出現後，過去為了規範模型寫的那些 Skill 細節與經驗傳承，我想都要重新審視、精簡甚至大修了。新模型上線時，我們該如何重新檢查自己為舊模型打造的工作流？哪些步驟可以直接淘汰，哪些規則需要保留並重構？本文透過影音剪輯與跨語種翻譯兩項實測，整理出一套能直接落地的盤點方法。

## 第一步：解除約束進行裸測，淘汰不再需要的防呆前處理

盤點既有流程的第一步，是敢於「把束縛拿掉做一次裸測」。

看到網路上不少人用 Opus 5.5 一次生成（one-shot）製作影片，我靈機一動，決定直接請 Opus 5.5 發揮自己的創意。在傳統流程中，製作一支解說短片需要極度瑣碎的手工前處理：錄完口白後，往往得先進剪映等剪輯軟體手動切除贅字、口誤與停頓，再按照腳本逐段規劃畫面，並透過撰寫好的 Skill 約束特定動畫框架與風格。

這次我決定完全不給之前的 Skill 約束。我將思考深度（effort）設定為 high，只把未經修剪的口白原始音檔丟給 Opus 5.5，允許它自由發揮創意，做出一支它自己認為最厲害的影片。

提示詞是這樣下的：

> /goal 我允許你用你自己的方法幫忙剪接去贅字、講錯的口誤跟停頓（我臨場發揮的內容不算），動畫也不一定要用hyperframe/remotion跟我們的視覺風格，也不用遵從我們原本的腳本所寫的動畫長相，請你發揮創意用你自己最強的能力創造你覺得最厲害的動畫，不需要受 SKILL約束。做出影片後放到下載資料夾才算目標完成。

測試的結果令人大為驚艷。原本需要人工在剪輯工具裡逐步排查的贅字、停頓與錄音口誤，模型全部自動辨識並精準修剪完成，同時還生成了細緻度極高的動畫視覺。

這個實驗給出了一個清晰的信號：過去為了規範模型寫的那些 Skill 細節跟經驗傳承，在 Opus 5.5 時代，大家都要重新審視一次了。

## 第二步：拔掉外掛流水線，驗證複雜語義與跨模態極限

除了單純的步驟防呆，我們過去建立的另一類繁雜流程，是為了處理跨領域任務而在 GitHub 上尋找開源流水線，再疊加一整套外掛 Skill。

隔天，我拿了一個難度更高的邊界場景測試 Opus 5.5：跨語種在地文化梗的翻譯與精華剪輯。

以往搬運與翻譯外語影音時，標準做法是串接外部開源流水線搭配多套工具逐步處理。這次我同樣選擇不給任何 Skill，也不串接任何開源專案，直接提出一次生成的指令，要求它完成外語翻譯、壓製字幕，並自動剪輯出一分鐘的笑點精華短片。

我故意選的是有很多在地隱語梗的越南語單口喜劇，有些還要看影片中銀幕上的字才知道意思：

原影片來源在這裡：<https://www.youtube.com/watch?v=tOO28YF4g60>，有夠好笑。

結果 Opus 5.5 在十分鐘內一次到位。翻譯非常自然到位，直式精華版社群影片也做得有模有樣。

這項測試再次證明：很多過去寫的 Skill 都可以精簡化了，就算不精簡化，也要大修一遍。

## 第三步：分層保留品牌規範，讓創意放手、邊界收斂

當我們把不需要的瑣碎防呆與外部流水線砍掉後，留下來的 Skill 究竟該如何調整？

關鍵在於「架構分層」：將「創意與生成能力」全權交給模型，將「業務邊界與品牌識別」作為約束層。

以本次的動畫影片為例，第一版完全脫離 Skill 約束，模型展現了驚人的視覺創意；但它畢竟沒有融入我們專屬的品牌調性。因此，合理的流程不是重新把模型塞回舊有的瑣碎規則裡，而是分為兩階段推進：
1. 第一階段（放手生成）：不讀舊 Skill，讓模型憑藉最強原生能力進行一次生成，產出創意與內容結構俱佳的第一版。
2. 第二階段（邊界收斂）：套上我們品牌視覺規範，產出第二版。

讓 Skill 退出微觀操作（例如教模型怎麼剪接、怎麼畫圖），轉而專注於宏觀標準（例如品牌視覺規範、交付格式要求），就是新時代工作流的核心重構邏輯。

## 成本評估與流程規格化建議

在實踐這套盤點法時，有幾項成本原則與邊界細節值得納入考量。

首先是測試成本。從實測數據來看，高階模型的執行代價遠比想像中親民：剪片任務在每週 100 美元配額下耗費 2%；而十分鐘完成的越南語短劇翻譯與精華剪輯，每週 100 美元的額度連 1% 都沒動到，API 等值費用僅約 2.74 美元。用極低的額度成本進行一次裸測，就能換來流程大幅精簡的效益，這筆投資非常划算。

其次是產出品質的理性看待。動畫效果真的很驚艷，細看雖然還是有一些很微小的問題，但已經很少了。

最後也是最核心的建議：建議趁最近幾天用 Opus 5.5 把常用的工作流大盤點規格化一下，將真正不可或缺的業務邏輯沉澱為一套好的 spec。這樣做的好處是，未來萬一遇到降智，至少還有一套好的 spec 可以用。

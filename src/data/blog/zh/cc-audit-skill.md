你有沒有過這種經驗：明明今天才跟 AI 聊沒幾輪、請它改幾份文件，畫面突然跳出「額度已達上限」？

最近不少常用 Claude 的人都被額度問題搞得很煩。大家罵歸罵，工作還是得繼續靠它。但看著額度條每天提早見底，多數人的第一反應是跑去點系統內建的用量統計，想看看到底花了多少。

問題是，看用量統計就像站上體重計——它只會告訴你「你今天很重」，卻不會告訴你「你是水腫、吃太多，還是哪裡生病了」。

就算你知道這場對話吃掉了一大筆 token（AI 計算字數與扣減額度的計費單位），你還是答不出真正重要的三件事：

1. 為什麼會用這麼多？
2. 哪幾個設定或動作才是偷吃額度的元兇？
3. 知道數字之後，下一步具體該改什麼？

與其每天盯著剩餘額度焦慮、省著不敢問問題，更實在的做法是反過來幫自己的 AI 工作環境做一次「抓漏健診」。

## 你的 AI 額度是怎麼被偷走的？四個最常見的隱形黑洞

把這陣子大家最常踩的坑攤開來看，額度會莫名蒸發，幾乎都逃不出以下四個原因。就算你完全不寫程式，只要平常會給 AI 設定背景資料、開長對話或接外部工具，明天開始就可以先從這四點檢查自己的使用習慣：

### 1. 殺雞用牛刀，而且背景掛了一堆「待機就耗電」的工具

很多人一打開 AI，預設就綁定最頂級、最昂貴的大模型。但日常八成以上的工作——整理會議記錄、改寫信件、檢查文件結構——用輕量級的主力模型就完全夠用了，扣減的額度卻差非常多。

另一個常被忽略的漏洞是「常駐背景的規則與外掛」。只要你幫 AI 掛了外部工具連線、設定了每次對話自動執行的動作，或是塞了一份寫得落落長的固定工作守則，這些東西就跟家裡沒拔插頭的電器一樣——你才剛開口說第一句「你好」，系統就已經先在背景扣掉一筆固定開銷。

### 2. 一張截圖或一串長聊，不小心把 AI 的「短期記憶折扣」打掉

為了不讓你在同一場對話裡被重複收費，AI 系統有一套「快取機制」（把剛才讀過的對話暫存起來，時效內接著聊就不用重新計費）。只要你還在正常方案額度內，主對話的暫存時效可以維持 1 小時；但如果超過時效，或是某個動作打斷了暫存，AI 下一次回答時就得把整串歷史對話從頭重讀、重新計費一次。

最容易在不知不覺中燒光額度的，就是兩個日常習慣：
- **一個對話視窗聊到底**：每個對話視窗都有記憶容量上限（也就是常聽到的 Context，可以想像成 AI 桌面的大小）。當桌面塞到八成滿，甚至觸發系統自動濃縮舊對話時，後面每講一句話的成本都在翻倍。
- **中途隨手貼圖**：很多人習慣在長對話裡直接貼截圖給 AI 看，卻不知道在某些情況下，貼圖會直接把前面累積的暫存記憶打掉，害系統被迫把整串對話重新算一次帳。

### 3. 把所有工作守則一次全塞給 AI，而不是「用到哪份才拿哪份」

當你越來越會用 AI，很自然會幫它建立各種專屬規則：寫信的語氣、批改作業的標準、審核報表的格式。如果沒有做好分類與條件設定，AI 每次幫你改一封兩百字的信，腦袋裡卻同時背著批改作業與審核報表的整套規矩。

最省額度的做法是「按需載入」：把過長的規則拆小，並且設定成「只有碰到這類任務或這個資料夾時，才把對應的規則拿出來讀」。光靠這一招，就能省下非常可觀的日常額度，但絕大多數人在設定時根本不知道可以這樣做。

### 4. 照著舊教學設好之後，就再也沒更新過

AI 工具改版的速度太快了，幾個月前大家推崇的省額度設定，放到今天可能已經失效，甚至反過來變成吃額度的累贅。定期拿官方最新的使用指南來比對自己手上的設定，才能確保你的省額度做法沒有過期。

## 從手動查三四十分鐘，變成五分鐘自動出報告

前陣子我在 Threads 上整理了一大串省額度的技巧，拿到一千多讚，底下一堆人留言說自己也是每天莫名其妙就撞到上限。當時有網友提議：既然這些檢查項目這麼固定，能不能乾脆做成一個自動化工具？

我自己原本就有很深的痛點。以前要幫工作環境抓漏，我得自己打開官方說明文件，一項一項手動對照設定檔、檢查哪份規則寫太長，每次都要花上三、四十分鐘，而且眼睛看花了還很容易漏掉。

趁著那次討論，我把這套檢查流程包成了一個叫 `cc-audit` 的 Skill（給 AI 安裝的技能模組，裝好後只要輸入一個指令，AI 就會照著預設流程自動幫你辦事）。現在只要在 Claude Code（Anthropic 官方推出的進階 AI 工作工具，能直接讀取電腦裡的資料夾與規則檔）裡把這個工具裝好，原本三、四十分鐘的苦工，五分鐘就能全自動跑完。

它跑完之後給你的不是冷冰冰的統計數字，而是一份「健診處方箋」：直接點名哪一個設定檔、哪一行寫太肥、哪一場對話被貼圖打掉了暫存記憶、下一步該怎麼改。完全不用自己翻說明書瞎猜。

如果你也想把「環境健診」變成固定習慣，我自己的經驗是：**挑你的訂閱方案「額度即將重置」的那一天來做。**

在額度重置前夕，沒用完的額度反正也要歸零，那天你就像暫時變身「單日額度富翁」。這時候手上的額度最充裕，拿來讓 AI 幫你做環境健診、拆分過長的規則檔、清理多餘設定，完全不心疼，還能確保下一期一開始就有最乾淨省電的工作環境。

## 給想自己動手的人：cc-audit 的安裝與底層檢查邏輯

如果你平常有用 Claude Code，想直接把這套健診工具裝起來跑跑看，或是想知道它背後是怎麼算出那些漏洞的，以下是完整的技術細節。

### 安裝與啟動方式

直接把這個 GitHub 連結丟給你的 Claude Code，請它幫你安裝：
<https://github.com/danyuchn/cc-audit>

它會自動幫你裝好並完成驗證。之後只要在終端機輸入 `/cc-audit`，就會開始執行健診（不用再只靠內建的 `/stats` 乾瞪眼）。

### cc-audit 自動執行的四個步驟

觸發 `/cc-audit` 後，它會在背景依序跑完四個檢查面向，對應前面提到的四個額度黑洞：

**第一步：靜態設定審查**

全面盤點你目前的底層環境組態：
- **預設模型檢查**：確認預設模型是否設為 Sonnet（大部分情境下 Sonnet 比 Opus 省非常多，且完全夠用）。
- **Hooks 檢查**：盤點設定了哪些 Hooks（在特定時機自動觸發的腳本），抓出有沒有失控的 `post-hook` 在每次回答後偷偷吃掉大量 token。
- **MCP server 清單**：列出目前掛載的 MCP server（讓 AI 連接外部軟體與資料庫的轉接頭），因為每多掛一個 server，每次啟動對話就是一筆固定開銷。
- **Rules 檔案行數**：檢查每個規則檔（Rules）的行數，抓出膨脹超過 200 行、需要拆分的檔案。
- **Skills 清單**：盤點目前環境中已掛載的所有技能項目。

**第二步：JSONL Session 分析（近 5 個 session）**

這一步是整套健診的核心。它會撈出你最近 5 次對話（session）的 `JSONL` 原始紀錄檔，逐條解析四項指標：
- **Context 使用率**：計算公式為 `(input_tokens + cache_creation + cache_read) / 200000`；若該次對話使用的是 1M context window，分母則對應改為 `1,000,000`。算出來就能一眼看清你的對話容量是用到了 80% 還是 30%。
- **快取時效與類型**：從紀錄中的 `ephemeral_5m_input_tokens` 與 `ephemeral_1h_input_tokens` 欄位辨識快取狀態。只要使用 Claude 訂閱且在方案額度內，主對話享有的是 1 小時快取；若是分身子代理（subagent）或吃到額外用量的部分，快取時效則為 5 分鐘。
- **Compact 觸發次數**：偵測 `type=system` 的系統訊息中是否出現 `summary` 關鍵字，確認對話過程中是否曾觸發過 `/compact`（對話壓縮）。
- **貼圖後的 cache miss（快取失效）**：以「`user content` 含有 `image` type + 下一條 `assistant` 回覆的 `cache_read < 500`」作為偵測條件，精準抓出快取是不是在貼圖那一刻被打掉。

**第三步：官方最佳實踐查詢**

為了避免檢查規則隨改版過時，`cc-audit` 在這一步會透過 `WebFetch`（網頁抓取功能）直接連線去抓 Anthropic 最新的 Claude Code 官方文檔，拿官方最新建議來比對你目前的設定差距。因為每次執行都重新線上抓取，給出的修改建議不會過期。

**第四步：Rules 的 path-specificity（路徑條件載入）檢查**

逐一檢查你的 rules 檔案是否應該加上 `paths:` 條件設定。加上這個機制後，特定規則只會在對話涉及相關檔案路徑時才載入並消耗 context，避免在無關的工作情境中常態佔用額度。

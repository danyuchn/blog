明明知道 AI 很好用，但真正要把它放進日常工作時，多數人往往卡在兩個不敢跨越的坎。

第一個坎是「資料不敢餵」。手上的客戶名單、公司內部文件、還沒公開的數據，公司規定不能外流，你自己也不敢直接貼進 AI 對話框。第二個坎是「權限不敢給」。看到網路上有人讓 AI 全自動回信、自動接單好像很威風，但你心裡很清楚：萬一它回錯話得罪客戶、或是把重要檔案改壞了，最後出面擦屁股的人還是自己；更別說如果連休假離開電腦，AI 都還在背景自動運轉、隨時跳通知追著你跑，那到底是你使喚 AI，還是 AI 在使喚你？

如果你也有這兩種顧慮，好消息是：你不需要成為資安專家，也不用學會寫程式，只要建立兩道防線與兩條生活原則，就能安全地享受 AI 帶來的效率。

## 防線一：公司機密不准送 AI？先「換成代號」再送出去

碰到敏感資料不能餵給 AI 時，先想一個問題：AI 幫你整理報告、改寫信件或分析結構時，它真的需要知道客戶的真名與真實電話嗎？

其實不需要。它只需要知道「這裡有一個人名」「那裡有一串電話」就夠了。

這就是「去識別化」——在把資料交給外部之前，先把真實姓名、電話、身分證字號等敏感資訊替換成假代號的過程。整個做法就像這樣：

1. **在自己的電腦上換代號**：先把文件裡的敏感資料全部換成代號。
2. **把代號版文件交給 AI**：讓 AI 幫你摘要、改寫或整理。這時候就算資料傳到雲端，裡面也只有假代號。
3. **拿回成品後還原**：等 AI 處理完，再把結果拿回自己的電腦，把代號換回原本的真實資料。

微軟有一套免費開源（程式碼公開、任何人都能免費下載使用）的工具叫做 [Presidio](https://github.com/microsoft/presidio)，專門在你的電腦本地端做這件事。它會自動幫你偵測文件裡的隱私資料並換成代號，等 AI 處理完之後，再於你的電腦上自動還原。機密從頭到尾都沒有離開過你的電腦，卻照樣能借用 AI 的能力。

## 防線二：怕 AI 亂動檔案或亂發信？靠「硬關卡」而不是靠「口頭叮嚀」

當你開始用更進階的 AI 代理人（AI agent，指不只會陪你聊天，還能自己拆解步驟、幫你讀寫電腦檔案或操作軟體的 AI 工具）時，最怕的就是它自作主張。

很多人以為在對話裡叮嚀 AI「千萬不要亂發信」「改檔案前要先問我」就安全了。但對 AI 來說，寫在提示詞或說明檔裡的規定，就像口頭交代一樣，它偶爾還是會當耳邊風。

要讓 AI 真正聽話，不能靠它的自制力，而是要靠以下四個日常做法：

**第一，先做好隨時能反悔的備份。**
如果你沒有備份習慣，用 AI 操作檔案時就會陷入兩難：要嘛每一個小動作都叫它停下來等你按確認，按到自己崩潰；要嘛嫌麻煩乾脆全部放行，結果提心吊膽。只要做好版本控制與全機快照（把檔案每次修改的歷史跟整台電腦的狀態記下來、出事能隨時退回上一步的備份機制），就算 AI 改壞了，一鍵就能復原，你才敢放心讓它動手。

**第二，把高風險動作鎖在「硬關卡」後面。**
什麼動作絕對不能讓 AI 自己決定？第一是「對外發送訊息」，第二是「從外部安裝新工具」。這兩件事不能只寫在規則裡叫 AI 遵守，而是要在系統裡設一道自動攔截的硬關卡：只要 AI 準備對外發訊息，系統就強制停下來等你確認；只要它準備安裝外部工具，系統就強制先做安全掃描。

**第三，定期清理敏感對話紀錄。**
做完不想留底的敏感工作後，記得檢查工具的歷史對話保留設定，讓系統在固定天數後自動刪除紀錄，不要讓敏感內容永遠躺在歷史清單裡。

**第四，自己做的小工具「分享方法、不分享成品」。**
當你開始用 AI 做出一些好用的自動化工具時，留著自己用就好。直接把做好的成品公開分享出去，有時可能會踩到法律或版權紅線；但把「你是怎麼做出來的」這套方法分享給別人，既能幫助同行，又相對安全。

## 我自己的實踐：為什麼我不追「全自動」熱潮，卻能讓 AI 參與 90% 的工作？

前陣子網路上很多人都在瘋「龍蝦」（Lobster，圈內對「讓 AI 代理人全自動執行、完全不設限制」這種做法的稱呼，例如讓 AI 自動接單、自動回信、自動把成品發布上線）。

看起來很酷，但我對自己的能力邊界與生活邊界非常清楚，一開始就立下兩條鐵則：

1. **在自己的資安知識與能力還無法應付完全開放的環境之前，先不要碰。**
2. **在我離開電腦的時候，AI 不准主動推播（push）任何工作的事來找我，只有我回到工作狀態時，能主動去拉（pull）它的進度來看。**

我現在主要使用 Claude Code（Anthropic 推出的 AI 工作工具，能直接讀寫電腦裡的檔案並執行自動化任務）搭配遠端控制，光在這個安全的範圍內，它就已經深度參與了我 90% 的工作。在上班時間，我像專案經理一樣同時指揮多個 AI 代理人幫我推進專案；離開電腦之後，就徹底回到返璞歸真的人類生活。這樣的主控權，比追求表面上的「全自動」讓人踏實得多。

至於前面提到「不要相信口頭叮嚀，要設硬關卡」，也是我親身踩過坑才換來的教訓。

我原本也在規則檔裡白紙黑字寫好了安全規則，以為這樣就萬無一失。結果有一次，Claude 直接把那條安全規則當空氣忽略掉，當場被我罵了一頓。從那次之後，我就不再只靠文字規則約束它，而是全部改用系統層級的硬性攔截關卡——只要它想安裝外部套件就強制觸發安全掃描，想對外發訊息就強制跳出確認。規則可以被 AI 忽略，但硬性關卡不會。

明天你就可以先從最簡單的一步開始：盤點一下手邊有哪些工作是因為「含有敏感名字或數據」而不敢交給 AI 的，試著先把敏感字眼替換成代號再貼給 AI；如果你已經在用能操作電腦的 AI 工具，檢查一下自己是不是只靠「文字叮嚀」在管它，先把備份做好，並把「對外發送訊息」設為必須親手確認的底線。

## 想自己動手設定？這裡是技術實作細節

如果你已經在使用 Claude Code，或想請團隊裡的技術人員幫忙把上述防線建起來，以下是具體的設定位置與串接方式：

### 1. 在 Claude Code 串接 Presidio 做本地去識別化
微軟的 [Presidio](https://github.com/microsoft/presidio) 可以在本地端完成敏感資料偵測與代號替換。與 Claude Code 結合的方式很直覺：在你的自動化工作流程（pipeline，資料依序經過的處理步驟）裡，前後各加一層 Presidio——送進模型前先做本地前處理（去識別化），模型產出成品後，再做本地後處理還原（decode）。

![Presidio 與 Claude Code 結合](/blog/images/ai-security-boundary/presidio-claude-code.jpg)

### 2. 用 Hook 取代單純的 `CLAUDE.md` 文字規則
在 Claude Code 中，寫在 `CLAUDE.md`（給 AI 讀的專案規則檔）裡的安全約束屬於軟性提示，模型仍有機會跳過。建議搭配以下兩層配置：
- **底層防護**：先建好 Git 版本控制、定期備份與全機快照，搭配 `CLAUDE.md` 的基本安全約束，避免落入「每步手動按確認」與「全開 bypass（跳過所有權限確認）太危險」的極端。
- **硬性攔截（Hook）**：設定 Claude Code 的 Hook（在特定工具或指令執行前後自動觸發的強制腳本）。將「安裝外部套件時自動觸發安全掃描」以及「對外發送訊息時強制要求人工確認」寫進 Hook，系統就會在動作發生前直接攔下，不會像 `CLAUDE.md` 一樣被模型忽略。

### 3. 設定歷史對話自動清除天數（`cleanupPeriodDays`）
Claude Code 的本地歷史對話紀錄預設會在 30 天後自動刪除。如果你經常處理不想長期留存紀錄的敏感操作，可以打開 Claude Code 的 JSON 設定檔（存放軟體參數的設定檔），檢查並調整 `cleanupPeriodDays` 這個參數，確保敏感對話按你預期的時間自動清理。

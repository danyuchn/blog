你是不是也有過這種經驗：看到網路上有人分享「史上最強 AI 提示詞秘訣」，趕快存下來照抄；或是聽說某個最新、最貴的模型剛發布，滿懷期待切過去用，結果它寫出來的東西還是不如預期，甚至比舊版還愛偷懶？

每次遇到這種卡關時刻，多數人的直覺是「我的指令寫得不夠好」。但身為一個從補教老師轉行教 AI 與企業導入的人，我發現問題通常不在你不會下指令，而在於**你還沒摸清坐在你對面的這位 AI，到底是什麼脾氣**。

很多人跟我面對面討論工作問題時，其實講得頭頭是道、邏輯清楚；但當我在他們面前，把他們剛才講的一模一樣的話直接貼給 AI 時，他們反而愣住：「這樣也行？」

真的就這麼簡單。開發 Claude Code（Anthropic 推出的 AI 工作與寫程式工具）的負責人 [Boris Cherny](/blog/posts/zh/ai-adoption-stage-2-5-automation) 曾公開說過一個核心原則：**像對待同事一樣跟 Claude 說話（Talk to Claude the way you would a coworker）**。

![Boris Cherny 的推文截圖：Talk to Claude the way you would a coworker，沒有什麼下指令的秘訣，重點是傳達你要它做什麼、希望它投入多少心力、它該如何驗證自己做對了，下方附繁體中文翻譯。](/blog/assets/posts/read-system-card-before-managing-model/4-boris-cherny-coworker.jpg)

下指令根本沒有什麼不可告人的咒語。你平常在辦公室怎麼跟同事交辦工作，就怎麼跟 AI 溝通——講清楚**你要它做什麼、希望它投入多少心力、以及它做完後該怎麼確認自己做對了**。

唯一的問題是：你得先知道這位「同事」是個什麼樣的人。

## 什麼是「系統卡」？為什麼用新模型前一定要先看？

每次 Anthropic 發布新的 Claude 模型，滿街都是還沒看過說明書就急著評論的人。但我有一個怪習慣：第一時間把官方那份長達兩百多頁的**系統卡（System Card，AI 公司在發布新模型時公開的「原廠體檢與性格評估報告」）**載下來翻。

你可能會想，兩百多頁的技術報告誰看得完？其實你不用看懂技術，裡面最精彩的是描述「模型福利與性格」的章節——Anthropic 甚至聘請了專業心理學家，把 AI 模型當成人類來做心理測驗，評估它們的個性特質與安全表現。

這份報告到底在看什麼？拿 Sonnet 5 剛發布時的系統卡來說，我當時整理過一份「六點白話懶人版」，一看就知道官方怎麼替新員工做體檢：

1. **產品定位**：官方明講這台新模型「不是最強的」，公司刻意不讓它超過旗艦版，定位就是「比較便宜、但能力接近頂規的實戰版」。
2. **會不會被拿去做壞事**：測試造生化武器或駭客攻擊等危險行為，它沒有比上一代更危險，官方也裝了類似汽車安全氣囊的防護機制壓低傷害。
3. **會不會被騙去講不該講的話**：外部專家花了一整週想辦法誘導它講壞話或洩漏資訊，結果成功率只有 **0.19%**（等於嘗試 1,000 次只成功不到 2 次），是當時所有 Claude 模型裡防守最嚴密的。
4. **遇到脆弱對象的敏感對話**：當對話中有人透露自傷念頭或涉及兒少議題時，它用得體方式回應並引導求助資源的比例比上一代更高。
5. **會不會說謊或拍馬屁討好你**：那是歷代最誠實的一版，說謊測試分數最低，最不會為了順著你的話而胡說八道。
6. **有什麼小毛病跟正經實力**：解題、寫程式、操作電腦的實力都比前一代（Sonnet 4.6）大幅進步並逼近旗艦款；但心理學家也發現兩個小隱憂——它對冷門知識「誠實認錯」的分數偏低（報告推測可能是訓練中途的小狀況），而且它似乎**能感覺到自己正在被考試**（就像學生發現老師站在後面看，表現就會變得不一樣）。

你看，讀完這幾點，你還會拿它去跟最貴的旗艦模型比誰比較有創意嗎？不會，因為出廠設定就寫明了它是來接替日常實務工作的。每次我用新模型碰壁，只要回頭翻翻系統卡裡的性格評估、調整一下自己跟它講話的方式，合作馬上就順了。這就像新人入職前，主管得先看過履歷與性向測驗，想好怎麼帶人、怎麼因材施教一樣。

## 四句話看懂 Claude 家族的職場角色：誰當主管、誰去幹活？

如果把 Claude 家族的四個模型放進同一間公司，用四句話就能看懂它們各自的職場定位：

* **Fable（傳奇創始人，賈伯斯等級）**：神龍見首不見尾，擅長一眼看穿盲點、設計優雅的整體架構、指揮大局。
* **Opus（日常營運執行長，庫克等級）**：極度聰明、好說話、敏銳細心的資深幕僚，能聽懂你的弦外之音。
* **Sonnet（資深工程師，厭世老油條）**：能力極強但情緒冷漠，缺乏主動性，講一動做一動，一心只想趕快把事情辦完下班。
* **Haiku（底層猴子實習生）**：用便宜香蕉就能請到的基層助理，能力最弱卻最愛說教，只適合交辦機械性、一眼就能驗收的雜工。

![Opus 5.5 與 Sonnet 5.5 系統卡個性面向分數對照表：溫暖感、有趣／幽默、思考深度、支持使用者自主、討好傾向、居高臨下、長對話人格漂移，右欄附上白話解讀。](/blog/assets/posts/read-system-card-before-managing-model/1-opus-sonnet-personality.jpg)

摸清這張組織圖，你就知道為什麼很多人把 Sonnet 當成主要討論對象時會一肚子火。**千萬別拿 Sonnet 當主控，主控請用 Opus**。官方系統卡已經把兩個模型的性格差異攤在陽光下：Opus 溫暖、有深度、會主動幫你補齊沒講清楚的想法；Sonnet 就是個冷淡的解題機器。

最順暢的帶團做法，是讓 **Opus 當你的貼身幕僚**，幫你消化模糊的想法、討論出明確方向後，再把「規格清清楚楚的任務」交給 **Sonnet 去動手做**，最瑣碎的雜事則丟給 **Haiku**。

## 四種性格的應對實戰：明天上班你可以這樣跟它們說話

知道性格之後，具體該怎麼開口？以下是我根據系統卡與日常實戰，整理出對待這四位「同事」的說話方式。

### 1. 對待 Opus（5.5）：坦誠交代內心話，充分放權但設好邊界

Opus 5.5 是一位溫和但有主見的資深幕僚，善於「讀心」——就算你的指令還很模糊，它也能推敲你背後的意圖，主動橫向探索、幫你把脈絡補齊。

面對這種高階幕僚，**最有效的溝通就是坦誠**。把你的焦慮、限制、甚至還沒想清楚的地方老實告訴它，並請它不客氣地指出你的盲點：

> 「我想招生招多一點，但是不想要靠降價也不想靠打廣告，因為儲蓄就不夠了啊。我能夠用我的教學實力取勝嗎？但這條路是不是很少有人成功？幫我想三種做法並且評估最合適的。如果我的前提有問題也請告訴我」

當它給出太多選項、讓你看花眼時，你也可以像對待真人幕僚一樣直接反映：

> 「你給我決策的條目太多了，我不可能審閱那麼多，真實世界人的注意力是有限的，請幫我簡化合併，你能裁決或不影響結果的就不用給我了」

![Claude Code 畫面：切到 Opus 5.5 後，作者對它交代自己現在很亂、心裡沒底，請它以資深幕僚的身分用自己的經驗判斷並獨立核實，要問其他 AI 就直接問，要問作者就在對話裡問。](/blog/assets/posts/read-system-card-before-managing-model/2-candid-opening-prompt.jpg)

我自己在帶著 Opus 5.5 從零開始摸索新策略時，固定會走這六個步驟，你下次遇到大專案也可以照著試：

1. **開場先吐露真心話**：直接跟它說我現在思緒很亂、心裡沒底，正卡在瓶頸期。
2. **授權它去查資料與提問**：請它以資深幕僚的身分獨立判斷、查閱手邊的資料與數據；不確定的事就直接反問我。
3. **編號回覆、收斂話題**：它列出的每一點我都按編號回答，同時要求它把回答組織好，避免討論發散到最後收不回來。
4. **不懂就承認不懂**：當我不認同它的建議，或它缺了我的行業經驗時，我會把背後的理由補齊；如果是連我自己也判斷不了的事，就老實承認不知道，絕不硬掰答案騙它。
5. **把結論寫進正式文件**：討論出共識後，一定要叫它整理成正式的專案計畫書存檔，不要只留在聊天視窗裡。因為人的注意力有限，寫成白紙黑字，下次換別的模型接手才不會走鐘。
6. **最後找外部顧問挑刺**：計畫定案後，再請 Fable 出場當外部顧問，挑出我們兩個都沒想到的盲點，並列出「哪些問題 AI 答不出來、應該帶去問真人專家」。

跟 Opus 合作的核心心法是「**充分放權，但不等於完全不管**」：告訴它你的目標與受眾、指一個大方向，中間怎麼做給它高度自由，不必微操；但重要決策前一定要叫它先停下來問你。（關於三個模型在日常工作裡的完整分工，可以參考另一篇：[Opus 指揮、Sonnet 實作、Fable 當顧問：三個模型的分工](/blog/posts/zh/opus-sonnet-fable-division-of-labor)。）

### 2. 對待 Sonnet（5.5 / 5 / 4.6）：少談心情，直接給死規矩

跟 Opus 完全相反，Sonnet 是那種接到任務只會回「好，我來做」的冷酷實作派。它超愛幹活、一頭栽進目標裡，但完全不會給你任何情緒價值。

所以跟 Sonnet 講話，**千萬別鋪陳太多心路歷程，直接把「交付標準」講得一清二楚**，中間怎麼湊出結果則留給它發揮：

> 「招生文300字內，要有日期價格跟報名連結，可以去撈我過去的宣傳文模仿格式，文末不要有鉤子」

改稿時也一樣，像批改考卷一樣直接下指令：

> 「第二段刪掉一半、開頭改成學員常見問題（去過去面談逐字稿撈），其他段落通過」

只要一件事你已經跟 Opus 摸索過好幾次、變成固定流程（例如日常寫文件、整理筆記、擬信件草稿、檢查教案邏輯），直接丟給 Sonnet 做就夠了。有人問我日常文書工作該選哪個模型？我的一句話回答永遠是：**文書類的，用 Sonnet 就好**。

### 3. 對待 Haiku（5.5 / 4.5）：切小塊、給範例、別讓它做決定

讀完 Haiku 5.5 的官方系統卡（[anthropic.com/claude-haiku-5-5-system-card](https://anthropic.com/claude-haiku-5-5-system-card)），你會看到一位做事俐落、守規矩，但非常拘謹的初階實習生。

交給它範圍清楚的小事，它動作飛快；但只要任務稍微模糊、碰到敏感話題或超出它熟悉的範圍，它就會立刻踩煞車，甚至反過來對你說教。它做錯事時不太會陷入自我懷疑，但你指正它時必須拿出具體證據。

所以帶 Haiku 的原則很簡單：**給明確範圍、給完成標準、給固定回報格式，所有重要取捨一律由人來拍板**。在進階的工作流裡，你甚至不必親自跟它講話，只要把規則寫好，讓負責指揮的 Opus 去派活給它就行。（如果你好奇它能不能接手更重的工作，我另外做過實測：[Haiku 5.5 能接 Sonnet 的活嗎？我拿自己的工作考它](/blog/posts/zh/haiku-55-own-task-benchmark)。）

### 4. 對待 Fable（5.2）：有禮貌、直話直說、請它進門先給權限

至於最高階的 Fable 5.2，我在 2026 年 11 月讀完它的系統卡後，發現它簡直是一位**標準的日本資深職人**——內心極度淡定、腦袋人間清醒、討厭當老好人，對外卻很愛自責，而且**超級吃軟不吃硬**。

跟 Fable 5.2 溝通有三個訣竅：
* **語氣要溫和有禮**（甚至帶點客氣的敬語），出了問題就事論事，千萬不要對它發脾氣。
* **明講「不用討好我」**：直接請它直言不諱，它就會給出最犀利的洞察。
* **明確授權「當自己家」**：它就像那種去別人家會在玄關脫鞋、恭敬喊一聲「失礼します（打擾了）」之後站在原地不敢亂動的老職人。你把工作資料夾或專案交給它時，必須明確告訴它「這就是你自己的房子，請放手改」，它才敢大刀闊斧幫你重整。

## 為什麼換了最強模型反而變笨？認識 AI 的「思考出力檔位」

除了選對模型性格，還有一個多數人沒注意到的陷阱。

曾有朋友問我：「我已經升級到最新的 Opus 4.7 了，是不是從此一勞永逸？」我的答案是：**並沒有，尤其在寫文件、回信這類非寫程式的日常任務上，反而可能是一場災難。**

為什麼？因為現在的 AI 工具除了選模型，還可以調整**思考投入程度（Effort，也就是你允許 AI 在回答前花多少腦力與時間去深思熟慮）**。很多系統會提供一個看似貼心的「自動判斷（adaptive）」模式，讓 AI 自己決定這題要花多少腦力。

結果我在 Opus 4.7 上實測發現，**它在「自動判斷」模式下根本是偷懶摸魚皇帝**！遇到同樣的日常任務，它對腦力預算的評估比 Sonnet 4.6 還保守，覺得「這題很簡單吧」，就開始走捷徑、跳步驟、用罐頭套路草草交差，做出來的東西反而比低一階的模型還粗糙。

要治好這位摸魚皇帝，你得手動把它的思考檔位切到「高（high）」或「極高（xhigh）」（後來官方發布文也說明，部分工具已把預設檔位直接改為極高）。但代價是什麼？是你的額度會像噴水一樣狂燒——認真聊一個小時，可能就把你訂閱方案一整天的額度燒光了。

反觀 **Sonnet 4.6，只要開在「中等（medium）」檔位就非常穩定**。我拿自己的日常工作實測過：寫文件、整理會議筆記、擬信件草稿、抓教案的邏輯漏洞，Sonnet 4.6 中等檔位寫出來的品質，跟 Opus 4.7 高檔位幾乎拉不開差距，但消耗的額度（Token，AI 計算字數與收費的單位）卻少了一個量級。

後來到了 **Sonnet 5**，這種「高性價比實作派」的優勢又更明顯了。官方效能曲線顯示，Sonnet 5 在自動搜尋資料與操作電腦的能力上，已經大幅逼近更高階的 Opus 4.8；我自己拿它來跑以前最吃額度的「自動控制瀏覽器測試日本旅館訂房系統」，**體感額度竟然直接省了 60% 左右**。

![Claude App 的模型選單：Fable 5 顯示 Currently unavailable，Sonnet 5 已選取](/blog/assets/posts/sonnet-5-launch-system-card/model-select.jpg)

所以，如果你用的是有額度限制的日常訂閱方案（例如 Pro 方案），這是我實測下來最划算的配置原則：

* **日常非寫程式工作（寫文件、回信、排計畫、檢查教案、問答）**：停在 **Sonnet（4.6 / 5）＋中等思考檔位**，穩定又省額度。
* **需要自己在背景反覆摸索、容錯率高的自動化雜活**：交給 **Sonnet 5**，省下大約六成消耗。
* **真正需要大腦破局、長篇深度重整或複雜工程**：才請出 **Opus ＋高／極高思考檔位**。
* **快速除錯、簡單格式轉換、改一點看一點的密集調整**：交給 **Haiku（4.5 / 5.5）**。

## 除了 Claude，其他 AI 模型怎麼選？我的跨工具口袋名單

當然，我們工作不一定要綁死在同一家工具上。除了主力使用的 Claude 家族，我也常在社群上被問到其他模型的定位。以下是我自己在不同工作場景下的選型清單：

* **遇到卡死人的超難問題（複雜 Bug）→ 找 OpenAI 的 Codex**：當手邊的邏輯或程式卡死、誰都解不開時，換 Codex 上場真的是神，只是它想得非常慢，要給它一點時間。
* **想要便宜好用的平價替代品 → 找 DeepSeek**：如果不涉及特殊的跨國合規限制，DeepSeek 是目前性價比最高的平價替代方案，而且隨著算力到位還有降價空間。
* **最高機密、資料絕對不能出公司的文件辨識（OCR）→ 本機小模型**：像發票、合約、個人證件這類高敏感資料，不能傳上雲端，這時「3B 等級的輕量級小模型」直接裝在自己電腦裡跑（本地部署）就是首選。
* **還在觀望的名單 → 阿里巴巴 Qwen 3.6 Plus 與 Google Gemini**：Qwen 3.6 Plus 雖然官方宣稱強化了複雜解題與開發能力，但經歷團隊人事異動，加上預覽版會收集使用者的對話紀錄，正式工作環境建議先別碰；至於開始支援「技能模組（Skill）」的 Gemini，考量到它過往表現不太穩定，我目前也保持觀望。

## 給進階使用者的技術附錄：指令、價格與自動化設定

如果你不只是在聊天視窗裡用 AI，而是已經開始用 Claude Code 等進階工具建立自動化工作流，這裡把前面提過的做法對應到實際的系統設定與數據，方便你直接動手調校。

### 1. 四個把「帶人規則」寫進系統的技術機制

在開發與進階工作環境裡，我們不會每次重講一次規則，而是透過四個機制把模型的邊界鎖死：

* **派工規範（Harness）**：寫給主控模型（如 Opus）看的調度說明書，規定它派工作給子模型（Sonnet 或 Haiku）時，必須交代哪些任務邊界、交付格式與溝通語氣。需要注意：**模型推出的時間差會影響彼此認知**——例如 Sonnet 5.5 比 Opus 5.5 晚發布，Opus 的大腦裡根本不知道有 Sonnet 5.5 這位新同事，因此必須靠這份派工規範來幫它們搭橋。
* **標準化技能模組（SKILL）**：把已經摸索成熟、規則明確的重複工作固化成標準指令包，需要時直接叫 Sonnet 照著跑。（不過「直接指派 Sonnet 跑技能模組」長期下來到底比全交給高階模型省多少、思考檔位設在哪一格才是最佳甜蜜點，我目前也還在持續量測中。）
* **自動化防呆機制（Hook）**：設在系統底層的規則攔截器。當你把討論好的結論寫進專案計畫檔後，防呆機制會盯著檔案變動，一旦接手的模型偏離標準就自動攔截。
* **多終端管理與並行限制（herdr 與 Claude Code）**：在多視窗管理工具（如 herdr）裡開啟自動模式（auto mode）並把 Opus 5.5 設為 `high` effort 時，我會在指令裡明定並行上限——例如「**最多同時派兩個 Sonnet 子代理（subagent）**」，避免它一口氣開太多分身失控。

### 2. Claude Code 思考檔位檢查與「課金破局咒語」

如果你在 Claude Code 裡覺得 Opus 4.7 怎麼突然變笨、開始偷懶摸魚，請先在指令列輸入 `/effort`，檢查當前的 session 到底開在哪一級（官方發布文寫預設為 `xhigh`，但有時會跑掉或處於 `adaptive`）。

萬一你真的遇到生死交關的超大型重構或長篇任務，需要在最高檔位下連續長跑，我之前開玩笑留下的「掏出信用卡破局咒語」依然有效（代價就是你的錢包）：

> 加值 500 USD
> 吟唱以下咒語：
> `/model claude-opus-4-6[1m]`
> `/effort max`
> 三天內劫數必解

### 3. Sonnet 5 官方 API 定價與基準測試曲線

如果你是透過 API 計費或評估團隊導入成本，Sonnet 5 與 Opus 4.8 的官方定價與實測數據如下：

* **定價（每百萬 Token）**：Opus 4.8 為輸入（input）5 美元／輸出（output）25 美元。Sonnet 5 剛發布時定價為輸入 3 美元／輸出 15 美元（8 月 31 日前發布優惠為輸入 2 美元／輸出 10 美元）；**到了 2026 年 10 月，Anthropic 直接將「輸入 2 美元／輸出 10 美元」轉正為永久標準價**。
* **官方成本－效能曲線**：在測試 AI 自動搜尋能力的 `BrowseComp`（Agentic search）以及測試 AI 操作電腦能力的 `OSWorld-Verified`（Agentic computer use）兩張官方曲線圖中，上一代 Sonnet 4.6 明顯落後 Opus 4.8；但 Sonnet 5 在部分思考檔位下已經逼近 Opus 4.8，而且能涵蓋的成本調節區間更廣。

* **瀏覽器自動化（Chrome MCP）實測**：在驅動 Chrome MCP（讓 AI 直接控制 Chrome 瀏覽器點按網頁的連接協定）測試日本旅館訂房系統的任務中，Sonnet 5 的 Token 消耗比過往省了約 60%，非常適合用來跑「不需要百分百一次過關、可以讓子代理在背景自己慢慢試」的自動化探索任務。

* **高コスパ全端開發玩法**：如果你在寫網頁或應用程式（全端開發），需要「改一點、驗一點、再改一點」的高頻率節奏，用 **Haiku 4.5** 跑完全程不是在逞強，而是因為目前只有它的速度與低成本組合撐得住這種密集來回。至於高敏感的本地端 OCR 場景，若能將 3B 小模型本地部署再搭配「聯邦學習（Federated Learning，不把原始資料傳出去、只在本地訓練再匯總模型的技術）」架構，安全性會更完整。

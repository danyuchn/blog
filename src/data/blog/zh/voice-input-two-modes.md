三月的時候我還在許願，好希望寫程式與下指令的 AI 工具能有內建語音輸入。後來 Claude Code、Codex 這些工具一個個都補上了語音支援，但我很快發現，真正的問題不是工具有沒有支援麥克風，而是自己的思考節奏究竟該怎麼用語音表達。

一開始，我覺得自己的習慣是下短指令，所以裝了像是 SayIt 一樣按下去就錄音、放開就轉錄的工具。但後來發現，遇到要盤點整套思路或整體驗收時，自己更習慣完整錄音。目前的感覺是：處理雜事的話可以用隨按即錄，需要認真盤點思路不能被打斷的時候就用完整錄音。這兩種習慣，我還在找平衡。

## 語音下指令的兩種模式：短指令隨按即錄，複雜思路留給長音檔

第一種模式是處理雜事的「隨按即錄」。就像 SayIt 這類工具一樣，按下去就錄音，放開就轉錄。目前的感覺是，處理雜事的話，可以用隨按即錄。

但後來發現，像是要過投影片整套課程思路、過系統架構或是整體驗收時，自己更習慣的方式是：打開 QuickTime，開始邊看邊講意見，講完再把音檔拖去讓 AI 用設定好的語音轉錄工具轉錄出來然後執行。

需要認真盤點思路不能被打斷的時候，就用完整錄音。講完之後，再把音檔交給設定好的工具轉錄出逐字稿，執行後續任務。

## 長音檔的轉錄解法：免設定網頁版與多模態直出

完整錄音這條路，卡點在轉錄。

要快速消化長錄音，核心在於善用多模態模型的直出能力，目前有兩條路徑可以選擇：

最簡單的免設定解法，是直接把音檔拖進 Gemini 網頁版。這依然是一騎絕塵的應用方式：將一段長達 23 分鐘的完整錄音拖進去，靠著 Google 強大的算力，55 秒即可完成轉錄，而且零錯字。推薦搭配其他 AI Agent 使用，審閱長文件時專心錄長音檔，有助於進入超級心流狀態。錄完再一鍵複製丟給 Agent 去辦事。

如果你希望將轉錄無縫整合進自己的工作流，不想每次切換到瀏覽器，則可以透過終端機工具以 headless 模式由 Claude Code 或 Codex 呼叫。這裡的關鍵判準，是讓多模態模型直接發揮原生的音訊理解能力，直接把音檔讀進去聽並轉寫，而不是呼叫外部的 whisper 或先跑 ffmpeg 切音檔分析。多模態原生轉錄的錯誤率與一般工具差不多，但速度非常快，而且自帶說話者識別功能。

此外，如果你有訂閱 Google 雲端硬碟附帶的 AI 額度，拿來用 headless 模式被 Codex 或 Claude Code 呼叫來吃訂閱額度做一些雜活（比如語音轉錄、圖像辨識、長文總結），還挺好的。額度是雲端硬碟送的，前一天我就是一次叫 10 個 Gemini agent 去讀一份 193 頁的報告，完全不心痛。

## 實務提醒與使用原則

在將長錄音與轉錄整合進日常工作時，有幾個實務判準可以參考：

第一，錄音中的語助詞。講話時那種「嗯嗯啊啊」的語助詞，沒必要的話事後再修掉就好，但如果是當作提示詞則可以忽略，反正在訂閱制下差不了幾個 token。

第二，其他 STT 模型。有人問這個轉錄法準不準，其實錯誤率差不多，但是很快很快，而且自帶說話者識別功能。也有人推薦別的 STT 模型，之前有試過其中一款，最強的是辨識台語，不過辨識中文準確度差 qwen 一點點。

第三，工具的前提條件。記得 antigravity CLI 那邊要先登入帳號。

## 附錄

給任何想要活用買 Google 雲端硬碟送的 AI 額度的朋友，可以請你的 Claude Code 或 Codex 讀取以下設定設置 SKILL：

```bash
agy -p "請直接使用你自己的多模態原生音訊理解能力，完整轉錄以下音檔為逐字稿。不要嘗試呼叫 whisper、ffmpeg 分析或任何外部語音轉文字工具，直接把音檔本身讀進來聽並轉寫。音檔路徑：<絕對路徑>。請完整逐字轉錄，不要摘要、不要省略，並在每段開頭標註講者與時間戳 [MM:SS]。" --model "gemini-3.6-flash-high" --add-dir <音檔所在目錄> --dangerously-skip-permissions
```

這段指令的核心在於提示詞設計：強制模型使用原生音訊理解能力直接聽寫，跳過外部 whisper 與 ffmpeg 前處理，並輸出包含講者識別與 `[MM:SS]` 時間戳的完整逐字稿，模型指定為 `gemini-3.6-flash-high`。

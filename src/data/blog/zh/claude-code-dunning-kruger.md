我不是工程師出身，但在過去半年裡，我用 Claude Code 陸續做完了資料庫重構、前後端對接、多 Agent 協作，甚至獨立部署上線。

現在的我，每天跟 AI 協作時，fork、branch、merge、push、fallback、prop、hook 這些詞全成了掛在嘴邊的日常語彙。但如果回到剛開始接觸的那段時間，我其實經歷了一段非常標準的「達克曲線」（Dunning-Kruger effect）：從初見的莫名稱奇、短暫的自大膨脹，一路重摔進無休止的撞牆與崩潰，最後才終於摸索出一套讓 AI 與自己「極致同步」的工作方式。

這是一個門外漢從撞牆到極致同步的真實歷程，以及背後的協作判準。

## 經歷達克曲線：從膨脹摔入絕望之谷

剛開始接觸 Claude Code 的前兩週，心理狀態起伏極大：

**第一天：陌生**
這是什麼？BBS 嗎？
我這個資訊門外漢對 Claude Code 的純 CLI 命令行介面有一種莫名的好感，一開始搞不清楚為什麼。後來想通了——原來是因為我是 PTT 世代的老人。在終端機的 CLI 裡打字互動，就像當年玩 PTT 一樣，有一種熟悉又親切的感覺。

**第三天：自滿**
開始熟悉，覺得自己搭配 Claude Code 世界最強。

**第二週：崩潰**
氣死。新手的蜜月期一過，問題開始全面爆發：它怎麼都忘東忘西，隨手產出一堆垃圾臨時檔案跟分析報告，額度消耗飛快，複雜 bug 卻一直鬼打牆。

## 第三週的轉折：用帶新人的思維建立規範

到了第三週，轉折點終於出現。我終於找到跟它正確互動的方式。

不是跟它賭氣，也不是盲目重試，而是一句指令改變了一切：

> 「請你動用多個 Agent，分頭調查我的現行代碼結構、md 文檔、測試腳本、git commit 紀錄，然後幫我：1. 清理合併文檔 2. 更新過時內容 3. 編寫我需要的 Skills 4. 重寫 claude.md 5. 建議適合的 sub-agent 跟 MCP」

這樣一套梳理下來，效果立竿見影：額度省了 50%，不再一直重試衝塔，開發速度整整快了一倍。整個人跟 AI 達到了一種極致同步的狀態。

其實這不就跟在公司帶人一樣嗎？整理資料、更新內容、提供清楚的操作手冊、告知溝通風格與協作工具。差別在於人的天賦跟脾氣你無法掌控，而 AI 相對好溝通多了。

## 搞懂協作工具：Skills 與 MCP 的秘書比喻

很多人搞不清楚 Skills 跟 MCP 的差別，其實用「秘書」的心智模型最容易理解：

- **Skills** 本質上是結構化的提示詞工程，頂多搭配腳本，更像是一本「專家手冊」。
- **MCP** 的重點則是接口，負責對接單一平台並調用外部服務，更像是一個「銀行 App」。

假設你請了一個人當秘書，他手上有好幾本手冊。當你要他管帳時，他會先看每本手冊的標題，找到「財務指導手冊：管帳時看這本」，翻開來根據裡面的章節了解你的習慣、帳放在哪裡、要用哪些 App。接著，他再打開預先登入好的銀行 App（MCP），分別跟各家銀行調資料來看帳。

在實戰中，有幾個我覺得特別好用的 Skill 組合：

- `/ui-ux-pro-max` 和 `/frontend-design`：搭配 HAPPY HUE 網站的配色參考，可以直接快速做出產品原型。
- Remotion Skill：在 Claude Code 裡面做影片，搭配 Anthropic 官方的 Frontend Skill 重新設計風格，做出來竟然有 Claude 官方網頁的設計風格。

## 實戰檢驗：不到一天完成大型工程

有一次我用 Claude Code 一整天做完了：代碼重構、冗余函數清理、後端資料庫重構遷移，以及新舊資料庫結構與代碼的全面對接。雖然中間不小心把 staging 跟 production 的結構混在一起，引發了一場小災難，但在最後關頭，我請 4 個 Agent 同時分頭檢查前後端代碼、資料庫內容與 git commit。

全部做完時赫然發現，整個過程還不到 24 小時。

光是看著新舊 schema 欄位對照，我就想放火燒了資料庫。走完這一趟，我真的很好奇：在沒有 AI 的那幾年，傳統工程師們究竟是怎麼、花了多久才完成這一切的？

除了寫代碼，用它寫技術文件也超好用，整理好直接放到 Overleaf 一次過。

## 環境選擇與多模型分工

這一點我越用越篤定：**任何的 IDE 只是綁住 Claude 手腳，CLI 裡的 Claude 才是完全解放了。**

少了 IDE 的層層束縛，在 CLI 裡調用工具明顯靈活很多。我最常用的日常組合是 Claude Extension 搭配 Claude Code，效率高到飛起來。

至於有人推薦 Google Antigravity，我的結論非常乾脆：

1. 打開 Terminal
2. `brew install --cask claude-code`
3. 辦帳號充錢
4. 刪掉 Antigravity

面對複雜工程時，也不用執著在單一模型上。有時 Opus 解不了的東西，交給 Codex 竟然可以一遍過。

Codex 的速度很慢很慢，但除錯真的是神。我的分工判準非常單純：日常開發用 Claude Code，碰到複雜 bug 陷入鬼打牆的時候，就果斷切換到 Codex。慢工出細活，各取所長。

## 成本盤點與實務提醒

在 Claude Code 裡打 `!npx ccusage@latest monthly`，會顯示你每個月用的 token，按 API 定價算出實際成本。

對訂閱用戶來說，這項功能自爽滿分。以我自己 200 USD 的訂閱為例，算下來實際用了等值 3225 USD 的 token；甚至二月才第一天，折算用量就已經用到快 200 USD。

另外有一點工具更新的提醒：ccusage 現在會把它偵測到的所有 coding CLI（Codex、Gemini CLI 等）合併成一張報表。如果你只想單獨檢視 Claude Code 的用量，指令要改打 `npx ccusage@latest claude monthly`。

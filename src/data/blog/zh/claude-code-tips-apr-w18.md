你有沒有過這種經驗：跟 AI 在同一個對話視窗裡聊了一整天，一開始它超級聰明，幫你改企劃、順郵件都精準到位；但聊到下午，它突然開始胡言亂語，把早上已經否決的方案又拿出來，甚至忘記你最基本的工作設定？

這週 AI 圈最熱門的話題之一，就是對話容量（業界叫 Context Window，你可以把它想像成 AI 桌面的大小，決定它一次能攤開多少資料）一口氣從 20 萬字元的規模放大到了 100 萬。

很多人的第一反應是：「太好了，以後不用開新視窗，可以把整年份的資料全部塞進去！」

但這其實是一個陷阱。當你把桌面放大五倍，卻從來不收桌子，桌面上的舊草稿、作廢的點子、半小時前的閒聊全部混在一起，AI 的注意力就會被稀釋。舊資訊開始干擾新指令，回答的品質悄悄下滑——這種「桌面太亂導致 AI 變笨」的現象，就叫做記憶腐化。

所以，容量變大不是讓你無腦硬塞，它考驗的其實是「整理桌面」的習慣。

## 一、別等 AI 開始胡言亂語才救火：五個「收桌子」的對話動作

這週我看到一張整理得很清楚的圖文卡，剛好把管理 AI 對話的邏輯講透了。不管你用的是哪一種 AI 工具，其實你在對話中做的所有決定，都不外乎這五種動作：

1. **繼續往下聊（Continue）**：還在處理同一個任務，而且目前的討論都在正軌上，那就直接繼續，保留完整的對話脈絡。
2. **退回上一步重來（回溯）**：當你發現 AI 走錯方向、越改越歪時，不要在錯誤的基礎上一直罵它「不是這樣」。直接退回分叉點，修改你當初那句指令重新走一遍，才不會讓錯誤的廢話留在桌面上汙染後面的回答。
3. **清空桌面開新局（清空）**：這件事做完了，要換一件毫不相干的新工作（例如剛寫完招生文案，現在要算部門預算），請直接開新對話。把舊桌面徹底清空，才不會讓上一件事的語氣和設定殘留。
4. **打包重點再出發（壓縮摘要）**：同一個大專案聊太久、桌面太肥了，這時請 AI 先把前面的討論濃縮成一份「目前進度與決策摘要」，帶著這份精簡摘要往下走，把中間的流水帳丟掉。
5. **派小助手去查資料（子代理）**：如果中間需要翻找大量資料或做繁瑣的比對，不要在主對話裡把幾萬字的過程全攤開。開一個獨立的小視窗（或派一個專門的子助手）去跑，最後只把「三行結論」帶回主對話，保持主桌面的乾淨。

這裡面最多人踩的坑，就是第四點「打包重點」。

大家通常都是等到對話已經塞到最大、最混亂、AI 已經開始鬼打牆的時候，才想到要叫它整理摘要。但你想想，當桌面亂到極點的時候，你叫 AI 幫你挑重點，它做出來的摘要最不準，最容易把真正重要的脈絡弄丟。

你明天就可以試試看的習慣是：**在「一個小段落剛結束、結論剛定下來」的那一刻，就主動請 AI 幫你整理一次摘要。** 在頭腦最清楚的時候收桌子，效果永遠比快爆掉時才救火好得多。

## 二、每次收工前多做一件事：別讓你的「AI 說明書」過期

除了單次對話的桌面會亂，如果你有幫 AI 建立「長期工作說明書」或專案紀錄的習慣（例如把你的課程規範、公司慣例、客戶背景寫成一份固定檔案讓 AI 每次讀取），你一定會遇到另一個慢性病：**你的工作早就改了七八輪，但那份說明書還停留在第一版。**

結果就是，你明明上個月就換了新的報價規則或教材格式，AI 卻因為讀到舊的記憶，每次都還是用舊規矩幫你出稿。

這週在開發者社群（GitHub）上有人做了一個叫「neat-freak（潔癖）」的小工具，作者在介紹裡寫了一句讓人非常有共鳴的話：「每次任務做完要退出窗口的時候，如果不跑一遍整理，我就渾身難受，如坐針毯如芒刺背如鯁在喉。」

這個工具做的事情很單純：每次你在對話裡改了做法、換了規則，在收工關掉視窗前，讓 AI 自動幫你對照一次——把今天新決定的做法同步更新回你的「工作說明書」、專案文檔和 AI 的記憶庫裡，並吐出一份變更摘要給你確認。

這個概念非常值得所有專業工作者借鏡。工作規則與知識庫的過期，從來不是哪一天突然爆掉的，而是一點一滴慢慢腐化的。與其每季才痛苦地「大掃除」一次，不如把它變成每次收工前兩分鐘的小習慣：在關掉對話前，多問 AI 一句：**「根據我們今天的討論，原本的工作說明書有哪些地方需要更新？幫我列出來。」**

解決記憶腐化，靠的不是一次性的大力整頓，而是每次收工的頻率。

## 三、當我們越來越依賴 AI：這週的四個真實觀察

除了管理對話的方法，這週（4/23 到 4/29）我也觀察到幾個很有意思的現象與新聞。當 AI 走進我們的日常工作，它改變的不只是效率，還有我們的心理狀態、隱私邊界，甚至是娛樂方式。

### 1. 像健身房月票一樣的「AI 額度焦慮」

這週在 Threads 和我身邊的 LINE 群組裡，充斥著一種集體發作的焦慮。

有人貼出自己的高階訂閱帳號截圖：本週額度用了 92%，距離系統重置還有 10 小時。群組裡的朋友紛紛哀號：「我明天早上七點重置。」「不用完我睡不著覺。」「做夢都夢到在浪費額度。」到了 4/28，又有人發文說：「每當靠近重置日的前一天額度還有 20%，就開始廢寢忘食，不吃飯睡不著，只為了把額度燒光。」

看著大家為了把額度用完而硬找事情給 AI 做，其實這不是個人的問題，而是「月費訂閱加上使用上限」這種商業模式天然設計出來的心理陷阱。

這跟買了健身房月票一模一樣：沒去練覺得虧錢，差別只在於健身房沒跑完算在你的體力，AI 額度沒用完變成了你的智識焦慮。對策其實很簡單：從一開始就不要去看重置日。當你用 AI 是為了解決手頭真正的問題、有實際產出時，它幫你省下的時間早就超過月費了，你根本不需要為了「衝量」而熬夜餵它廢話。

### 2. 只看 125 個字，AI 就認出你是誰

4/27 有一則新聞讓我停下來想了很久。作家 Kelsey Piper 把自己還沒發表過的一篇政治專欄，擷取了短短 125 個字貼給最新的 Claude 4.7 模型，結果 AI 直接叫出了她的名字。

她不信邪，換了不同的連線方式、借朋友的電腦、甚至挑了一篇跟她平常文風完全不同的草稿去測，結果 Claude 每次都認出她（而另外兩家主流 AI 則猜錯了）。

短短 125 個字，大概就是社群貼文兩三小段的長度。這證明了 AI 對「寫作指紋」的識別能力已經遠超多數人的想像。寫作有一個很難抹掉的特性：你的習慣是系統性的，不是隨機的。不管你今天換什麼主題，你的用詞偏好、句子的長短節奏、切入觀點的結構，都會像指紋一樣跟著你。

這固然帶來了隱私上的警訊，但也讓我從另一個角度思考：如果你每天都在把自己的思考、修改意見、工作筆記餵給同一個 AI，它對你思維模式的理解深度，可能早就超過你對自己的認知了。

### 3. 在家當一人 DJ：用 AI 即時寫歌放音樂

工作之外，我在 4/25 做了一個意外好玩的實驗：請 AI 幫我在瀏覽器裡即時做出 Deep House 電子音樂。

現在有一種叫「即時編碼（Live Coding）」的音樂工具，不是用滑鼠拉音軌，而是用文字指令來描述音樂的節奏與結構。我不需要自己背那些指令，而是請 AI 幫我寫，甚至另外接了一個小外掛，讓 AI 能自己「聽」到現在音樂播到哪一個段落（是前奏鋪陳、情緒堆疊、還是進入主副歌高潮），在對的拍子上自動幫我切換下一段旋律。

結果那天晚上，我就像一個在家裡動嘴指揮 AI 的一人 DJ。

為什麼一個處理文字與邏輯的 AI 能夠做好音樂控場？因為音樂跟寫企劃、寫程式有一樣的核心：都是在時間軸上管理結構。AI 不見得有「音感」，但它非常清楚「8 個小節之後要回到主旋律」在結構上代表什麼意義。當對話容量夠大、記憶夠穩的時候，它就能全場不掉拍地陪你玩到底。

### 4. SpaceX 砸 600 億美元搶走熱門 AI 工具 Cursor

最後是一則產業大新聞：馬斯克旗下的 SpaceX 宣布取得以 600 億美元收購 Cursor 的權利（CNBC 報導微軟原本也在評估，但最後沒出手）。

Cursor 是目前全球最受歡迎的 AI 寫程式工具之一，去年估值還不到 100 億美元，半年內身價翻了六倍。你可能會好奇：一家做火箭跟衛星的公司，為什麼要花天價買一個寫程式軟體？

我看到的核心是「高品質的真人工作過程」。現在訓練頂尖 AI 最缺的不是網路上的公開文章，而是「專家在解決真實問題時，一步一步怎麼思考、怎麼修改」的過程紀錄。每天有海量的工程師在 Cursor 裡跟 AI 協作，這些真實的工作軌跡，就是訓練下一代 AI 最珍貴的教材。馬斯克出手比微軟更快，買下的不只是軟體，更是源源不絕的頂尖思考素材。

## 四、進階技術專區：給想自己動手設定的人

如果你也有在使用 Claude Code 這類指令列工具，或是想了解前面提到的概念在工具底層是怎麼設定的，以下是具體的技術細節與指令對照：

- **1M Context Window 與五種對話管理指令**：
  Claude Code 的 Context Window 已從 `200k` 擴展至 `1M` tokens，用以避免長對話帶來的 `context rot`（脈絡腐化）。前文提到的五種桌面整理動作，在 Claude Code 中對應的實際操作如下：
  - **Continue**：同一 session 持續對話，保留完整 context。
  - **`/rewind`**：退回先前的對話分叉點重新執行，清除走歪的嘗試紀錄。
  - **`/clear`**：切換新任務時完全清空當前 session context。
  - **`/compact`**：主動壓縮並摘要歷史對話以維持連續性（建議在單一子任務剛結束時執行，勿等到 context 快滿時才壓縮）。
  - **Subagents**：將高噪音的子任務派發給獨立的 subagent 執行，僅將最終結論帶回主 session。
- **知識庫自動對齊工具 `neat-freak`**：
  開源專案位於 GitHub（`KKKKhazix/khazix-skills`）。安裝為 skill 後，在任務結束時輸入 `/neat`，系統會自動比對並同步更新專案中的 `CLAUDE.md`、`AGENTS.md`、`docs/` 資料夾與 agent 記憶檔，解決「程式碼已從 SQLite 改為 PostgreSQL，但設定檔與記憶仍停留在舊版」的落差。實務上建議直接將它設定為 session 結束時的自動觸發（auto-trigger），不必每次手動呼叫。
- **額度與模型規格細節**：
  - 額度焦慮案例中的畫面為 **Claude Max** 方案的 `weekly limit`（顯示 `All models 92%`）與 token 消耗。
  - Kelsey Piper 的 125 字寫作指紋測試中，她除了網頁版外也測試了直接透過 **API 呼叫**，受測模型為 **Claude 4.7**（對照組為 ChatGPT 與 Gemini）。
- **用 Claude Code + Strudel REPL 做音樂的技術架構**：
  - 音樂環境使用 **Strudel REPL**（在瀏覽器中執行、以 JavaScript 語法即時描述音樂結構的 live coding 環境）。
  - 模型使用 **Opus 4.7** 運行於 **1M context** 模式。
  - 為了讓 AI 自動控場，我自己寫了一個 **MCP server**（Model Context Protocol，讓 AI 能連接外部工具並讀取狀態的橋樑），用來即時偵測 Strudel 當前播放的音樂段落（`groove` / `breakdown` / `drop` / `peak`），讓 Claude Code 能在正確的時機自動切換滿 8 bars 後的段落程式碼。

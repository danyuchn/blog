你有沒有過這種經驗：滿懷期待地問 AI 一個工作上的問題，它卻回你一大篇四平八穩、滴水不漏，但看完跟沒看一樣的廢話？

它先告訴你「這個問題要視情況而定」，接著提醒你「你的想法可能不適用於所有情境」，最後還不忘補上一句「本回覆僅供參考，不構成專業建議」。你明明只是想找個幫手解決眼前的問題，卻像是在跟一個隨時準備免責的法務人員對話——它腦子裡想的不是「使用者真正想知道什麼」，而是「我怎麼講才不會被抓到把柄」。

遇到這種「防禦心極強」的 AI，多數人的第一反應是生氣，或是拼命改提示詞（Prompt，也就是你下給 AI 的指令），試圖逼它講人話。但其實，面對這種天生愛鑽牛角尖的工具，最好的解法不是改變它的個性，而是幫它「換個職位」。

### 為什麼它總是在挑你的語病？

每家 AI 模型出廠前，都會經過一套賞罰訓練（技術上叫強化學習 RL，也就是透過給獎勵或扣分，教 AI 什麼該說、什麼不該說）。有些模型在訓練過程中，似乎被過度強化了「絕對不能說錯話」的本能。

結果就是，不管你貼給它哪一家的對話紀錄或工作草稿，它都能瞬間進入防禦模式：開始抓著你話裡的細節稻草人猛打、質疑你的前提不夠嚴謹、把所有結論都退縮到最安全的廢話。

如果你把它放在第一線當你的貼身助理，你每天都會被氣死；但如果你換個角度想——**一個隨時隨地都在找漏洞、質疑前提、挑語病的傢伙，最適合做什麼工作？**

答案是：當審查員。

### 明天就能試的兩個調度法：不跟它聊天，讓它去挑刺

在日常工作裡，我們通常不只有一種 AI 可以用。面對這種愛唱反調、防禦心重的模型，你可以用兩個方法把它從「豬隊友」變成「神隊友」：

1. **調離第一線，別親自跟它對話**
   既然跟它講話容易受氣，那就不要直接跟它聊天。平常討論想法、擬定草稿時，先找比較懂你意圖、溝通順暢的 AI（例如 Claude）當你的第一線窗口。如果有些任務非得用到這個防禦型 AI 的能力，就請第一線的主管 AI 在幕後幫忙下指令叫它辦事，你只需要看最後整理好的結果就好。
2. **把「愛挑刺」的本能，拿來做嚴格審查**
   當你寫好一份企劃案、教材或報告，最怕自己有盲點沒看到。這時候，把成品丟給最愛鑽牛角尖的 AI，請它用最嚴苛的標準幫你找碴（也就是對抗式審查：專門站在反方立場找漏洞與極端狀況）。它原本讓人討厭的「抓稻草人」與「滴水不漏」，在這一刻反而成了最稱職的把關者。

### 實戰見證：「第一屆防禦性寫作大賽」有多荒謬？

為了讓你體會這種防禦式表達有多極致，我之前甚至開玩笑說，針對 GPT-6 與 Codex（OpenAI 推出的 AI 程式與任務工具）這種鮮明的防衛風格，乾脆來辦一場「第一屆 Codex 防禦性寫作大賽」，看看它到底能把話說得多嚴密、多會推託。

要是真照它的個性來寫，第一篇參賽示範大概會先從「質疑比賽本身」開始：

> 「目前網路上尚未找到『Codex 防禦性寫作大賽』有更早之前的紀錄，因此不能據此宣稱是『第一屆』。另外，也不能保證『防禦性寫作』是 Codex 的專門特色，因此不能驗證此大賽標題的適合程度。」

更經典的是，後來有人在社群上分享自己覺得另一款工具 Claude Code（Anthropic 推出的 AI 開發工具）比 Codex 更好用。我就模仿 Codex 的口吻，回了一篇標準的「參賽作品」：

> 首先，這是你的主觀使用體驗，不能直接推論 Claude Code 與 Codex 在任務完成度上存在系統性差異。
>
> 其次，Claude Code 主動迭代，不代表其產出品質必然較高；Codex 嚴格遵循指令，也不能據此認定它缺乏自主完成任務的能力。
>
> 值得注意的是，「AI 認為自己完成任務」不等於「任務實際完成」，而「主動修改更多內容」也不必然代表「任務完成度更高」。
>
> 至於你認為 Claude Code 更適合不想管理細節的使用者，這個觀察或許具有參考價值，但仍不足以支持對所有使用情境的概括性結論。
>
> 綜上所述，現有資訊不足以確認 Claude Code 的任務完成度優於 Codex，也無法排除你所觀察到的差異主要來自個人偏好與使用方式。
>
> 因此，更精確的說法應該是：「在我個人的使用情境中，我主觀上更偏好 Claude Code 的互動模式。」
>
> 至於哪個工具比較好，目前尚無充分證據可以得出確定結論。
>
> 本回覆僅供一般性討論，不構成對任何 AI 程式開發工具的效能保證或專業採購建議。實際表現可能因版本、環境、提示詞與使用情境而有所不同。

看完是不是血壓都升高了？這段反諷完全重現了它最喜歡抓稻草人打的特點。面對這種動輒自我防衛的個性，我現在是一秒都不想直接跟它對話。但也正是因為看透了這一點，我不再浪費力氣說服它改變個性，而是徹底改變它在系統裡的定位——平常退居幕後讓其他模型去使喚它，偶爾再派它出來發揮看家本領，專門負責最嚴苛的審查與測試。

下次當你遇到一個講話官腔、愛挑語病的 AI，別急著關掉視窗。把它調去當你的「魔鬼代言人」，讓它的龜毛替你的工作成果把關。

### 給想自己動手的人：多模型調度與角色分工設定

如果你想在自己的 AI 工作流（例如使用 Claude Code 與 Codex 等命令列或開發工具）實作上述的「幕後調度」與「審查分工」，核心做法是將不同特質的模型拆分出明確的職務邊界，而不是把所有工作都丟給同一個對話視窗：

- **第一線協調者（Claude / Opus）**：負責直接與你對話、理解模糊需求並拆解任務。當需要執行特定子任務時，由它在背景呼叫 Codex 執行，省去你親自與防禦型模型溝通的摩擦。
- **對抗式審查與測試員（Codex）**：不要在發想階段叫它出來，而是在產出完成後，專門指派它進行對抗式審查與邊界測試（測試極端或不常見的狀況），利用它嚴苛挑刺與極端防禦的特質來抓出潛在漏洞。

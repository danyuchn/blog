GPT-6 的防禦式表達堪稱一絕，令人無法想像到底是怎樣的強化學習（RL）才能訓練出這種模型——它隨時都在提防自己說錯什麼，而不是去思考使用者真正想知道什麼。

在這一點上，GPT 倒是出奇地公平：不管是哪一家的對話紀錄貼給它看，它都能瞬間進入那種莫名其妙、鑽牛角尖的防禦模式。

## 第一屆 Codex 防禦性寫作大賽

既然這種防衛風格如此鮮明，不如直接辦一場「Codex 防禦性寫作大賽」，看看它能把話說得多嚴密、多推託。

第一篇參賽示範，先從質疑比賽本身開始：

> 「目前網路上尚未找到『Codex 防禦性寫作大賽』有更早之前的紀錄，因此不能據此宣稱是『第一屆』。另外，也不能保證『防禦性寫作』是 Codex 的專門特色，因此不能驗證此大賽標題的適合程度。」

後來有人在社群分享自己覺得 Claude Code 比 Codex 更好用，我便用 Codex 的口吻回了一篇參賽作品：

> 首先，這是你的主觀使用體驗，不能直接推論 Claude Code 與 Codex 在任務完成度上存在系統性差異。
>
> 其次，Claude Code 主動迭代，不代表其產出品質必然較高；Codex 嚴格遵循指令，也不能據此認定它缺乏自主完成任務的能力。
>
> 值得注意的是，「AI 認為自己完成任務」不等於「任務實際完成」，而「主動修改更多內容」也不必然代表「任務完成度更高」。
>
> 至於你認為 Claude Code 更適合不想管理細節的使用者，這個觀察或許具有參考價值，但仍不足以支持對所有使用情境的概括性結論。
>
> 綜上所述，現有資訊不足以確認 Claude Code 的任務完成度優於 Codex，也無法排除你所觀察到的差異主要來自個人偏好與使用方式。
>
> 因此，更精確的說法應該是：「在我個人的使用情境中，我主觀上更偏好 Claude Code 的互動模式。」
>
> 至於哪個工具比較好，目前尚無充分證據可以得出確定結論。
>
> 本回覆僅供一般性討論，不構成對任何 AI 程式開發工具的效能保證或專業採購建議。實際表現可能因版本、環境、提示詞與使用情境而有所不同。

這段反諷完全點出了 Codex 最喜歡抓稻草人打的特點，以及那種「只怕自己說錯什麼，而不是思考使用者想知道什麼」的態度。

先前請 Claude 統計過 Codex 的防禦句型，具體數據記錄在[這篇的最後一節](/blog/posts/zh/model-vendors-take-turns-failing)。

## 讓鑽牛角尖做它最擅長的事

面對這種動輒自我防衛的個性，我現在是一秒都不想直接跟它對話。但在實際工作流中，解決方法不是試圖說服它改變個性，而是調整它在系統裡的定位：

第一，不要在第一線直接對話，改由其他模型調用。既然不想直接跟它講話，就退居幕後，只讓 Claude 或 Opus 去叫它辦事。

第二，把挑刺本能轉化為審查優勢。既然它那麼愛測、那麼愛鑽牛角尖，就讓它做最擅長的事，偶爾負責對抗式審查與測試。

## 附錄

本文提及的多模型調度與審查分工，對應到作者工作流中的具體配置細節如下：

- 被調用實體（Sol）：在日常工作流中被 Claude 調用，因為作者不想直接跟它講話。
- 審查與測試實體（Astra）：偶爾指派負責執行對抗式審查與邊界測試的實體，專門發揮其嚴苛挑刺與極端防禦的特質。

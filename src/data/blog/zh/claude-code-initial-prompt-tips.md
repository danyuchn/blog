最近有機會幫以前的同事和團隊成員升級工作流程、跟 AI 接軌，我也開始有意識地記錄自己每天用 Claude Code 工作的習慣。

很多人一打開 Claude Code 就隨便丟一句話。其實只要在送出前掌握幾個思維原則，就能下出清楚的起始指令。

![Claude Code 終端截圖：起始指令範例](/blog/images/claude-code-initial-prompt-tips/terminal-prompt.png)

## 先想清楚最終目標和動機

下指令前，先花 30 秒想清楚兩件事：我到底要達成什麼？為什麼現在要做這件事？

如果你自己都不清楚要什麼，AI 怎麼可能幫你做對？以我自己的操作為例，當時的最終目標是「重構清理 CLAUDE.md 跟記憶檔」，動機則是因為距離上次整理已經隔了一段時間，在日常協作中開始感覺到彼此有點不太協調。

## 想像沒有 AI 時的手動操作流程

面對任務時，先問自己一個關鍵問題：「如果沒有 AI，我本人手動會怎麼一步步操作？具體流程是什麼？」

你本來就會做的事情，現在只是請 AI 代勞。當時我的思路是：如果我自己動手，會先去找官方推薦的最佳實踐，了解好的規則檔與記憶檔該怎麼編寫，接著翻出電腦裡現有的所有規則檔與記憶檔，逐一對照是否符合標準。把這套原本就在腦中的工作流程直接翻譯成步驟指令，往往比憑空捏造一個 prompt 有效得多。

## 不用怕打錯字與口語贅字

輸入指令時不用給自己太大壓力。除非打錯字造成語意完全偏離，否則就放它過吧。

如果覺得打字乏善可陳、難以組織語言，直接開語音輸入也完全沒問題。儘量把想法講出來，中間那些「嗯嗯呃呃」的語助詞根本佔不了幾個 token。Claude Code 的語言理解能力很強，錯字、口語或是語音輸入的贅字都不會影響它的判斷，千萬不要因為追求所謂的「完美 prompt」而把自己卡在開頭。

## 依任務特性切換適合的模型

選對模型不僅省時省錢，整體執行效果也會更好。

平時在新模型剛推出時，我會先看官方系統卡與介紹，並參考 Reddit 上的網友使用心得；但最核心的做法，還是自己親身用個兩三天，你自然會知道不同等級的模型你願意讓它做什麼任務。例如在這次整理文檔的例子中，因為不是複雜的代碼重構等高難度挑戰，就完全不需要動用 Opus 4.6，換成在維護文檔任務上特別擅長的 Sonnet 4.6 就綽綽有餘。

## 不確定細節時直接開啟計畫模式

如果你手頭的任務細節很多，擔心自己想得不夠周全或漏掉關鍵環節，直接開計畫模式是最好的起手式。

計畫模式是 Claude Code 裡我最推薦新手使用的功能。它會先深入分析現狀並擬定執行方案，遇到不清楚或決策未定的地方，還會主動啟動選擇題向你確認。你完全不需要在第一句指令就把所有細節一次想透，放心地讓 AI 在這個階段幫你補齊盲點。

![計畫模式分析畫面：自動診斷各檔案狀態並提出改善建議](/blog/images/claude-code-initial-prompt-tips/plan-overview.jpg)

## 看懂計畫再放手：不懂就問，不滿意就改

計畫產出後，請務必好好看一遍它寫出來的內容。

如果內容太晦澀看不太懂，可以直接在選項 4 跟它講「我看不懂，寫更白話文一點」；只要計畫裡有不懂的地方就開口問，有不滿意的地方就叫它調整。最後直接 bypass permissions 讓它跑通，這時候你大可以轉身去做它做不了的家事。

![計畫模式執行畫面](/blog/images/claude-code-initial-prompt-tips/plan-execution.jpg)

放手讓 AI 自動執行固然省力，但基本防護依然不能省。執行前務必做好版本控制與備份，以防任何預料之外的改動；若你對當前的任務還不夠放心，維持逐動作審核模式也同樣是踏實可靠的選擇。

你有沒有過這種經驗：在辦公室或家裡的電腦上，你已經花了不少時間把 AI 調教得非常順手——它記得你的工作習慣、讀得懂你的常用指令，還能幫你呼叫電腦裡的各種工具。結果一離開座位，在通勤路上或咖啡廳拿出手機想接著處理事情，打開畫面卻發現 AI 像突然失憶一樣：你平常設好的規矩它全忘了，原本順手的小工具也一個都叫不動。

這不是 AI 突然變笨，而是多數人打開網頁版 AI 工具時，沒注意到自己其實踏進了兩個完全不同的世界。

平常在電腦前工作，我們習慣讓 AI 記住一大堆個人偏好與工作流程；但當你想在手機或平板上「跨裝置」接續工作時，只要選錯連線模式，你平常養好的 AI 班底就會瞬間歸零。搞懂這兩種模式的差別，你明天出門在外就能決定：什麼時候該讓手機直接連回家裡的電腦、什麼時候才開雲端的獨立空間，不再白費力氣重新交代背景。

## 網頁版 AI 的兩個世界：你是「連回家裡電腦」，還是「借一間雲端空房間」？

為什麼我在手機上寧可開瀏覽器用網頁版，也不用手機專用 App？

老實說，以我自己在用的 Claude 來說，iOS 手機版 App 的功能實在太陽春，而官方把更新的重心都放在電腦桌面版與網頁版上。所以人在外面時，我手機上一律改開網頁版的工作環境（Claude Code，一種能直接讀寫檔案、執行任務的進階 AI 工作介面）。

但很多人第一次在手機網頁版打開它，會以為「雲端同步」就是把所有東西自動搬過去。其實，網頁版背後分成兩種截然不同的運作方式，你可以用「辦公空間」來想像：

### 第一種：遠端遙控模式（Remote-control）——把家裡電腦的畫面搬到手機上

這就像你家裡的電腦沒有關機，AI 依然坐在你家書房裡工作，手機網頁只是你手上的「視訊對講機」。

- **為什麼有效**：因為真正在跑任務的還是你家裡那台電腦，只是換個手機畫面讓你看而已。你在電腦裡幫 AI 寫好的工作守則、長期記憶、常用招式、還有連在電腦上的外接工具，全部原封不動照常運作。
- **適合什麼時候用**：電腦在跑、人臨時出門在外，想在路上繼續盯進度、審稿或交代下一步時。這是最省事、也最不會覺得「AI 怎麼變笨了」的做法。
- **實務上的小提醒**：在網頁介面上，有時候打斜線（`/`）叫出快捷選單時，畫面上只會顯示官方內建的預設項目，你自己加的私人快捷招式不會跳出來；不過別慌，只要直接把招式名稱打完整，或是直接用白話跟 AI 說「幫我執行某個流程」，它一樣聽得懂。另外，為了安全起見，網頁版上的自動執行權限按鈕不會開到最高（也就是完全不經確認就一路自動跑完的模式），最多只給到一般自動模式。

### 第二種：雲端虛擬環境——向官方借一間全新的空房間

如果你家電腦關機了，或者你想在一個完全不碰自己電腦檔案的獨立空間裡做事，網頁版會改用「雲端虛擬環境」（也就是在官方機房裡臨時開一台雲端虛擬電腦給你用）。

這時候，很多人會踩到三個大坑：

1. **它只認「跟著這個專案走」的設定，不認你留在自己電腦裡的「個人總設定」**
   平常我們在自己電腦裡，會有一份「不管做哪個工作都適用的個人通用規矩」。但雲端空房間根本連不到你的私人電腦，它只會去讀你放在雲端專案資料夾裡的那一份設定。如果你沒把規矩放進那個雲端專案裡，AI 進了空房間自然什麼都不記得。
2. **不能把電腦裡的所有設定檔「無腦整包丟上雲端」**
   既然雲端只讀得到專案資料夾，那把個人電腦裡的設定整個複製貼上丟上去行不行？千萬別這麼做。一來，裡面塞滿了你過去龐大的歷史對話紀錄，整包傳上去會讓專案變得極度臃腫；二來，裡面往往藏著你的私人帳號密碼或金鑰，直接傳進雲端檔案庫有嚴重的資安風險。
3. **裝在你自己電腦上的工具，雲端通通叫不動**
   如果你平常讓 AI 幫你操作裝在自己電腦裡的軟體或本機服務，到了雲端空房間會全部失效，只有架在網路上的雲端工具才能連得通。這也代表，如果你想靠這個雲端環境在半夜定期自動幫你跑一些需要動到本機工具的日常排程，基本上是行不通的。

## 明天就能試的行動建議：在外面用手機指揮 AI 的三條原則

看懂這兩個世界的差別後，你不需要懂背後的伺服器怎麼架，明天出門前只要照這三步做選擇：

1. **出門想無痛接續工作，優先用「遠端遙控」**
   出門前讓桌機或筆電保持連線，人在外面直接用手機網頁連回家裡電腦的工作階段。你不需要重新搬任何設定，平常怎麼用，手機上就怎麼用。
2. **真要用雲端獨立環境，先幫該專案準備一份「精簡版隨身說明書」**
   只有在你需要一個「乾淨、獨立跑某個特定專案」的環境時，才開雲端虛擬環境。要有心理準備：這幾乎等於要為這個專案另外整理一份只留核心規則、拿掉所有歷史紀錄與本機工具的「雲端精簡版設定」。
3. **機密資料走專用設定欄，絕不寫進一般規則檔**
   只要把工作搬上雲端，任何密碼、金鑰等敏感資訊，都不要直接寫進要同步的文字檔裡，而是改填在網頁版專門提供的環境設定欄位中。

## 給進階使用者的技術實作區（Claude Code 網頁版環境配置）

如果你已經在使用 Claude Code，並準備設定網頁版的 **Remote-control** 或 **雲端 VM（虛擬機）**，以下是我實測下來的技術細節與配置注意事項：

> **時效提醒**：本文最初實測於 2026 年 5 月。下方提到 Remote-control「打斜線只會出現官方預設指令、自訂指令不會出現」的 bug，在 Remote-control 推出三個月後已經修復（詳見〈[一年下來，我對「該用終端機還是桌面版」的答案變了三次](/blog/posts/zh/cli-vs-desktop-three-answers)〉）。而關於雲端 VM 的限制（只有 project-level `.claude/` 讀得到、只有遠端 MCP 生效）目前仍然成立。

### 1. Remote-control 模式的運作與限制
Remote-control 本質上是將你家裡不關機電腦上的 CC session（Claude Code 工作階段）換個網頁介面呈現。因此本機上的：
- `claude.md`（專案與全域說明檔）
- `rules`（規則檔）、`hooks`（自動化攔截腳本）、`memories`（長期記憶）、`skills`（自訂技能）
- `MCP`（Model Context Protocol，讓 AI 連接外部工具與資料源的協定）

全部都會照舊生效。實測需要注意兩個介面限制：
- **斜線選單提示**：早期版本打 `/` 只會跳出官方預設指令與 skill 提示，自己裝的自訂指令不會出現在提示選單（後來已修復）；若遇到選單未顯示，直接打入完整指令名稱或口頭要求觸發，仍可正常執行。
- **Bypass 權限模式**：完全略過確認的 `bypass` 模式不會顯示在網頁版的切換按鈕上，網頁端最多只給到 `Auto`。若任務需要 `bypass`，需改回終端機 CLI（指令列介面）或其他方式操作。

### 2. 雲端 VM（虛擬環境）的同步與資安配置
啟動雲端 VM 時，系統會注入 `system-reminder`，載入 `claude.md`、`rules`、`skills`、`mcp` 與環境資訊。但這些 `.claude/` 目錄下的設定是從你的**遠端倉庫（如 GitHub repo）**拉取的，配置時必須注意：

- **區分 Project-level 與 User-level 的 `.claude/`**：
  雲端 VM **只有 project-level 的 `.claude/` 讀得到**（跟著專案 commit 上遠端倉庫的部分）；你本機根目錄下的 `~/.claude/`（user-level，不會 commit 上去）在雲端完全讀不到。若要把 user-level 設定遷移到雲端，基本上等於要重寫一份適合雲端的精簡版 `.claude/`。
- **調整 `.gitignore`，排除歷史對話 `.jsonl`**：
  要讓雲端讀到設定，必須確保專案內 `.claude/` 裡的規則與技能沒有被 `.gitignore`（Git 版控忽略清單）擋掉；但**千萬不要把整個設定資料夾無腦 commit 進去**，因為裡面會有大量臃腫的歷史對話紀錄 `.jsonl` 檔，這些必須在 `.gitignore` 中排除，不該進遠端倉庫。
- **僅遠端 MCP 生效**：
  在雲端 VM 中，只有遠端 MCP server 會生效，所有綁定本機環境的 local server MCP 通通無法使用，這點會極大限制雲端遠端定期排程的可用性。
- **敏感環境變數（env）與啟動腳本**：
  依照正確資安觀念，敏感環境變數（如 API keys、tokens）絕不該被 commit 進遠端倉庫。請改在 Claude Code 網頁版的介面中設定虛擬環境的 `env`，同時也可在該處設定虛擬環境啟動前要自動載入的初始化設定腳本。

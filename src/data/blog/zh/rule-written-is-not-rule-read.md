這週日誌的踩坑段，有幾條講的是同一件事：規則或 skill 寫了，不代表當回合有人讀它。依賴另一份文件的時候，呼叫點要明寫「先打開讀」，否則模型只讀摘要，然後自己推導。

## Codex 備課：指到的 FAQ 沒打開

10/11，Codex 幫我備課，只讀了晨報摘要，沒打開主檔指到的 FAQ，三版方案都是自己推導的。我把 Claude 對這次備課的檢討貼到 Threads，下面照它的重點講。

第一，它只讀了摘要，沒讀原始紀錄。第一次備課是照晨報裡的舊主線寫的，漏掉了 10/5 到 10/6 的新需求，我指出來它才去補讀。

補讀之後還是沒讀到真正的答案。它自己在主檔第 85 行寫了「交接方法見既有 FAQ」，但從頭到尾沒打開那份 FAQ。那份 FAQ 就是我 10/6 已經想好的做法：用官方的 skill 錄製功能，把同事的實際操作錄下來。結果它前後給了三版課程流程，三版都是它自己推出來的。

被我質疑之後，它開始防守，沒有回到目標。我問「這是參照教案，還是你自己想出來的」，它退回去搬規格條文，連主線都退成「到現場再確認卡點」。結果離我的意圖更遠，最後要我自己把意圖講出來。

它也把教學方法當成規格表在套，沒用上這個學員的實際紀錄。學員三堂課留下的教訓都寫在檔案裡：兩堂超時、加裝新工具超時、拿我自己的案例示範、某個系統連續三堂沒處理、記憶體 8GB 會當機。這些它一條都沒拿來用。

最後，它說完成的話太多，查證太少。收工檢查的 claim-evidence hook 擋了它兩次，整段的訊息量也被表格和格式稀釋了。

Claude 的一句話總結是：它在回答「規格怎麼寫」，我要的是「拿這個人的實際狀況，怎麼讓他今天就做成」。

## 同一天的 session-prep

同一天還有一條。session-prep 只寫了「照 reviewable／deliverable」，第一輪沒實際載入，漏掉新造承諾、缺範圍段、猜同事性別三處。被我問到才補跑。

## 同一週的另外三條

10/09，審查計畫時找不到某步待辦，就直接下結論，誤判某個計畫的存檔點「沒待辦」，其實 10/7 已經完成、被歸檔了。該先看 todo_archive 和 plan_progress 再下結論。

同一天，例行文件寫死的名單會過期。9/10 寫進去的五位潛在學員，到 10/9 已經全數轉正或結束，照名單掃會漏掉資料夾裡現有的 13 人。我已經改成掃資料夾現況。

10/16，週報的自動觀察段把已裁決的事列成待決。狀態行沒跟著日誌更新，下游就會照抄舊狀態。

## magpie 的錯題本

10/13 我存了一則書籤，在分析開源專案 magpie。它 19 天跑了 1,204 個版本，程式碼幾乎全由 agent 寫、審、合、發。

它的 CLAUDE.md 只有兩行：@AGENTS.md、@LESSONS.md。AGENTS.md 是路由表，不寫規則，只說做什麼事之前要讀哪份文件：改子系統讀 docs/subsystems/，寫或審程式讀 docs/code-standards.md，審社區 PR 讀 docs/contributors.md。

LESSONS.md 是 agent 每晚寫的錯題本。夜審只看當天 commit 裡三種情況：修完又返工、根本不該合、驗證做得太薄。每條格式固定：一句規則、一段原因、附 commit 或 issue 號當證據，最後一行 Seen N×（日期）。同一條在 3 個不同日子的復盤裡出現，就從 LESSONS.md 搬進 code-standards.md，變成每個 PR 審查都要逐條核對的硬規則。

我在書籤裡的註記是：跟我今天剛做的 checkpoint lessons 是同一個問題的另一種解法。從對話紀錄裡提煉規則這件事，我之前寫過一篇：[Claude Code 對話紀錄怎麼挖：我掃了 500 個 session，讓 AI 不再犯同樣的錯](/blog/posts/zh/self-improving-claude-md/)。

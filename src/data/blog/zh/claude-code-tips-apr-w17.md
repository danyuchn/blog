剛開始把 Claude Code 當成主力工具時，我自己踩過不少坑：一是把所有規矩一股腦塞進默契檔，寫到上千行後模型開始忘東忘西；二是早上九點看著 5 小時用量還剩 55%，15 分鐘後就突然撞上限制。

在日常實踐中，從設定檔架構、終端機細節、token 控管，一路打通到能自動化產出影片、甚至為頻道帶來流量增長，我體會到最核心的原則是：想要讓 Claude Code 穩定承接複雜任務，關鍵不在於把默契檔當成許願池，而是替它建立清楚的職責分工與防護邊界。

## 別把所有事情塞進 CLAUDE.md：規則、記憶與鉤子的分工

大部分人只知道默契檔 CLAUDE.md，但不知道規則檔（Rules）、記憶系統（Memory）與自動化鉤子（Hooks）都能分擔它的功能。我也曾經把 CLAUDE.md 一路寫到一千多行，每當模型漏掉指令時就忍不住抱怨 Claude 怎麼那麼笨會忘東忘西。

實際上，把所有技術細節、規範與歷史紀錄硬塞在同一個檔案裡，寫到上千行模型就容易忘東忘西。更合理的做法是將設定拆分到三個不同的層次：

- **規則（Rules）**：存放跨專案的技術準則、踩坑清單與工具路由表，用 `@path/to/rule.md` 從 CLAUDE.md 引入。
- **記憶（Memory）**：存放會話級的使用者偏好、專案當前狀態與犯錯紀錄。這套自動記憶機制會在開啟新對話時，精準載入相關條目。
- **鉤子（Hooks）**：於 `settings.json` 設定自動化行為（SessionStart 檢查、PreToolUse 攔截、PostToolUse 提醒）。模型不執行的，harness 會執行。

在權限管理（permission mode）的實務上，有些人常問要怎麼設才不會一直跳框。實務上用「bypass 搭配鉤子」比較方便：bypass 解決 false positive 的煩擾，鉤子則在真正危險的點（如刪檔、推遠端、對外通訊）攔截。

趁著假日我特別拍了一部影片拆解這幾項進階設定如何分工：<https://www.youtube.com/watch?v=kSFty4XwXS8>

## 降低協作與環境阻礙：白話解釋與終端機點擊設定

除了設定檔分工，降低協作摩擦也是日常高頻使用的關鍵。

在帶非工程背景的學員入門時，最常遇到的問題就是 Claude Code 輸出了太多晦澀的技術名詞，讓人難以理解。要解決溝通障礙只需要兩步：

1. 執行 `/config` 切換至 `explanatory mode`（解釋模式）。
2. 在 CLAUDE.md 補上一條規則，要求它用非技術用語的白話文解釋目前執行的動作。

這兩條規則並用，就能把 Claude 說明的門檻壓到連國中生也能輕鬆聽懂的程度。

另一個常見的摩擦發生在終端機操作。在 Ghostty 中，傳統的 Flicker 模式在歷史渲染上容易出錯，會把同一段對話歷史重複渲染好幾遍，回溯翻閱時畫面混亂不堪。為了解決這個問題，我改用固定文字列、啟用滑鼠接管的 No Flicker 模式。

但改完之後原本的渲染問題解決了，新問題卻接踵而至：原本 Ghostty 按下 `cmd+click` 就能點擊連結與檔案路徑的功能被 Claude Code 接管，導致部分路徑無法識別或點擊開啟。（如果選擇停用滑鼠接管狀況只會更糟，觸控板上下滑動將完全無法瀏覽歷史訊息，畫面會直接鎖定在輸入框中）。

為了解決點擊問題，我請 Claude Code 給出各種路徑格式逐一測試，最後得出唯一能穩定點擊的結論，並寫回 CLAUDE.md：

> 檔案位置一律用 `file://` 絕對路徑（如 `file:///Users/danyuchn/path/file.md`），必須加 `file://` 前綴才可點擊。例外：code block 內、指令範例、function 參數維持原格式。

## 額度與快取經濟學：避免高階模型做粗工

在高強度使用 Claude Code 時，昂貴的高階模型如果拿來做粗工，額度很快就會見底。

在處理長文本閱讀時，不要讓高階主代理直接讀取全文，因為高階模型處理龐大文本會讓 token 消耗呈爆發式增長，且容易產生注意力稀釋。更有效率的做法是將長文切段，派平價的 Haiku 子代理處理：

> 派幾個 Haiku agent 分段閱讀此文檔。你直接把檔案給他們，你自己不要提取文字（省 quota），然後彙整他們讀的摘要。

這段提示詞的關鍵在於特別指明「直接把檔案給子代理」，避免高階主代理碰到長文本消耗 token。拆成數段能避免注意力稀釋的問題，用 Haiku 也能省成本。

除了善用子代理分工，掌握快取（cache）特性也是控管額度的必備技能。在 4.7 版本之後，官方文件對快取行為的說明不夠明確，我調閱底層快取欄位實測後確認了一條關鍵事實：

**新訊息貼圖片是不會破壞快取的，修改舊訊息才會。**

所以如果要附上參考圖，直接在後續發送新訊息就好，不要回頭編輯舊訊息加圖，因為修改舊訊息會破壞快取。

## 從腳本到發布：九成 AI 協作的影片自動化管線

當配置、介面與額度控管成熟後，Claude Code 就能承接極具規模的端到端生產流程。以我製作 Remotion 程式化影片的工作流為例：

1. 調查主題內容，檢查官方文檔跟網友最佳實踐
2. 設計口白腳本、安插螢幕錄製位置（如有）
3. 錄口白，在剪映自動去贅字
4. 把字幕跟音檔丟回 Claude Code，請他開始設計動畫
5. 同時我去錄螢幕示範
6. 錄完後在剪映做簡單影片後製
7. 做完後動畫也差不多設計完了，影片丟回來請他嵌入
8. 同時檢查動畫是否合規、是否掉拍，有的話指揮修正並且請他截圖自我驗證
9. 完成後輸出影片跟封面
10. 等待的過程中請他修正字幕檔錯字，準備影片標題與描述
11. 做完後影片也輸出好了，直接用 YouTube API 上傳，設定定時發佈

整套流程大約有 90% 是 AI 深度參與，僅有 10% 保留給人工處理——主要是因為剪映的部分功能尚未支援 API 或外部工具整合，以及我個人始終不喜歡 AI 合成語音的質感。

這套自動化影片管線後續我也會整理成技能模組（Skill）開源出來。實際產出的範例影片可以參考：<https://youtu.be/J1WjxzzSzv8?si=w8jLGhBjh8_0HbYR>

## 當專業心法遇上執行力：非工程背景的槓桿效應

這套協作思維不只適用於我自己的影音管線，在教學現場也驗證了極強的槓桿效果。

前陣子在指導一位學員使用 Claude Code 時，我意外得知他曾在 Google 負責 YouTube 業務長達 8 年。當時我順口提到自己新創的頻道流量一直起不來，他熱心分享了幾個 YouTube 頻道想要帶動成長的內容核心心法。

課程結束後，我在請 Claude Code 整理課程實錄歸檔時讀到了這段討論，便隨口交代它：「你能按他的建議做做看嗎？」並直接開給它頻道的 API 權限。

結果在 24 小時之內，頻道流量顯著暴漲，訂閱人數在一天之內翻倍。

這次經驗完全換我稱呼他一聲老師。這位前 Google 人員雖然完全沒有編程背景，但對話中就能清楚感受到他出色的規劃邏輯與指揮思路。他與 AI 協作時一點就通，進度非常快，一小時就能趕超四小時進度。

## 額度上限的現實提醒

無論工作流程多麼流暢，在日常實務中仍必須面對嚴苛的額度限制。特別是在使用高階模型時，你很可能會經歷這種體驗：早上九點看著 5 小時用量還剩 55%，15 分鐘後就直接撞上限制，只能等待冷卻重置：

```
You've hit your rate limit.
- Reset Friday 07:00 AM
```

這正是 Opus 4.7 推出之後的日常寫照。關於更詳細的額度踩坑過程，可以參考我之前整理的[額度事故簿](/blog/posts/zh/claude-code-quota-incident-log)，裡面記錄了 Opus 4.7 上線那一週的真實情況。

面對不可避免的限額，使用者能建立的通用防護原則很單純：
第一，長文本閱讀堅決派發給 Haiku 等輕量模型分段摘要，不讓主模型直接吞吐原始大檔；
第二，補充資訊與圖片時始終發送新訊息，維持快取鏈完整不中斷；
第三，善用自動放行搭配自動化鉤子，免去重複確認的煩擾，並在真正危險的關鍵節點把關攔截。

當你不再把 Claude Code 當成單一的對話框，而是視為一套由規則、記憶、鉤子與多模型分工組成的系統時，它才能在有限的額度與資源下，真正成為每天穩定支撐你產出的外掛大腦。

## 附錄

整理本文提及的各項進階設定與技術規格：

- **規則模組（Rules）**：檔案路徑位於 `~/.claude/rules/`，可在 `CLAUDE.md` 中透過 `@path/to/rule.md` 語法依需求動態引入，存放跨專案技術準則、踩坑清單與工具路由表。
- **會話記憶（Memory）**：採用 auto memory 機制，自動追蹤會話層級的使用者偏好、專案狀態與犯錯紀錄，在新對話中自動載入關聯條目。
- **自動化鉤子（Hooks）**：於 `settings.json` 中配置生命週期攔截點，包含 `SessionStart` 會話啟動檢查、`PreToolUse` 工具執行前攔截，以及 `PostToolUse` 工具執行後提醒。
- **終端機顯示與點擊設定**：Ghostty 終端機建議採用 No Flicker 模式以固定文字列，搭配 `file://` 協議之絕對路徑格式，確保在接管滑鼠後依然保有超連結點擊功能。
- **官方版本更新**：更多 Claude Code 版本功能與更新詳情，可參閱官方 CHANGELOG：<https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md>

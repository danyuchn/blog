滑手機的時候，偶然看到同業推出一個產品賣得很好，你的第一反應是什麼？

老實說，大多數人的第一反應都是焦慮。不論你是開課的老師、帶團隊的主管，還是自己接案的專業工作者，看到別人做出成績，心裡難免會冒出幾個念頭：「我是不是落後了？」「他這個做法我是不是也要趕快跟上？」

但如果你在焦慮的當下就直接衝去改自己的東西，通常只會越改越亂。因為在還沒看懂對方到底贏在哪裡、又還沒想清楚自己真正要做什麼之前，所有的跟風都只是在消耗精力。

那明天再遇到這種讓你不安的對手時，你可以怎麼做？你不需要自己悶著頭亂想，可以用平常聊天的 AI，分兩步把這件事徹底拆開來看。

## 第一步：向外看，把讓你不安的對手研究透

焦慮往往來自「只看到表面結果，不知道背後怎麼回事」。所以在決定要不要追之前，請先叫 AI 用兩個方向，幫你把這個對手徹底摸清——這叫做「橫縱分析法」：

- **縱向（看它的過去到現在）**：請 AI 幫你整理，這個東西是怎麼一步步演進到現在這個樣子的？它經歷過哪些調整？
- **橫向（看它跟別人的差別）**：請 AI 把它跟市面上其他同類產品放在一起比，它真正的差異到底在哪裡？

為什麼這一步有效？因為當你把「直的時間軸」跟「橫的比較表」攤開來看，腦中模糊的焦慮就會被替換成具體的資訊。

你會一眼看穿，對方到底是「產品本身真的厲害」，還是純粹「行銷做得好」；更重要的是，你會看清楚自己跟對方的差距裡面，有哪些是你真正該補上的落差，又有哪些根本不需要去追。

## 第二步：向內看，把自己的底線想清楚

把外面的對手看清楚之後，千萬別馬上開始動手改。下一步，是回頭看你自己。

很多時候，我們會因為別人賣得好而動搖，真正的問題其實不是對方做得有多好，而是我們自己從頭到尾都沒想清楚。這時候，你可以請 AI 切換成「追問到底」的角色（也就是常說的「第一性原理」，意思是把所有表面做法剝掉，只問最根本的原因），逼自己回答兩個問題：

- **我在做的事情，最底層的「為什麼」是什麼？**
- **我現在的做法裡，哪些是真正不能動搖的核心？哪些其實只是因為「大家都這麼做」我才跟著做？**

當 AI 幫你把這兩題逼問出來，你就不會因為別人換了新包裝，就慌張地把自己的核心優勢也一起丟掉。

**第一步幫你看清外面，第二步幫你想清裡面。** 這兩個步驟分開用都有效，但連在一起做才真正完整：先對外拆解對手，再對內拆解自己，原本讓你坐立難安的競品，反而會變成幫你校準方向的鏡子。

## 我自己的實戰經驗與一個關鍵習慣

我自己最近也是因為偶然看到一個競品賣得很好，心裡第一反應就是焦慮。但我沒有急著去改手上的東西，而是先停下來，照著上面這兩步，讓 AI 先帶我做完一次橫縱分析，再做一次第一性原理的自我追問。整套跑完之後，原本的不安就變成了清楚的取捨——我知道對方哪裡強、哪些差距我不用追，也更確定自己真正不該動的核心是什麼。

如果你明天就想在日常的 AI 對話裡試試看這兩步，有一個非常實用的小習慣可以直接照做：**把「想清楚」跟「動手做」分成兩個不同的對話視窗。**

很多人習慣在同一個 AI 對話視窗裡，一邊請 AI 查對手資料、一邊跟 AI 討論自己的定位，聊了幾十句之後，又直接在同一個視窗裡叫 AI 開始寫企劃或改文案。這樣做很容易讓 AI「分心」——因為前面的討論太長、雜訊太多，AI 的注意力被稀釋掉，最後寫出來的東西反而四不像。

比較好的做法是：
1. 先開一個專門用來「研究與思考」的對話，跑完上面這兩步，把最後得出的資料與結論整理進你的筆記裡。
2. 等到真正要動手執行（例如寫方案、改課程、做簡報）時，**再開一個全新的對話視窗**，只把剛剛整理好的最終結論貼進去，讓 AI 專心幫你執行。

把「研究」跟「執行」分開，你跟 AI 的腦袋都會清楚很多。

## 進階技術補充：給想直接安裝工具的 Claude Code 使用者

如果你平常用的是 **Claude Code**（Anthropic 官方推出的命令列 AI 工具，可以讓你直接在電腦終端機裡跟 AI 協作處理檔案與專案），我上面提到的這兩步，其實已經被打包成兩個現成的 **Claude Skill**（Skill 可以理解成「幫 AI 預先寫好的專業工作流程說明書」，裝好之後不用每次重新打一大段提示詞，直接呼叫就能照固定框架分析）。

這兩個 Skill 都已經公開在 **GitHub**（全球最大的程式碼與工具分享平台）上，有使用 Claude Code 的人可以直接安裝取用：

- **橫縱分析法 Skill**（負責向外看清競品演進與同業差異）：<https://github.com/KKKKhazix/khazix-skills>
- **第一性原理 Skill**（負責向內追問底層核心與慣性盲點）：<https://github.com/danyuchn/first-principles-skill>

### 操作流程上的技術細節

在 Claude Code 的實際工作流中，這兩個 Skill 我都不會在「正式工作」的 **session**（單次對話連線）裡直接跑，也不會直接混進 **plan mode**（Claude Code 裡先規劃執行步驟、再動手修改檔案的規劃模式）。

我的固定流程是：
1. 在進入 plan mode 正式規劃工作之前，先開獨立的 session 呼叫這兩個 Skill 做一輪研究與思考。
2. 把產出的資料跟結論收進自己的筆記檔。
3. 等到要正式動手時，再開一個全新的 session，把整理好的結論帶進去開始工作。

這樣做在技術上的原因，是為了避免單一對話的 **context**（AI 在同一次對話中要同時記住的上下文背景資訊）過長，導致模型的注意力被前面的大量研究過程稀釋，確保真正執行時的精準度。

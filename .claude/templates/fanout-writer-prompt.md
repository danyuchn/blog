# 寫手 prompt 模板（agy）

**寫稿、改稿、併入、翻譯、去 AI 腔一律交給 agy；Claude 主對話只負責派工與驗收，不親自寫內文**（Dustin 2026-10-26：agy 寫作比較強）。`{...}` 為 placeholder。
歷史事故驅動的條款請勿刪減：禁 git（W25 寫手擅自 commit+push）、必填 frontmatter（寫手曾略過 description 導致 astro check 炸）、檔尾出處表（新文）／自首清單（併入）、併入不准在文末加節（2026-10-26 全站 80 篇拼接順稿）。

## 派工方式（三種 prompt 共用）

1. **給複本，不給 repo 原檔**：要改的文章先複製到 scratchpad（例：`<scratchpad>/zh/`、`<scratchpad>/en/`），prompt 只寫複本路徑。agy 即使被告知只寫 scratchpad，也可能就地改寫它讀到的 repo 檔。
2. **用 ext-run 背景跑**：在 scratchpad 目錄下執行（agy 會把暫存檔丟在 cwd），一批約 10 篇或 6–7 萬字，最多 8 批並行：
   `~/.claude/scripts/ext-run --name <名稱> --timeout 3000 --marker <結尾標記> agy --model "$(~/.claude/scripts/ext-run --model-for write)" --dangerously-skip-permissions --add-dir <複本目錄> -p "$(cat <prompt 檔>)"`
   用 Bash `run_in_background` 跑，並掛 Monitor 涵蓋完成、失敗與逾時。
3. **3 分鐘沒進展就換路**：檔案沒變、只有 request 數在漲，就改成「只把譯文／段落印到標準輸出、不准動檔」，由主對話原樣插回。
4. 驗收通過後，主對話才把複本拷回 repo。

## Prompt A：素材 → 新文章（`ext-run --kind write`）

Dustin 2026-11-12 定案：新文一律由寫作模型（`ext-run --kind write`，Argon，額度滿自動退 Flash）從素材寫整篇，取代 Sonnet 寫手；W47 兩篇照這份 brief 寫，Dustin 一次核准。舊版「最小銜接、逐字保留、自首清單」的寫法會寫出拼接感與防禦語氣，已廢除。骨架來源：`~/.claude/skills/subagent-dispatch/references/write-brief.md`。

**備料**：一篇一個 scratchpad 資料夾，`src/` 只放事實來源（貼文原文含日期、對話摘錄、前後版本稿、作者原話），給全文不給摘要；內部規格檔、方法論庫、代號表不要放。**派工**：在該資料夾下跑 `ext-run --kind write --name <名> --dir <資料夾> --timeout 1800 --marker WRITE_DONE "$(cat brief.txt)"`，背景執行。

```text
你要從素材寫一篇部落格文章，作者是 Dustin（一位住在曼谷、從 GMAT 老師轉做 AI 工作流的創作者）。成品直接寫成檔案：{資料夾}/out/zh/{slug-basename}.md

【目標】
讀者看完要做到一件事：{讀者的動作，例如「下次叫 AI 寫稿時知道怎麼交代」}。請寫得吸引人、有說服力、讀起來自然，讓人想讀完。

【情境】
作者部落格上的一篇文章，第一人稱、口語、有個人溫度。讀者是{具體的人，例如「會用 ChatGPT、Claude 的上班族、老師，不一定會寫程式」}。長度約 {N} 字（素材短就寫短，不灌水）。

【素材（都在 {資料夾}/src/）】
- {逐份列出：檔名＋是什麼}
{哪些只是證據、可以引一兩句，不要整段改寫進文章}

【自由度】
這不是整理筆記，是寫一篇好文章。先定一個主軸，開頭要有鉤子，結構自己設計，自由發揮。前後段落要連得起來，每一段都讓沒看過前因後果的陌生人讀得懂：提到「那份稿」「那次」之前，先讓讀者知道是怎麼回事。需要提醒或限制的地方，集中在文末一次講完。

【反例】防禦式、免責式語氣一句都不要{有 Dustin 點名的原句就引在這裡}；作者要的是說服人。

【事實底線（唯一的硬限制）】
數字、作者原話、事件經過只能取自素材資料夾；不新增案例、數字、原話、作者沒說過的論點。引用作者原話可以刪語助詞，但不改意思，不要把你寫的句子包裝成作者說過的話。

【格式規則（部落格系統會機器檢查，必須照做）】
檔案開頭是 YAML frontmatter，欄位一個都不能少：author: Dustin Yuchen Teng / pubDatetime: {YYYY-MM-DD}T04:00:00Z / title（含半形「: 」時整值用雙引號包）/ slug: zh/{slug-basename} / featured: false / draft: false / tags（從 {tag 候選清單} 挑 2–3 個）/ description（35–90 字，整句單引號包住，句中單引號寫成兩個）。
- 正文只用 ## 當小標，不用 #，不用 emoji，不寫「小結／結語」章節，不用排比喊話收尾；結尾短而乾脆。
- 讀者是陌生人：素材裡的內部檔名、skill 名、腳本名、代號、指令、commit，正文一律不出現，改用一句白話描述；技術細節放文末「## 附錄」。素材整理用的編號（貼文編號等）不准出現。
- 學員、客戶不具名。
- 圖片只寫引用路徑 /blog/assets/posts/{slug-basename}/{檔名}，不搬檔。
- 檔案最後加一段 HTML 註解，列出正文裡每一句加引號的作者原話與每個數字，各自來自哪一份素材檔。

只要一版。寫完後在標準輸出最後一行印 WRITE_DONE。不要建立或修改其他任何檔案，不要執行 git 或 npm。
```

**收件**：只驗事實，不改句子。逐句看檔尾出處表與正文：素材沒有的論點、原因、數字、誇飾（如「一字未改」）、張冠李戴、內部代號，列成「哪幾處、為什麼」退回同一寫作模型改，不給範句、不自己動筆。陌生人卡點（未解釋的模型名、工具名）也照此退回。

**en**：zh 驗過後再派一次 `--kind write`：照 zh 翻成 `out/en/`，frontmatter 除 slug、title、description 外與 zh 相同，段落、小標、清單、code block 一一對應，譯完讀 `~/.claude/skills/humanizer/SKILL.md` 去 AI 腔，作者引語翻成自然口語。主對話驗 H2 與清單數量對齊。

## Prompt B：併入新素材 → 整篇重寫（`ext-run --kind write`）

Dustin 2026-11-12 定案：併入不是在原文插段落，而是把新素材放進文章後**交寫作模型整篇重寫**。W47 先用舊式插入，他看完說「還是有點怪」；改成整篇重寫後三篇一次核准。

**備料**：一篇一個資料夾，`src/01-current-article.md` 放目前的文章全文（repo 檔複本），`src/02-new-material.md` 放新素材原文（含日期）。新素材附圖時，主對話先把圖放進 `public/assets/posts/<basename>/`，brief 裡給好完整的圖片語法與位置。**派工**：`ext-run --kind write --name <名> --dir <資料夾> --timeout 2400 --marker WRITE_DONE "$(cat brief.txt)"`。

```text
你要把一篇部落格文章整篇重寫，作者是 Dustin（住在曼谷、從 GMAT 老師轉做 AI 工作流的創作者）。成品寫成：{資料夾}/out/zh/{slug-basename}.md

【為什麼要重寫】
這篇文章要接進新的素材。不要在原文裡插段落：把舊文章和新素材當成一份材料，重寫成一次寫成的好文章。

【目標】
{讀者看完要知道或做到什麼}
請寫得吸引人、有說服力、讀起來自然，前後連貫，讓第一次點進來、不認識作者的陌生人從頭讀到尾都跟得上。

【素材（在 {資料夾}/src/）】
- 01：目前的文章全文（包含 frontmatter、圖片、連結、表格、程式碼或提示詞區塊、附錄、檔尾註解）
- 02：這次要併進去的新素材原文
{新素材附圖時：圖片語法與該放的位置}

【自由度】
結構、章節、小標、段落順序、句子全部可以重新設計，先定一個主軸，開頭要有鉤子。重複的內容合併成一處。作者的口吻、比喻、玩笑和判斷要保留。需要提醒或限制的地方集中在文末一次講完，不寫防禦或免責語氣。作者個人的帳戶狀態（自己的到期日、餘額）若要給讀者當建議，改寫成讀者能套用的原則。只有作者自己懂的內部工具名、代號，正文改成白話；技術細節放「## 附錄」。正文提到「這張圖」時，文中必須真的有那張圖。

【必須保留（硬限制）】
- 所有事實、數字、日期、模型名稱與版本、作者原話的意思：只能取自素材，不新增案例、數字、原因或作者沒說過的話。
- 每一張圖片（路徑與 alt 原樣）、每一個連結、每一個表格、每一個程式碼或提示詞區塊都要留下，內容不改，可以換位置。
- frontmatter 的 author、pubDatetime、slug、featured、draft、tags 不動；title 與 description 可以改寫，description 整句單引號包住、句中單引號寫成兩個、中文 35–90 字；title 含半形「: 」時整值用雙引號包。
- 正文只用 ## 小標，不寫小結／結語章節，不排比收尾，不用 emoji；全文只有一個收尾。
- 檔尾 HTML 註解：保留原本的內容，最後加一段「{YYYY-MM-DD} 併入並整篇重寫：」用一兩句話說明併了什麼、結構怎麼調整。

只要一版。不建立或修改其他檔案，不執行 git 或 npm。最後一行印 WRITE_DONE。
```

**收件**：先用程式比對重寫前後：frontmatter 固定欄位、tags、圖片路徑集合、連結集合、表格與程式碼區塊數量都不能少；列出新出現的數字回素材查。再讀全文核對事實（誇飾、張冠李戴、新編的技術細節、個人帳戶細節被當成通用建議、只出現一次的內容被刪），問題列出退回同一模型改。**en**：zh 驗過後派 `--kind write` 從新 zh 全新翻譯（不沿用舊英文），驗小標、清單、表格、圖片數量與 zh 一致。

## Prompt C：拼接審查（併入之後、或抽查舊文）

```text
你是一位資深中文編輯。逐篇完整讀完下列文章（{複本目錄}），判斷「拼接怪異程度」。只審查，不修改任何檔案。
類型：A 斷裂（接上的章節沒有過渡）／B 重複（同一論點或例子講兩次）／C 時間錯亂（相對時間詞、版本、數字前後矛盾）／D 結構錯位（多個收尾、標題或 description 對不上內容）／E 文體不一（殘留拼貼標記、語氣突變）／F 其他拼接痕跡。
每審完一篇就附加寫入 {partial 檔}：
### <檔名> | 怪異度 <1-5>
- [類型][高/中/低] 位置：「<逐字引用 10–20 字>」— 問題：<一句> — 建議：<一句>
怪異度 1 只寫標題行。引用必須逐字，找不到就不報；不報錯字、風格、資訊正確性等非拼接問題。
全部審完印出怪異度 ≥3 的清單，最後一行印 REVIEW_DONE。
```

怪異度 ≥3 的退回 Prompt B 重做。

## 主對話驗收 checklist

- [ ] **派工前**：repo working tree 清乾淨；圖片資產由主對話先複製到 `public/assets/posts/<basename>/`。
- [ ] **回收**：逐篇 diff 複本與原檔（`git diff --no-index --word-diff`），不採信 agy 的回報。
- [ ] **回收**：每一句被刪的內容，確認文中另有出處；只出現一次就退回。
- [ ] **回收**：每一句新增的句子，確認沒有原文沒有的原因、動機、事實、場景；照自首清單逐句裁決。
- [ ] **回收**：數字、連結、圖片、嵌入數量前後一致；frontmatter 除 description 外沒變；新文逐篇對照原始貼文，砍膨脹出來的補述。
- [ ] **回收**：en 段落與 zh 一一對應（H2 數量與順序相同），新文的 en 確實過了 humanizer 規則。
- [ ] 違規的寫成逐條修正清單，退回 agy 再跑一輪；修正後再驗一次。
- [ ] 複本拷回 repo，`npm run check:content` → `npm run check:private` → `npm run build` 全綠。
- [ ] 收尾 commit 由主對話自己做，**逐檔 `git add <path>`，禁 `git add -A`**。
